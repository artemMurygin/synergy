# file-storage Specification

## Purpose
Хранение файлов пользователя, с которыми работает агент: загрузка, метаданные, скачивание, удаление и автоматическое удаление по сроку хранения. Результаты обработки при этом живут в БД дольше самих файлов.

## Requirements

### Requirement: Загрузка файла
Система SHALL принимать от аутентифицированного пользователя один файл за запрос (multipart, поле `file`) и сохранять его вместе с метаданными:
- идентификатор;
- исходное имя (UTF-8, в том числе кириллица);
- тип содержимого;
- размер в байтах;
- вид файла: `recording` (аудио или видео) или `document`;
- время загрузки;
- срок хранения.

Владельцем файла MUST становиться загрузивший пользователь. Ответ MUST содержать метаданные файла. Неаутентифицированный запрос MUST получать 401.

#### Scenario: Загрузка таблицы
- **WHEN** пользователь загружает `Отчёт.xlsx` размером 2 МБ
- **THEN** ответ 201 содержит идентификатор, имя `Отчёт.xlsx`, тип xlsx, размер, вид `document` и срок хранения через 30 дней

#### Scenario: Загрузка записи встречи
- **WHEN** пользователь загружает `встреча.m4a`
- **THEN** ответ 201 содержит вид `recording` и признак, что запись ожидает обработки

#### Scenario: Пустой запрос
- **WHEN** в запросе нет поля `file` или файл пустой
- **THEN** ответ 400, ничего не сохраняется

### Requirement: Допустимые типы файлов
Система SHALL принимать только файлы из белого списка:
- **документы**: xlsx, xls, csv, docx, doc, pdf, txt;
- **записи**: mp3, m4a, ogg/opus, wav, webm, flac, mp4.

Тип MUST определяться по содержимому файла. Для текстовых форматов без сигнатуры (csv, txt) тип определяется по расширению при условии, что содержимое — текст в UTF-8. Если содержимое не соответствует ни одному допустимому типу, MUST возвращаться 415, и файл MUST не сохраняться.

#### Scenario: Исполняемый файл с расширением xlsx
- **WHEN** пользователь загружает исполняемый файл, переименованный в `data.xlsx`
- **THEN** ответ 415, файл не сохраняется

#### Scenario: CSV без сигнатуры
- **WHEN** пользователь загружает `list.csv` с текстом в UTF-8
- **THEN** файл принимается с типом csv и видом `document`

### Requirement: Лимиты размера
Система SHALL ограничивать размер файла по виду: записи — до настроенного лимита (по умолчанию 1 ГБ), документы — до настроенного лимита (по умолчанию 50 МБ). При превышении лимита MUST возвращаться 413, а частично записанные данные MUST удаляться из хранилища.

#### Scenario: Слишком большой документ
- **WHEN** пользователь загружает документ размером 60 МБ при лимите 50 МБ
- **THEN** ответ 413, в хранилище не остаётся ни файла, ни его частей

### Requirement: Доступ только владельца
Метаданные, скачивание и удаление файла SHALL быть доступны только его владельцу. Запрос к чужому или несуществующему файлу MUST получать одинаковый ответ 404.

#### Scenario: Чужой файл
- **WHEN** пользователь запрашивает метаданные файла, загруженного другим пользователем
- **THEN** ответ 404, такой же, как для несуществующего идентификатора

### Requirement: Метаданные файла
Система SHALL отдавать владельцу метаданные файла по идентификатору (`GET /files/:id`): поля загрузки, статус (`active` или `deleted`) и срок хранения. Если запись ожидает обработки, MUST возвращаться признак ожидания, а срок хранения MUST быть пустым. Метаданные удалённого файла MUST оставаться доступными со статусом `deleted` и временем удаления.

#### Scenario: Файл удалён по сроку
- **WHEN** владелец запрашивает файл, удалённый очисткой
- **THEN** ответ 200 со статусом `deleted` и временем удаления

### Requirement: Скачивание по подписанной ссылке
Система SHALL выдавать владельцу активного файла подписанную ссылку на скачивание (`POST /files/:id/download-link`). Ссылка действует настроенное время (по умолчанию 5 минут). По ссылке MUST отдаваться содержимое файла без заголовка `Authorization`, с исходным типом и заголовком `Content-Disposition: attachment`, где имя файла закодировано по RFC 5987. Ссылка MUST подходить только для того файла, для которого выдана. Если ссылка просрочена или подделана, MUST возвращаться 403. Для удалённого файла MUST возвращаться 410.

#### Scenario: Скачивание
- **WHEN** владелец получил ссылку и открыл её в течение 5 минут
- **THEN** ответ 200 с содержимым файла и именем `Отчёт.xlsx` в `Content-Disposition`

#### Scenario: Просроченная ссылка
- **WHEN** ссылку открывают через 6 минут после выдачи
- **THEN** ответ 403

#### Scenario: Ссылка на другой файл
- **WHEN** токен из ссылки на файл A подставляют в адрес файла B
- **THEN** ответ 403

#### Scenario: Файл удалён после выдачи ссылки
- **WHEN** файл удалён, а ссылку открывают до её истечения
- **THEN** ответ 410

### Requirement: Удаление файла владельцем
Система SHALL позволять владельцу удалить файл (`DELETE /files/:id`). Содержимое MUST удаляться из хранилища, метаданные MUST оставаться со статусом `deleted`. Повторное удаление MUST возвращать тот же успешный ответ (204).

#### Scenario: Повторное удаление
- **WHEN** владелец дважды удаляет один и тот же файл
- **THEN** оба ответа 204, файл в статусе `deleted`

### Requirement: Срок хранения по виду файла
Система SHALL назначать срок хранения по виду файла:
- `document` — настроенное число дней (по умолчанию 30) с момента загрузки;
- `recording` — настроенное число дней (по умолчанию 1) с момента завершения обработки (успешного или окончательно неудачного). Пока обработка не завершена, запись MUST не удаляться, но не дольше настроенного максимума удержания (по умолчанию 7 дней с загрузки). После него срок отсчитывается так, как будто обработка завершилась в этот момент.

#### Scenario: Запись после расшифровки
- **WHEN** расшифровка записи завершилась в 12:00
- **THEN** срок хранения записи — 12:00 следующего дня

#### Scenario: Обработка зависла
- **WHEN** обработка записи не завершилась за 7 дней с загрузки
- **THEN** удержание снимается, и запись удаляется через 1 день

#### Scenario: Документ
- **WHEN** документ загружен 1 марта
- **THEN** срок хранения — 31 марта

### Requirement: Ежедневная очистка просроченных файлов
Система SHALL не реже раза в сутки удалять содержимое файлов с истёкшим сроком хранения и переводить их в статус `deleted`. Очистка MUST выполняться одним экземпляром бэкенда за раз и MUST быть идемпотентной: если содержимого в хранилище уже нет, это не ошибка. Сбой удаления одного файла MUST не останавливать очистку остальных. Удаление файла MUST не затрагивать результаты его обработки.

#### Scenario: Просроченный документ
- **WHEN** срок хранения документа истёк, и запустилась очистка
- **THEN** содержимого в хранилище нет, файл в статусе `deleted`

#### Scenario: Содержимое уже отсутствует
- **WHEN** у просроченного файла содержимого в хранилище уже нет
- **THEN** очистка переводит его в `deleted` без ошибки

#### Scenario: Расшифровка переживает запись
- **WHEN** очистка удалила запись встречи
- **THEN** расшифровка этой записи по-прежнему доступна владельцу

### Requirement: Событие о загрузке файла
Система SHALL публиковать доменное событие о загрузке файла атомарно с сохранением его метаданных. Событие содержит идентификатор файла, владельца, вид, тип и размер, но не содержимое и не имя файла. Подписчики MUST получать событие по гарантиям outbox (хотя бы один раз).

#### Scenario: Запись загружена
- **WHEN** пользователь загрузил запись встречи
- **THEN** публикуется событие с видом `recording`, и подписчики его получают
