# agent-streaming-protocol Specification

## Purpose
Потоковый протокол запуска агента sheets-qa: клиент отправляет вопрос в чат (thread) и получает ответ и ход работы агента как последовательность событий по мере их появления, а не одним готовым ответом.

## Requirements

### Requirement: Запуск агента в чате
Система SHALL принимать запуск агента для существующего чата (thread): идентификатор чата и новое сообщение пользователя. В ответ система MUST отдавать поток событий в формате протокола AG-UI, начинающийся с события начала запуска и заканчивающийся событием завершения или ошибки. Контекст агента MUST определяться только историей этого чата.

#### Scenario: Успешный запуск
- **WHEN** клиент отправляет вопрос в существующий чат
- **THEN** система открывает поток событий, который начинается с события начала запуска и завершается событием завершения запуска

#### Scenario: Чат не найден
- **WHEN** клиент запускает агента с идентификатором чата, которого нет в системе
- **THEN** система отвечает ошибкой «не найдено» до начала потока, вопрос агенту не передаётся и ничего не сохраняется

#### Scenario: Некорректный вопрос
- **WHEN** клиент отправляет пустое сообщение или сообщение длиннее допустимого лимита
- **THEN** система отклоняет запуск с ошибкой валидации и ничего не сохраняет

### Requirement: Потоковая выдача ответа
Система SHALL передавать текст ответа агента частями в порядке генерации, не дожидаясь окончания ответа. Склейка частей MUST давать тот же текст, который сохраняется в истории чата.

#### Scenario: Ответ по частям
- **WHEN** агент формирует длинный ответ
- **THEN** клиент получает несколько событий с фрагментами текста до события завершения запуска

#### Scenario: Совпадение с историей
- **WHEN** запуск завершился успешно
- **THEN** текст сообщения агента в истории чата равен склейке переданных фрагментов

### Requirement: Прозрачность вызовов инструментов
Система SHALL сообщать в потоке о каждом вызове инструмента агентом: имя инструмента, аргументы и признак завершения. Данные, скрытые от агента (служебные столбцы и ячейки таблиц), MUST NOT попадать в события потока.

#### Scenario: Поиск по таблице
- **WHEN** агент ищет данные в таблице через инструмент
- **THEN** в потоке есть события начала и завершения вызова с именем инструмента и аргументами

#### Scenario: Скрытые данные
- **WHEN** результат инструмента содержал бы скрытый от агента столбец или ячейку
- **THEN** ни аргументы, ни результат вызова, ни текст ответа в потоке не содержат этих данных

### Requirement: Завершение и ошибки запуска
Система SHALL завершать каждый открытый поток либо событием завершения, либо событием ошибки с понятным текстом. Ошибка агента, превышение лимита шагов или времени MUST передаваться событием ошибки клиенту, у которого поток ещё открыт; сообщение пользователя при этом остаётся в истории чата, а неполное сообщение агента не сохраняется.

#### Scenario: Ошибка агента
- **WHEN** агент завершился ошибкой в середине ответа
- **THEN** поток завершается событием ошибки, в истории остаётся вопрос пользователя, а ответ агента не сохранён

#### Scenario: Превышение времени
- **WHEN** запуск превысил лимит времени
- **THEN** поток завершается событием ошибки с указанием на превышение времени

### Requirement: Запуск не зависит от соединения
Система SHALL выполнять запуск агента независимо от соединения клиента. Закрытие или обрыв соединения MUST NOT останавливать агента: запуск доходит до завершения, ошибки или лимита времени, а завершённый ответ сохраняется в истории чата.

#### Scenario: Клиент закрыл соединение
- **WHEN** клиент закрывает поток во время ответа агента
- **THEN** агент продолжает работу, а после завершения запуска ответ сохранён в истории чата

#### Scenario: Поток закрыт, ответ позже
- **WHEN** клиент закрыл поток, а затем запросил историю чата после завершения запуска
- **THEN** история содержит полный ответ агента, события потока повторно не передаются

#### Scenario: Лимит времени без клиента
- **WHEN** клиент отключился, а запуск превысил лимит времени
- **THEN** запуск завершается ошибкой, ответ агента не сохраняется, вопрос пользователя остаётся в истории

### Requirement: Явная отмена запуска
Система SHALL останавливать работу агента по явной команде клиента на отмену запуска чата. Отмена MUST быть идемпотентной: отмена чата без активного запуска не является ошибкой. После отмены система MUST NOT сохранять неполный ответ агента, а вопрос пользователя MUST остаться в истории; клиент, у которого поток ещё открыт, MUST получить событие завершения с признаком отмены.

#### Scenario: Отмена пользователем
- **WHEN** клиент отправляет команду отмены во время ответа агента
- **THEN** агент прекращает работу, неполный ответ не сохраняется, чат доступен для новых вопросов

#### Scenario: Отмена без запуска
- **WHEN** клиент отправляет команду отмены для чата, в котором нет активного запуска
- **THEN** система отвечает успешно и ничего не меняет

### Requirement: Один активный запуск на чат
Система SHALL допускать не более одного активного запуска в одном чате. Запуск считается активным до его завершения, ошибки или отмены, но не до закрытия соединения. Параллельные запуски в разных чатах MUST быть независимыми.

#### Scenario: Повторный запуск в том же чате
- **WHEN** клиент запускает агента в чате, где предыдущий запуск ещё не завершён, в том числе после закрытия его соединения
- **THEN** система отклоняет новый запуск ошибкой «конфликт», а текущий продолжается

#### Scenario: Запуски в разных чатах
- **WHEN** агент отвечает в чате A, а клиент запускает его в чате B
- **THEN** оба запуска выполняются независимо, ответы не смешиваются

#### Scenario: Новый запуск после завершения
- **WHEN** предыдущий запуск чата завершён, отменён или завершился ошибкой
- **THEN** система принимает новый запуск в этом чате
