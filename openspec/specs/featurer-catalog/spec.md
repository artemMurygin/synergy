# featurer-catalog Specification

## Purpose
Минимальный каталог портала Featurer: продукты, их агенты и навыки агентов с жизненным циклом статуса. Навык — единица, к которой привязываются заявки и от статуса которой зависит видимый автору статус заявки.

## Requirements

### Requirement: Продукты и агенты из seed
Система SHALL содержать продукты и их агентов, заведённые сидером при развёртывании. Начальный набор продуктов: control-center, manager-helper, Telegram-бот, веб. Агент MAY входить в несколько продуктов и MUST входить хотя бы в один; навыки и статус агента общие для всех его продуктов. Агент с одним и тем же `slug`, указанный у нескольких продуктов, MUST быть одной записью, связанной с каждым из этих продуктов. Повторный запуск сидера MUST NOT создавать дубликаты, MUST NOT перезаписывать существующие записи и MUST NOT удалять связи агента с продуктами; недостающие связи из начального набора MUST добавляться. Создание и редактирование продуктов, агентов и их связей через API MUST NOT предоставляться.

#### Scenario: Первый запуск сидера
- **WHEN** сидер запускается на пустой базе
- **THEN** создаются продукты начального набора, их агенты и связи агентов с продуктами

#### Scenario: Повторный запуск сидера
- **WHEN** сидер запускается, когда продукты и агенты уже существуют
- **THEN** количество продуктов и агентов не меняется

#### Scenario: Агент в двух продуктах
- **WHEN** в начальном наборе агент Ассистент указан у продуктов control-center и Telegram-бот
- **THEN** создаётся один агент Ассистент, связанный с обоими продуктами

#### Scenario: Новая связь для существующего агента
- **WHEN** агент уже есть в базе, а в начальный набор добавили его второй продукт, и сидер запускается повторно
- **THEN** у агента появляется связь со вторым продуктом, имя и признак архива агента не меняются

### Requirement: Список агентов
Система SHALL возвращать вошедшему сотруднику список агентов с названием, всеми продуктами, в которые агент входит, и идентификатором, чтобы разработчик мог выбрать агента для нового навыка. Архивные агенты MUST NOT попадать в этот список.

#### Scenario: Получение списка
- **WHEN** вошедший пользователь запрашивает список агентов
- **THEN** система отвечает 200 и возвращает каждого агента один раз вместе со списком его продуктов

#### Scenario: Архивный агент не в списке
- **WHEN** агент Ассистент в архиве, и пользователь запрашивает список агентов
- **THEN** Ассистента в ответе нет

#### Scenario: Запрос без токена
- **WHEN** клиент запрашивает список агентов без access-токена
- **THEN** система отвечает 401

### Requirement: Поля навыка
Система SHALL хранить для навыка: идентификатор, агента, которому он принадлежит, название, описание, статус, время создания, время последней смены статуса, время первого запуска (`launchedAt`) и время архивации (`archivedAt`). Навык MUST принадлежать ровно одному агенту. Название MUST быть непустым после удаления пробелов по краям и не длиннее установленного предела; описание MAY быть пустым. У нового навыка `launchedAt` и `archivedAt` MUST быть пустыми. Система MUST NOT хранить историю статусов навыка: только текущий статус и время его смены. Создание навыка у архивного агента MUST отвечаться 409, навык не создаётся.

#### Scenario: Навык с полными полями
- **WHEN** разработчик создаёт навык «Сводка встречи» у агента Ассистент с описанием
- **THEN** навык сохраняется с названием, описанием, агентом, статусом `planned`, временем создания, пустыми `launchedAt` и `archivedAt`

#### Scenario: Пустое название
- **WHEN** разработчик создаёт навык, у которого название состоит из пробелов
- **THEN** система отвечает 400 и навык не создаётся

#### Scenario: Несуществующий агент
- **WHEN** разработчик создаёт навык для несуществующего агента
- **THEN** система отвечает 404 и навык не создаётся

#### Scenario: Архивный агент
- **WHEN** разработчик создаёт навык у агента, который в архиве
- **THEN** система отвечает 409 и навык не создаётся

### Requirement: Жизненный цикл статуса навыка
Система SHALL поддерживать для навыка статусы `planned`, `in_dev`, `testing`, `launched`, `rework`. Новый навык MUST создаваться в статусе `planned`. Система MUST разрешать только переходы:
- `planned → in_dev`, `in_dev → testing`, `testing → launched`;
- `testing → rework`, `launched → rework`, `rework → testing`.

Любой другой переход, включая повтор текущего статуса, MUST отклоняться ответом 409 без изменения навыка. Неизвестное значение статуса MUST отвечаться 400. При первом переходе в `launched` система MUST записать `launchedAt`; последующие переходы, в том числе повторный `launched`, MUST NOT менять `launchedAt`. Смена статуса архивного навыка или навыка архивного агента MUST отвечаться 409 без изменения навыка.

#### Scenario: Переход вперёд
- **WHEN** разработчик меняет статус навыка с `planned` на `in_dev`
- **THEN** система отвечает 200, статус навыка становится `in_dev`, время смены статуса обновляется

#### Scenario: Пропуск статуса
- **WHEN** разработчик пытается перевести навык из `planned` сразу в `testing`
- **THEN** система отвечает 409, статус остаётся `planned`

#### Scenario: Переход назад
- **WHEN** разработчик пытается вернуть навык из `testing` в `in_dev`
- **THEN** система отвечает 409, статус остаётся `testing`

#### Scenario: Первый запуск
- **WHEN** разработчик переводит навык из `testing` в `launched` впервые
- **THEN** статус становится `launched`, `launchedAt` равен времени перехода

#### Scenario: Доработка запущенного навыка
- **WHEN** разработчик переводит навык из `launched` в `rework`
- **THEN** система отвечает 200, статус становится `rework`, `launchedAt` не меняется

#### Scenario: Доработка после тестирования
- **WHEN** разработчик переводит навык из `testing` в `rework`
- **THEN** система отвечает 200, статус становится `rework`

#### Scenario: Возврат из доработки в тестирование
- **WHEN** разработчик переводит навык из `rework` в `testing`
- **THEN** система отвечает 200, статус становится `testing`

#### Scenario: Повторный запуск
- **WHEN** навык, уже запускавшийся раньше, снова переходит из `testing` в `launched`
- **THEN** статус становится `launched`, `launchedAt` остаётся временем первого запуска

#### Scenario: Из доработки сразу в запуск
- **WHEN** разработчик пытается перевести навык из `rework` в `launched`
- **THEN** система отвечает 409, статус остаётся `rework`

#### Scenario: Запущенный навык
- **WHEN** разработчик пытается перевести навык из `launched` в `planned`
- **THEN** система отвечает 409, статус остаётся `launched`

#### Scenario: Неизвестный статус
- **WHEN** разработчик передаёт значение статуса, которого нет в списке
- **THEN** система отвечает 400

#### Scenario: Архивный навык
- **WHEN** разработчик меняет статус навыка, который в архиве
- **THEN** система отвечает 409, навык не меняется, событие не записывается

### Requirement: Создание и смена статуса навыка только разработчиком
Система SHALL разрешать создавать навык, менять его статус, архивировать и восстанавливать навык и агента, а также читать архив только пользователю с ролью `developer`. Остальным вошедшим пользователям система MUST отвечать 403, неавторизованным — 401.

#### Scenario: Сотрудник без роли создаёт навык
- **WHEN** пользователь без роли `developer` пытается создать навык или сменить его статус
- **THEN** система отвечает 403, данные не меняются

#### Scenario: Сотрудник без роли архивирует
- **WHEN** пользователь без роли `developer` пытается архивировать или восстановить навык или агента
- **THEN** система отвечает 403, данные не меняются

### Requirement: Список навыков
Система SHALL возвращать пользователю с ролью `developer` список навыков с названием, агентом, продуктами агента, статусом, временем последней смены статуса и числом привязанных заявок, с фильтром по статусу. Архивные навыки и навыки архивных агентов MUST NOT попадать в этот список. Сотруднику без роли этот список MUST NOT возвращаться; каталог для всех описан в требовании «Каталог для всех».

#### Scenario: Список для разработчика
- **WHEN** разработчик запрашивает список навыков
- **THEN** система отвечает 200 и возвращает навыки с числом привязанных заявок

#### Scenario: Фильтр по статусу
- **WHEN** разработчик запрашивает список навыков со статусом `rework`
- **THEN** в ответе только навыки в этом статусе

#### Scenario: Архивные навыки скрыты
- **WHEN** один навык в архиве, а агент другого навыка в архиве
- **THEN** ни одного из этих навыков нет в списке

#### Scenario: Список для сотрудника без роли
- **WHEN** пользователь без роли `developer` запрашивает список навыков
- **THEN** система отвечает 403

### Requirement: Событие смены статуса навыка
Система SHALL при каждой успешной смене статуса навыка записывать в outbox событие в той же транзакции, что и смена статуса. Событие MUST содержать идентификатор навыка, прежний и новый статус и пользователя, сменившего статус. Отклонённая смена статуса MUST NOT записывать событие.

#### Scenario: Успешная смена
- **WHEN** статус навыка успешно сменился с `in_dev` на `testing`
- **THEN** в outbox есть одно событие с этим навыком, прежним статусом `in_dev` и новым `testing`

#### Scenario: Отклонённая смена
- **WHEN** смена статуса отклонена ответом 409
- **THEN** новое событие в outbox не записывается

### Requirement: Каталог для всех
Система SHALL возвращать любому вошедшему сотруднику каталог: продукты, у каждого — неархивные агенты, входящие в этот продукт, с выведенным статусом агента, у каждого агента — неархивные навыки с названием, описанием, статусом и временем последней смены статуса. Агент, входящий в несколько продуктов, MUST показываться в каждом из них с одинаковыми навыками и статусом. Продукт без неархивных агентов MUST возвращаться с пустым списком агентов. Неавторизованному клиенту система MUST отвечать 401.

#### Scenario: Каталог для сотрудника без роли
- **WHEN** пользователь без ролей запрашивает каталог
- **THEN** система отвечает 200 и возвращает продукты, агентов и навыки со статусами

#### Scenario: Агент в двух продуктах
- **WHEN** агент Ассистент входит в control-center и Telegram-бот
- **THEN** Ассистент есть в обоих продуктах каталога с одним и тем же статусом и набором навыков

#### Scenario: Архивные записи скрыты
- **WHEN** агент Ассистент в архиве, а у агента Аудитор в архиве один навык
- **THEN** в каталоге нет Ассистента и его навыков, а у Аудитора нет архивного навыка

#### Scenario: Запрос без токена
- **WHEN** клиент запрашивает каталог без access-токена
- **THEN** система отвечает 401

### Requirement: Выведенный статус агента
Система SHALL выводить статус агента из его навыков в момент чтения и MUST NOT хранить его. Агент «Работает» (`working`), если у него есть хотя бы один неархивный навык с непустым `launchedAt`, независимо от текущего статуса этого навыка; иначе агент «В разработке» (`in_development`). Действия «запустить агента» система MUST NOT предоставлять.

#### Scenario: Есть запущенный навык
- **WHEN** у агента один навык в `launched` и один в `planned`
- **THEN** статус агента «Работает»

#### Scenario: Запущенный навык на доработке
- **WHEN** единственный запускавшийся навык агента перешёл из `launched` в `rework`, а затем в `testing`
- **THEN** статус агента остаётся «Работает»

#### Scenario: Доработка без запуска
- **WHEN** единственный навык агента перешёл из `testing` в `rework` и ни разу не был в `launched`
- **THEN** статус агента «В разработке»

#### Scenario: Запущенный навык в архиве
- **WHEN** единственный запускавшийся навык агента архивирован
- **THEN** статус агента «В разработке»

#### Scenario: Агент без навыков
- **WHEN** у агента нет неархивных навыков
- **THEN** статус агента «В разработке»

### Requirement: Архивация навыка
Система SHALL позволять разработчику архивировать и восстанавливать навык. Архивация MUST записывать `archivedAt`, восстановление MUST его очищать; статус навыка и `launchedAt` при этом MUST NOT меняться. Повторная архивация архивного навыка и восстановление неархивного MUST отвечать 200 без изменений. Восстановление навыка, чей агент в архиве, MUST отвечаться 409. Несуществующий навык MUST отвечаться 404. Архивация и восстановление MUST NOT записывать событие смены статуса.

#### Scenario: Архивировать навык
- **WHEN** разработчик архивирует навык в статусе `in_dev`
- **THEN** система отвечает 200, у навыка заполнен `archivedAt`, статус остаётся `in_dev`, навык пропадает из каталога и списка навыков

#### Scenario: Восстановить навык
- **WHEN** разработчик восстанавливает архивный навык неархивного агента
- **THEN** `archivedAt` очищается, навык снова в каталоге с прежним статусом

#### Scenario: Восстановление при архивном агенте
- **WHEN** разработчик восстанавливает навык, агент которого в архиве
- **THEN** система отвечает 409, навык остаётся в архиве

#### Scenario: Повторная архивация
- **WHEN** разработчик архивирует уже архивный навык
- **THEN** система отвечает 200, `archivedAt` не меняется

### Requirement: Архивация агента
Система SHALL позволять разработчику архивировать и восстанавливать агента. Архив у агента — признак (`archivedAt`), а не статус. Агент архивируется целиком, во всех своих продуктах сразу. Архивный агент MUST скрываться из каталога (во всех продуктах), списка агентов и списка навыков вместе со всеми своими навыками, при этом признак архива самих навыков MUST NOT меняться. Восстановление агента MUST возвращать в каталог только те его навыки, которые не были архивированы отдельно. Повторная архивация и восстановление в том же состоянии MUST отвечать 200 без изменений. Несуществующий агент MUST отвечаться 404.

#### Scenario: Архивировать агента
- **WHEN** разработчик архивирует агента Ассистент с тремя навыками
- **THEN** система отвечает 200, Ассистент и три его навыка пропадают из каталога, у навыков `archivedAt` остаётся пустым

#### Scenario: Восстановление не возвращает отдельно архивированный навык
- **WHEN** у агента навык А архивирован отдельно, затем агент архивирован и восстановлен
- **THEN** агент и его неархивные навыки снова в каталоге, навык А остаётся в архиве

#### Scenario: Несуществующий агент
- **WHEN** разработчик архивирует агента с неизвестным идентификатором
- **THEN** система отвечает 404

### Requirement: Архив для разработчика
Система SHALL возвращать пользователю с ролью `developer` архив: архивных агентов с продуктами, числом навыков, которые вернутся вместе с агентом, и временем архивации, и архивные навыки с агентом, продуктами агента, статусом и временем архивации. Навыки архивного агента, не архивированные отдельно, MUST NOT попадать в список архивных навыков: они вернутся вместе с агентом.

#### Scenario: Архив
- **WHEN** разработчик запрашивает архив, где один агент и один навык другого агента архивированы
- **THEN** система отвечает 200 и возвращает этого агента и этот навык

#### Scenario: Архив для сотрудника без роли
- **WHEN** пользователь без роли `developer` запрашивает архив
- **THEN** система отвечает 403
