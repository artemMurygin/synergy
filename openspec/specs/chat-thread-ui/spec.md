# chat-thread-ui Specification

## Purpose
Отображение диалога с агентом в side panel расширения `manager-helper`: ответ появляется по мере генерации, виден ход работы агента, а запуском можно управлять (остановить, повторить).

## Requirements

### Requirement: Потоковое отображение ответа
Панель SHALL показывать ответ агента по мере поступления частей текста, а не после полного ответа. Пока ответ формируется, панель MUST показывать, что агент работает. Историю сообщений MUST отображать в хронологическом порядке: вопрос пользователя, ответ агента.

#### Scenario: Ответ появляется постепенно
- **WHEN** пользователь отправил вопрос, а агент начал отвечать
- **THEN** в чате сразу появляется сообщение агента, текст которого растёт по мере получения

#### Scenario: Завершение ответа
- **WHEN** запуск агента завершился
- **THEN** индикатор работы пропадает, текст сообщения полный, поле ввода доступно

### Requirement: Ход работы агента
Чат SHALL показывать вызовы инструментов агента в сообщении единой группой. Заголовок группы MUST показывать общее состояние:
- пока хотя бы один вызов не завершён — «Выполняется · K из N» с индикатором, в мобильном режиме — «K из N»;
- после завершения всех вызовов без ошибок — число вызовов и «готово»;
- если были ошибки — число ошибок, например «1 ошибка».

Пока вызовы выполняются, группа MUST быть раскрыта. После завершения запуска группа MUST сворачиваться, но не сворачиваться, если пользователь сам раскрыл её после завершения. Раскрытая группа MUST показывать строки вызовов: имя инструмента, состояние (выполняется, завершён, ошибка) и длительность вызова в секундах с одним знаком после запятой, например «0,4 с». По раскрытию строки показываются аргументы и результат. У вызова с ошибкой MUST показываться иконка ошибки и текст ошибки вместо аргументов. В сохранённых сообщениях вызовы MUST быть свёрнуты, а их длительность MUST показываться, если сервер её сохранил. Состояние «ожидает» для ещё не начатых вызовов не показывается: протокол сообщает о вызове только после его начала.

#### Scenario: Вызов во время ответа
- **WHEN** агент вызывает инструмент поиска
- **THEN** в сообщении появляется раскрытая группа «Выполняется · 1 из 1», после завершения всех вызовов группа сворачивается, а заголовок меняется на «готово»

#### Scenario: Раскрытие группы
- **WHEN** пользователь раскрывает группу из трёх вызовов, а затем один из вызовов
- **THEN** видны три строки с именами инструментов, статусами и длительностью, а у раскрытой строки — аргументы и результат

#### Scenario: Ошибка инструмента
- **WHEN** один из вызовов инструмента завершился ошибкой
- **THEN** строка этого вызова показывает иконку и текст ошибки, заголовок группы — «1 ошибка», остальные строки показывают свои состояния

#### Scenario: Открытие сохранённого чата
- **WHEN** пользователь открывает чат, где агент вызывал инструменты
- **THEN** сообщения агента содержат свёрнутые группы вызовов с той же длительностью вызовов, что была при ответе

### Requirement: Остановка ответа
Пока агент отвечает, панель SHALL предоставлять действие «Остановить» вместо отправки. Остановка MUST явно отменять запуск на сервере. После остановки полученный текст MUST оставаться видимым. Под ним показывается строка «Ответ остановлен» с иконкой остановки и маленькой кнопкой «Повторить». Строка MUST сообщать, что полученная часть не сохранена в истории чата. Такой ответ не считается завершённым, поле ввода становится доступным. «Повторить» MUST перезапускать ответ на тот же вопрос без дубля вопроса в истории.

#### Scenario: Остановка пользователем
- **WHEN** пользователь нажимает «Остановить» во время ответа
- **THEN** запуск отменяется на сервере, полученный текст остаётся, под ним строка «Ответ остановлен» с пояснением, что часть не сохранена, и кнопкой «Повторить», пользователь может задать новый вопрос

#### Scenario: Повтор после остановки
- **WHEN** пользователь нажимает «Повторить» под остановленным ответом
- **THEN** агент отвечает на тот же вопрос заново, в истории чата вопрос один

### Requirement: Ответ агента после закрытия панели
Закрытие панели или переключение на другой чат SHALL NOT останавливать ответ агента. Когда пользователь возвращается в чат с идущим запуском, панель MUST показать историю, индикатор того, что агент ещё отвечает, и заблокировать отправку; потокового показа частей ответа при этом не требуется. Когда запуск завершается, панель MUST сама показать готовый ответ без ручного обновления. Остановить такой запуск пользователь MUST иметь возможность действием «Остановить».

#### Scenario: Возврат во время ответа
- **WHEN** пользователь закрыл панель посреди ответа и открыл её снова, пока агент ещё отвечает
- **THEN** чат показывает прежнюю историю и индикатор «агент отвечает», поле отправки заблокировано, доступно «Остановить»

#### Scenario: Ответ появился после возврата
- **WHEN** агент заканчивает ответ, пока пользователь смотрит чат с индикатором
- **THEN** индикатор пропадает, ответ появляется в истории, отправка снова доступна

#### Scenario: Возврат после завершения
- **WHEN** пользователь открыл панель после того, как агент закончил ответ
- **THEN** чат показывает полный ответ из истории

#### Scenario: Остановка после возврата
- **WHEN** пользователь вернулся в чат с идущим запуском и нажал «Остановить»
- **THEN** запуск отменяется на сервере, индикатор пропадает

### Requirement: Ошибка и повтор
Ошибка запуска SHALL отображаться в чате как сообщение об ошибке, не удаляя историю. Панель MUST предлагать повторить последний вопрос. Повтор MUST перезапускать ответ с уже сохранённого вопроса и MUST NOT добавлять в историю второй экземпляр вопроса.

#### Scenario: Ошибка запуска
- **WHEN** запуск агента завершился ошибкой
- **THEN** в чате показано сообщение об ошибке и действие «Повторить»

#### Scenario: Повтор вопроса
- **WHEN** пользователь нажимает «Повторить» после ошибки
- **THEN** последний вопрос отправляется заново, а сообщение об ошибке заменяется новым ответом

#### Scenario: Нет дубля после повтора
- **WHEN** пользователь повторил вопрос после ошибки, получил ответ и перезагрузил историю чата
- **THEN** вопрос в истории один, за ним ответ агента

### Requirement: Недоступность сервера
Если сервер недоступен или адрес бэкенда не настроен, чат SHALL показывать над полем ввода баннер «Сервер недоступен» с иконкой отсутствия связи и кнопкой «Повторить». Пока связи нет, поле ввода MUST быть заблокировано с подсказкой «Нет связи с сервером», а история чата MUST оставаться видимой. Набранный до потери связи текст MUST сохраняться. Клиент считает связь потерянной при сетевой ошибке запроса к серверу. «Повторить» MUST проверять связь: при успехе баннер исчезает, поле разблокируется. В `manager-helper` баннер MUST также предлагать проверить настройки расширения.

#### Scenario: Сервер недоступен
- **WHEN** пользователь отправляет вопрос, а сервер не отвечает
- **THEN** чат показывает баннер «Сервер недоступен», поле заблокировано с подсказкой «Нет связи с сервером», текст вопроса сохранён для повторной отправки

#### Scenario: Связь восстановлена
- **WHEN** сервер снова доступен, и пользователь нажимает «Повторить» в баннере
- **THEN** баннер исчезает, поле ввода доступно, набранный текст на месте

### Requirement: Одинаковый чат в обоих приложениях
Требования этой capability SHALL выполняться одинаково в боковой панели `manager-helper` и в окне `control-center`. Везде, где в требованиях сказано «панель», имеется в виду интерфейс чата любого из приложений. Состав, вид и поведение ленты, сообщений, хода работы агента, подсказок следующего шага, формы отправки, ошибок и остановки MUST совпадать. Отличаться MAY только компоновка под режим раскладки.

#### Scenario: Ход работы агента в control-center
- **WHEN** пользователь `control-center` задаёт вопрос, и агент вызывает инструменты
- **THEN** в сообщении агента видна группа вызовов инструментов с их статусами, как в `manager-helper`

#### Scenario: Одинаковая форма отправки
- **WHEN** пользователь сравнивает форму отправки в `control-center` и в `manager-helper`
- **THEN** поле, кнопка прикрепления файла и круглая кнопка отправки со стрелкой выглядят и работают одинаково

### Requirement: Подсказки следующего шага
После завершённого ответа агента чат SHALL показывать над формой отправки подсказки следующего шага, если ответ — подборка программ (нумерованный список из двух и более пунктов) или карточка программы. Набор подсказок зависит от вида ответа и одинаков в обоих приложениях. Нажатие на подсказку MUST отправлять связанный с ней вопрос как новое сообщение пользователя. Во время ответа агента и после ошибки подсказки MUST NOT показываться. Подсказки предыдущего ответа MUST исчезать после отправки нового сообщения. Для ответов другого вида подсказки не показываются.

#### Scenario: Выбор подсказки
- **WHEN** агент закончил ответ подборкой из пяти программ, а пользователь нажал подсказку «Вступительные»
- **THEN** вопрос о вступительных испытаниях отправляется как сообщение пользователя, подсказки скрываются, агент начинает отвечать

#### Scenario: Подсказки в control-center
- **WHEN** пользователь `control-center` получил ответ с карточкой программы
- **THEN** над формой отправки показаны те же подсказки, что в `manager-helper` для карточки программы

#### Scenario: Подсказки во время ответа
- **WHEN** агент ещё формирует ответ
- **THEN** подсказки над формой не показываются

### Requirement: Пустой чат
Новый чат без сообщений SHALL показывать приветственное состояние с кратким описанием возможностей ассистента и форму отправки.

#### Scenario: Открытие нового чата
- **WHEN** пользователь создаёт новый чат
- **THEN** вместо ленты показано приветственное состояние, фокус в поле ввода

### Requirement: Стартовое окно с карточками-подсказками
Чат без сообщений SHALL показывать стартовое окно: иконку, заголовок «Чем помочь?», подпись «Начните новый чат по любой теме: цены, программы, документы» и карточки-подсказки. У каждой карточки есть заголовок и пример запроса. Набор карточек статичен и одинаков в обоих приложениях. В десктопном режиме показываются четыре карточки сеткой 2×2: «Цены на программу», «Сравнить программы», «Условия рассрочки», «Найти в таблицах». В планшетном и мобильном режимах — первые три. Нажатие на карточку MUST подставлять её запрос в поле ввода и ставить фокус в поле, но MUST NOT отправлять запрос. Текст, который пользователь уже набрал, MUST NOT теряться: запрос карточки заменяет только пустое поле. В `control-center` стартовое окно MUST показываться и тогда, когда чат не выбран: экрана «Выберите чат» больше нет.

#### Scenario: Новый чат на десктопе
- **WHEN** пользователь `control-center` создаёт новый чат
- **THEN** показано стартовое окно с четырьмя карточками, фокус в поле ввода

#### Scenario: Новый чат в узкой панели
- **WHEN** пользователь `manager-helper` открывает новый чат в мобильном режиме
- **THEN** показано стартовое окно с тремя карточками без «Найти в таблицах»

#### Scenario: Выбор карточки
- **WHEN** пользователь нажимает карточку «Цены на программу» при пустом поле ввода
- **THEN** запрос карточки появляется в поле ввода, фокус в поле, сообщение не отправлено

#### Scenario: Поле уже заполнено
- **WHEN** в поле есть набранный текст, и пользователь нажимает карточку
- **THEN** набранный текст остаётся без изменений

### Requirement: Копирование сообщения пользователя
Под каждым отправленным сообщением пользователя SHALL быть действие «Копировать». Оно копирует текст сообщения в буфер обмена и коротко подтверждает это сменой иконки. Под ответом агента действие «Копировать» не показывается.

#### Scenario: Копирование вопроса
- **WHEN** пользователь нажимает «Копировать» под своим сообщением
- **THEN** текст сообщения оказывается в буфере обмена, иконка кнопки на время меняется на подтверждение

### Requirement: Редактирование отправленного сообщения
Под сообщением пользователя SHALL быть действие «Изменить», если сервер отметил это сообщение как доступное для изменения. «Изменить» открывает на месте сообщения поле редактирования с текстом сообщения и кнопками «Отмена» и «Отправить». Пока поле открыто, ответ агента ниже MUST помечаться «будет заменён». «Отправить» MUST перезапускать ответ с этого сообщения:
- сообщение заменяется новым текстом с прежними вложениями;
- все сообщения после него удаляются из ленты;
- агент отвечает заново, не видя удалённых сообщений.

«Отмена» и Escape MUST закрывать поле без изменений. «Отправить» MUST быть недоступна при пустом тексте. Пока агент отвечает, «Изменить» MUST быть недоступно. Если сервер отказал с конфликтом, потому что ответ уже идёт, чат MUST показать сообщение об этом и оставить историю без изменений.

#### Scenario: Изменение вопроса
- **WHEN** пользователь нажимает «Изменить» под вопросом, меняет текст и нажимает «Отправить»
- **THEN** вопрос в ленте заменён новым текстом, прежние сообщения после него исчезли, агент отвечает на новый текст

#### Scenario: Изменение раннего вопроса
- **WHEN** в чате три пары «вопрос — ответ», и пользователь изменяет первый вопрос
- **THEN** после отправки в ленте остаются изменённый первый вопрос и новый ответ, а вторая и третья пары удалены

#### Scenario: Отмена изменения
- **WHEN** пользователь открыл редактирование и нажал «Отмена»
- **THEN** сообщение и ответ под ним не изменились

#### Scenario: Ответ идёт
- **WHEN** агент отвечает в этом чате
- **THEN** действие «Изменить» недоступно

#### Scenario: Сообщение нельзя изменить
- **WHEN** сервер отметил сообщение как недоступное для изменения
- **THEN** под сообщением есть «Копировать», но нет «Изменить»

### Requirement: Голосовой ввод
Форма отправки SHALL содержать кнопку микрофона. Нажатие на неё MUST начинать запись. Во время записи форма вместо поля показывает таймер, волну, подпись «Говорите…» и кнопку «стоп». Запись MUST останавливаться по кнопке «стоп» или автоматически через 3 минуты. После остановки форма MUST показывать состояние «Распознаю речь…» со спиннером, пока сервер расшифровывает запись. Расшифровку MUST вставлять в поле ввода: в конец уже набранного текста через пробел. Её MUST NOT отправлять автоматически. Пока идёт запись или расшифровка, отправка MUST быть недоступна. Ошибки показываются в форме понятным текстом, набранный ранее текст сохраняется:
- нет доступа к микрофону;
- речь не распознана;
- слишком длинная или большая запись;
- сервис распознавания недоступен;
- слишком много запросов.

Пока агент отвечает, микрофон MUST быть недоступен.

#### Scenario: Диктовка вопроса
- **WHEN** пользователь нажимает микрофон, говорит «сколько стоит MBA» и нажимает «стоп»
- **THEN** форма показывает «Распознаю речь…», затем текст «сколько стоит MBA» появляется в поле ввода, а сообщение не отправлено

#### Scenario: Дописывание к набранному тексту
- **WHEN** в поле уже есть «Цены на» и пользователь надиктовал «MBA в Москве»
- **THEN** в поле «Цены на MBA в Москве»

#### Scenario: Речь не распознана
- **WHEN** запись не содержит речи
- **THEN** форма сообщает, что речь не распознана, поле ввода не изменено

#### Scenario: Нет доступа к микрофону
- **WHEN** пользователь отказал в доступе к микрофону
- **THEN** запись не начинается, форма объясняет, как разрешить доступ

#### Scenario: Предел длительности
- **WHEN** запись длится 3 минуты
- **THEN** запись останавливается сама и отправляется на расшифровку

### Requirement: Поиск по сообщениям чата
В шапке чата в десктопном и планшетном режимах SHALL быть кнопка поиска. Она открывает строку поиска по сообщениям текущего чата. Ввод MUST подсвечивать вхождения подстроки без учёта регистра и показывать число совпадений «N из M». Кнопки «вверх» и «вниз» и клавиши Enter / Shift+Enter MUST переходить между совпадениями с прокруткой ленты к текущему. Escape или кнопка закрытия MUST закрывать поиск и снимать подсветку. Поиск идёт только по загруженной истории открытого чата, без запроса к серверу.

#### Scenario: Поиск слова
- **WHEN** пользователь открывает поиск и вводит «рассрочка», а слово встречается в двух сообщениях
- **THEN** вхождения подсвечены, показано «1 из 2», лента прокручена к первому

#### Scenario: Нет совпадений
- **WHEN** введённой строки нет в сообщениях
- **THEN** строка поиска показывает «Нет совпадений»
