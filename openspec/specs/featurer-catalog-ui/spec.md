# featurer-catalog-ui Specification

## Purpose
Страницы портала Featurer, через которые любой сотрудник видит каталог продуктов, агентов и навыков и роадмап навыков по статусам, а разработчик архивирует и восстанавливает агентов и навыки.

## Requirements

### Requirement: Каталог
Портал SHALL показывать любому вошедшему сотруднику раздел «Каталог»: продукты, внутри каждого — агенты, входящие в продукт, с выведенным статусом («Работает» или «В разработке») и числом навыков. Агент из нескольких продуктов MUST показываться в секции каждого из них. На плитке такого агента MUST быть подпись «Также в: …» с остальными его продуктами; у агента с одним продуктом подписи нет. Продукт без агентов MUST показываться с пометкой, что агентов пока нет. Архивные агенты и навыки MUST NOT показываться. Раздел MUST иметь состояние загрузки и состояние ошибки с повтором. Агент MUST открывать свою карточку.

#### Scenario: Каталог сотрудника
- **WHEN** сотрудник без ролей открывает «Каталог»
- **THEN** портал показывает продукты и их агентов со статусами

#### Scenario: Агент в двух продуктах
- **WHEN** агент Ассистент входит в control-center и Telegram-бот
- **THEN** плитка Ассистента есть в обеих секциях, в секции control-center с подписью «Также в: Telegram-бот», и обе ведут в одну и ту же карточку

#### Scenario: Продукт без агентов
- **WHEN** у продукта нет неархивных агентов
- **THEN** портал показывает продукт с пометкой «Агентов пока нет»

#### Scenario: Переход в карточку агента
- **WHEN** сотрудник выбирает агента в каталоге
- **THEN** открывается карточка этого агента

#### Scenario: Ошибка загрузки
- **WHEN** запрос каталога завершился ошибкой
- **THEN** портал показывает ошибку и кнопку повтора

### Requirement: Карточка агента
Портал SHALL показывать в карточке агента его название, все продукты агента, выведенный статус и список неархивных навыков с названием, описанием, статусом на русском и датой последней смены статуса. Агент без навыков MUST показываться с пустым состоянием. Если агента нет в каталоге (неизвестный или архивный), портал MUST показывать состояние «Агент не найден» со ссылкой на каталог. Пользователю с ролью `developer` карточка MUST предлагать действие «Архивировать агента» с подтверждением, где сказано, что агент скроется из всех своих продуктов, а его навыки — вместе с ним; после архивации портал MUST вести в каталог. Сотруднику без роли действие MUST NOT показываться.

#### Scenario: Карточка с навыками
- **WHEN** сотрудник открывает карточку агента с навыками в `launched` и `rework`
- **THEN** портал показывает статус агента «Работает» и навыки со статусами «Запущено» и «Доработка»

#### Scenario: Агент без навыков
- **WHEN** у агента нет неархивных навыков
- **THEN** портал показывает пустое состояние и статус «В разработке»

#### Scenario: Архивный агент по прямой ссылке
- **WHEN** сотрудник открывает адрес карточки архивного агента
- **THEN** портал показывает «Агент не найден» и ссылку на каталог

#### Scenario: Архивация агента разработчиком
- **WHEN** разработчик выбирает «Архивировать агента» и подтверждает
- **THEN** портал переходит в каталог, агента в нём нет

#### Scenario: Действие скрыто от сотрудника
- **WHEN** сотрудник без роли `developer` открывает карточку агента
- **THEN** действия «Архивировать агента» нет

### Requirement: Роадмап
Портал SHALL показывать любому вошедшему сотруднику раздел «Роадмап»: неархивные навыки, сгруппированные по статусам в порядке «Запланировано», «В разработке», «Тестируется», «Доработка», «Запущено». Каждый навык MUST показываться один раз, с названием, агентом и продуктами агента, и вести в карточку агента. Портал MUST предоставлять фильтр по продукту: навык остаётся, если его агент входит в выбранный продукт. Пустая группа MUST показываться с пустым состоянием. Раздел MUST иметь состояние загрузки и состояние ошибки с повтором.

#### Scenario: Группы по статусам
- **WHEN** сотрудник открывает «Роадмап»
- **THEN** навыки разложены по пяти группам статусов в заданном порядке

#### Scenario: Фильтр по продукту
- **WHEN** сотрудник выбирает продукт manager-helper
- **THEN** во всех группах остаются только навыки агентов этого продукта

#### Scenario: Навык агента из двух продуктов
- **WHEN** агент навыка входит в control-center и Telegram-бот
- **THEN** без фильтра навык показан один раз с обоими продуктами, и он остаётся при фильтре по любому из них

#### Scenario: Пустая группа
- **WHEN** ни один навык не находится в `rework`
- **THEN** группа «Доработка» показывает пустое состояние

#### Scenario: Переход к агенту
- **WHEN** сотрудник выбирает навык в роадмапе
- **THEN** открывается карточка агента этого навыка

### Requirement: Архив
Портал SHALL показывать пользователю с ролью `developer` раздел «Архив» с двумя списками: архивные агенты (название, продукты, число навыков, которые вернутся вместе с агентом, дата архивации) и архивные навыки (название, агент, продукты агента, статус, дата архивации). У каждой записи MUST быть действие «Восстановить». После восстановления запись MUST пропадать из архива и появляться в каталоге. Если сервер отвечает 409 на восстановление навыка, потому что его агент в архиве, портал MUST показывать сообщение, что сначала нужно восстановить агента. Пустые списки MUST иметь пустое состояние.

#### Scenario: Восстановить агента
- **WHEN** разработчик выбирает «Восстановить» у архивного агента
- **THEN** агент пропадает из архива и снова виден в каталоге

#### Scenario: Восстановить навык
- **WHEN** разработчик выбирает «Восстановить» у архивного навыка неархивного агента
- **THEN** навык пропадает из архива и снова виден в каталоге и в разделе «Навыки»

#### Scenario: Навык архивного агента
- **WHEN** разработчик восстанавливает навык, а сервер отвечает 409 из-за архивного агента
- **THEN** портал сообщает, что сначала нужно восстановить агента, навык остаётся в архиве

#### Scenario: Пустой архив
- **WHEN** архивных агентов и навыков нет
- **THEN** портал показывает пустые состояния обоих списков
