# task-attachments Specification

## Purpose

Работа с файлами, прикреплёнными к задачам: загрузка, скачивание и удаление вложений с ограничениями на размер и количество и безопасным хранением на диске сервера.

## Requirements

### Requirement: Загрузка вложения
Система SHALL принимать файл по `POST /tasks/{id}/attachments` в формате `multipart/form-data` (поле `file`) и возвращать метаданные вложения: идентификатор, исходное имя, размер в байтах, тип содержимого, время загрузки, загрузившего пользователя. Один запрос MUST добавлять один файл. Содержимое файла MUST сохраняться вне БД, в БД MUST храниться только метаданные.

#### Scenario: Успешная загрузка
- **WHEN** клиент отправляет файл допустимого размера для существующей задачи
- **THEN** система отвечает 201 и возвращает метаданные, а задача в последующих ответах содержит это вложение

#### Scenario: Задача не найдена
- **WHEN** клиент загружает файл к несуществующей или удалённой задаче
- **THEN** система отвечает 404 и не сохраняет файл

#### Scenario: Запрос без файла
- **WHEN** клиент отправляет multipart-запрос без поля `file` или с пустым файлом
- **THEN** система отвечает 400

### Requirement: Ограничения вложений
Система SHALL отклонять файл, размер которого превышает настроенный лимит (по умолчанию 20 МБ), ответом 413. Система MUST отклонять загрузку, если у задачи уже достигнуто максимальное число вложений (по умолчанию 10), ответом 422. Отклонённый файл MUST не оставлять следов на диске и в БД.

#### Scenario: Слишком большой файл
- **WHEN** клиент загружает файл больше лимита
- **THEN** система отвечает 413, вложение не создаётся, частично записанный файл удаляется

#### Scenario: Превышено число вложений
- **WHEN** клиент загружает файл к задаче, у которой уже максимальное число вложений
- **THEN** система отвечает 422 с кодом превышения лимита

### Requirement: Скачивание вложения
Система SHALL отдавать содержимое файла по `GET /tasks/{id}/attachments/{attachmentId}` с исходным именем файла в `Content-Disposition: attachment` и сохранённым типом содержимого. Ответ MUST содержать `X-Content-Type-Options: nosniff`. Файл MUST отдаваться только в рамках своей задачи.

#### Scenario: Скачивание
- **WHEN** клиент запрашивает существующее вложение своей задачи
- **THEN** система отвечает 200, отдаёт байты файла и заголовки с исходным именем

#### Scenario: Вложение другой задачи
- **WHEN** клиент запрашивает вложение, подставив идентификатор задачи, к которой оно не относится
- **THEN** система отвечает 404

#### Scenario: Файл потерян на диске
- **WHEN** метаданные вложения есть, а файла на диске нет
- **THEN** система отвечает 404 и фиксирует ошибку в журнале

### Requirement: Удаление вложения
Система SHALL удалять вложение по `DELETE /tasks/{id}/attachments/{attachmentId}`: запись в БД и файл на диске. Удаление MUST быть отвечено 204, повторное удаление 404.

#### Scenario: Успешное удаление
- **WHEN** клиент удаляет существующее вложение
- **THEN** система отвечает 204, вложение исчезает из задачи, файл удаляется с диска

#### Scenario: Повторное удаление
- **WHEN** клиент удаляет уже удалённое вложение
- **THEN** система отвечает 404

### Requirement: Безопасное хранение файлов
Система MUST сохранять файл на диске под сгенерированным именем, не зависящим от исходного, и MUST не использовать исходное имя в пути. Исходное имя MUST очищаться от путевых разделителей и управляющих символов и ограничиваться 255 символами перед сохранением в метаданных. Клиентский тип содержимого MUST не использоваться для исполнения: файлы отдаются только как скачиваемые.

#### Scenario: Имя с путевыми символами
- **WHEN** клиент загружает файл с именем `../../etc/passwd`
- **THEN** файл сохраняется под сгенерированным именем внутри каталога хранилища, а в метаданных имя очищено от разделителей путей

#### Scenario: Мягко удалённая задача
- **WHEN** задача удалена
- **THEN** её вложения недоступны через API, а файлы остаются на диске до отдельной очистки
