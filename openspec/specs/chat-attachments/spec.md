# chat-attachments Specification

## Purpose
Файлы в сообщениях чата с агентом: пользователь прикладывает к вопросу свои загруженные файлы, а агент может вернуть файлы в ответе. Вложения хранятся в истории чата вместе с сообщениями.

## Requirements

### Requirement: Вложения во входящем сообщении
Система SHALL принимать вместе с сообщением пользователя список идентификаторов ранее загруженных файлов, не более 5 за сообщение. Каждый файл MUST принадлежать текущему пользователю и иметь статус `active`. Если хотя бы один файл чужой, не существует или удалён, запуск MUST отклоняться до начала потока, и ничего не сохраняется. Сообщение с вложениями MUST допускать пустой текст. Сообщение без текста и без вложений MUST отклоняться как пустое.

#### Scenario: Запись встречи без текста
- **WHEN** пользователь отправляет в чат сообщение без текста с одним вложением — своей записью встречи
- **THEN** запуск агента начинается, а сообщение пользователя в истории содержит это вложение

#### Scenario: Чужой файл
- **WHEN** пользователь передаёт идентификатор файла, загруженного другим пользователем
- **THEN** запуск отклоняется ошибкой «не найдено», как для несуществующего файла, агент не запускается и ничего не сохраняется

#### Scenario: Удалённый файл
- **WHEN** пользователь передаёт идентификатор файла со статусом `deleted`
- **THEN** запуск отклоняется ошибкой с причиной «срок хранения файла истёк», ничего не сохраняется

#### Scenario: Слишком много вложений
- **WHEN** пользователь прикладывает к сообщению 6 файлов
- **THEN** запуск отклоняется ошибкой валидации, ничего не сохраняется

### Requirement: Агент видит вложения
Агент SHALL получать вместе с текстом сообщения сведения о каждом вложении: идентификатор, имя, тип, вид (`recording` или `document`) и размер. Содержимое файла MUST NOT подставляться в сообщение автоматически: агент получает его только через свои инструменты. Сведения о вложениях из прошлых сообщений этого чата MUST оставаться в контексте агента.

#### Scenario: Ссылка на прошлое вложение
- **WHEN** пользователь загрузил запись в начале чата, а через несколько сообщений пишет «извлеки задачи из этой встречи»
- **THEN** агент определяет запись по вложению из прошлого сообщения, не прося загрузить её снова

### Requirement: Файлы в ответе агента
Агент SHALL иметь возможность приложить к своему ответу файлы, созданные для пользователя в ходе запуска. Такие файлы MUST принадлежать пользователю, от имени которого работает агент. Вложения ответа MUST сохраняться в истории вместе с сообщением агента. Если запуск завершился ошибкой или отменён, файлы, созданные в этом запуске, MUST NOT попадать в историю, но могут оставаться в хранилище до истечения своего срока хранения.

#### Scenario: Агент вернул документ
- **WHEN** агент создал документ расшифровки и завершил ответ
- **THEN** сообщение агента в истории содержит вложение с этим документом

#### Scenario: Запуск отменён
- **WHEN** агент создал документ, но пользователь отменил запуск до завершения ответа
- **THEN** в истории нет сообщения агента и вложения

### Requirement: Вложения в истории чата
Каждое вложение сообщения в истории SHALL содержать идентификатор файла, имя, тип, размер, вид и текущий статус файла (`active` или `deleted`). Вложение удалённого файла MUST оставаться в истории со статусом `deleted`, чтобы клиент мог показать, что срок хранения истёк. Порядок вложений MUST совпадать с порядком при отправке.

#### Scenario: Файл удалён по сроку
- **WHEN** пользователь открывает чат, в котором месяц назад агент вернул документ, уже удалённый очисткой
- **THEN** сообщение содержит вложение со статусом `deleted`, имя и размер файла сохранены

### Requirement: Скачивание вложения
Скачивание вложения SHALL выполняться через существующую выдачу подписанной ссылки на файл и MUST быть доступно только владельцу файла. Отдельного способа скачивания для чата MUST NOT появляться.

#### Scenario: Скачивание документа из ответа
- **WHEN** владелец чата запрашивает ссылку на скачивание файла из ответа агента
- **THEN** он получает подписанную ссылку, и файл скачивается
