# tasks-extension-ui Specification

## Purpose

Компактный экран задач в side panel расширения manager-helper: быстрый доступ менеджера к своим задачам без перехода в desktop-приложение.

## Requirements

### Requirement: Переключение между чатом и задачами
Side panel SHALL позволять переключаться между «Чаты» и «Задачи» навигацией, общей с `control-center`: рейлом в планшетном режиме и нижним таб-баром в мобильном. Переключение MUST не прерывать идущий ответ ассистента и не терять состояние чата. Последний выбранный раздел MUST запоминаться между открытиями панели. Раздел задач MUST быть доступен только после входа.

#### Scenario: Переключение во время ответа
- **WHEN** ассистент отвечает, а пользователь переходит в «Задачи» и возвращается
- **THEN** ответ продолжает приходить, чат показывает актуальное состояние

#### Scenario: Запоминание раздела
- **WHEN** пользователь закрывает панель на разделе «Задачи» и открывает её снова
- **THEN** открывается «Задачи»

### Requirement: Мои задачи
Экран SHALL по умолчанию показывать представление «Мои»: задачи, где текущий пользователь ответственный, отсортированные по дедлайну (ближайшие первыми, без дедлайна — в конце). Строка содержит название, статус, дедлайн и метку просрочки текстом. Представления MUST показываться сегментированным переключателем:
- в планшетном режиме видны «Все», «Мои» и «Ещё»;
- в мобильном режиме видны «Все», «Мои», «Просрочено» со счётчиком и «Ещё»;
- в меню «Ещё» MUST быть остальные представления: «Я наблюдаю», «Созданные мной» и, в планшетном режиме, «Просрочено».

Фильтр по статусу и сортировка MUST быть доступны на второй строке под представлениями. Пользователь MUST иметь возможность искать по названию. Список постраничный с подгрузкой по запросу пользователя.

#### Scenario: Открытие экрана
- **WHEN** пользователь открывает «Задачи»
- **THEN** выбрано представление «Мои», ближайший дедлайн первым

#### Scenario: Представление из меню «Ещё»
- **WHEN** пользователь в планшетном режиме открывает «Ещё» и выбирает «Я наблюдаю»
- **THEN** список содержит задачи, где пользователь наблюдатель, а сегмент «Ещё» показан выбранным

#### Scenario: Просроченная задача
- **WHEN** дедлайн задачи в прошлом
- **THEN** строка подписана «Просрочено» и выделена акцентом

#### Scenario: Пустой экран
- **WHEN** у пользователя нет подходящих задач
- **THEN** показывается пустое состояние с действием «Создать задачу»

#### Scenario: Ошибка загрузки
- **WHEN** запрос завершился ошибкой
- **THEN** показывается сообщение и кнопка «Повторить»

### Requirement: Быстрое создание задачи
Пользователь SHALL создавать задачу из панели одним полем названия с необязательными дедлайном и ответственным (по умолчанию — текущий пользователь). В мобильном режиме быстрое создание открывается нижней шторкой с захватом и подсказкой «Enter — создать». В шторке есть:
- чипы дедлайна «Сегодня», «Завтра», «Дата…», «Без срока»;
- чипы ответственного «Я · <логин>» и «Выбрать…»;
- раскрывающийся блок «Описание и наблюдатели».

«Дата…» и «Выбрать…» MUST открывать вложенные шторки «Дедлайн» и «Ответственный» с кнопкой «Назад», которая возвращает к форме без потери введённого. Расширенные поля MUST быть доступны в раскрывающейся части формы. Отправка блокируется при пустом названии и во время запроса.

#### Scenario: Создание одним названием
- **WHEN** пользователь вводит название и подтверждает Enter
- **THEN** задача создаётся с ответственным «я», появляется в списке

#### Scenario: Дедлайн чипом
- **WHEN** пользователь в мобильной шторке вводит название, выбирает чип «Завтра» и нажимает Enter
- **THEN** задача создаётся с дедлайном на завтра

#### Scenario: Вложенная шторка
- **WHEN** пользователь нажимает «Выбрать…», а затем «Назад» во вложенной шторке «Ответственный»
- **THEN** форма быстрого создания показана с прежним названием и выбранным дедлайном

#### Scenario: Ошибка сервера
- **WHEN** сервер отклонил создание
- **THEN** введённый текст сохраняется, показана ошибка

### Requirement: Смена статуса
Пользователь SHALL менять статус задачи одним действием из строки списка и экрана деталей. Изменение отражается сразу и откатывается с сообщением при отказе сервера.

#### Scenario: Закрытие задачи
- **WHEN** пользователь отмечает задачу выполненной
- **THEN** она получает статус «Готово» и исчезает из представления «Мои»

#### Scenario: Отказ сервера
- **WHEN** запрос смены статуса завершился ошибкой
- **THEN** статус возвращается, показано сообщение

### Requirement: Детали задачи
Пользователь SHALL открывать экран деталей: описание, статус, дедлайн, создатель, ответственный, наблюдатели, вложения. Экран MUST позволять изменить название, описание, статус и дедлайн, сменить ответственного и наблюдателей, скачать, загрузить и удалить вложение. Возврат к списку MUST сохранять позицию прокрутки и фильтр.

#### Scenario: Открытие деталей
- **WHEN** пользователь выбирает задачу в списке в мобильном режиме
- **THEN** открывается экран деталей, кнопка «Назад» возвращает к списку в том же состоянии

#### Scenario: Скачивание вложения
- **WHEN** пользователь нажимает на вложение
- **THEN** файл скачивается под исходным именем

#### Scenario: Задача удалена
- **WHEN** сервер отвечает 404 на загрузку деталей
- **THEN** показывается сообщение, пользователь возвращается к списку, задача убрана

### Requirement: Планшетный режим растянутой панели
Пользователь может растянуть side panel по ширине, поэтому раздел задач SHALL иметь версию для широкой панели. При ширине панели от 640 px (тот же порог, что у чата) раздел MUST показывать два столбца: слева список с представлениями и быстрым созданием, справа детали выбранной задачи. Пока задача не выбрана, правый столбец MUST показывать подсказку «Выберите задачу». Выбор задачи, смена статуса и редактирование MUST работать без перехода между экранами. При сужении панели ниже 640 px раздел MUST вернуться к одноколоночному режиму, сохранив выбранную задачу и фильтр.

#### Scenario: Панель растянута
- **WHEN** ширина панели становится 640 px или больше
- **THEN** список и детали выбранной задачи показываются рядом, кнопка «Назад» в деталях не нужна

#### Scenario: Задача не выбрана
- **WHEN** в широкой панели ни одна задача не выбрана
- **THEN** справа показана подсказка «Выберите задачу»

#### Scenario: Сужение панели
- **WHEN** пользователь сужает панель ниже 640 px при открытой задаче
- **THEN** открывается экран деталей этой задачи, возврат к списку сохраняет фильтр и прокрутку

### Requirement: Компактная вёрстка и сессия
Экран SHALL корректно работать при ширине панели от 320 px без горизонтальной прокрутки, все действия доступны с клавиатуры, статусы и просрочка передаются текстом. Обработка потери сессии и недоступности сервера MUST совпадать с поведением чата (общий слой авторизации).

#### Scenario: Узкая панель
- **WHEN** панель имеет ширину 320 px
- **THEN** строки задач переносят текст, горизонтальной прокрутки нет

#### Scenario: Потеря сессии
- **WHEN** во время работы с задачами сессия истекла
- **THEN** показывается экран входа, как в чате

### Requirement: Загрузка и удаление вложений задачи
В деталях задачи пользователь боковой панели SHALL иметь возможность загрузить вложение и удалить своё вложение так же, как в `control-center`: с проверкой лимитов, прогрессом загрузки, понятными ошибками для слишком большого файла и неподдерживаемого типа, удаление — с подтверждением.

#### Scenario: Загрузка вложения
- **WHEN** пользователь в деталях задачи выбирает файл допустимого размера
- **THEN** виден прогресс, после загрузки файл появляется в списке вложений задачи

#### Scenario: Слишком большой файл
- **WHEN** пользователь выбирает файл больше лимита
- **THEN** файл не загружается, показано сообщение о превышении размера

### Requirement: Группы по сроку в компактном списке
В планшетном и мобильном режимах список задач, отсортированный по дедлайну, SHALL делиться на группы с подписями «Просрочено», «На этой неделе», «Позже», «Без срока». Пустые группы не показываются. При другой сортировке группы не показываются. Кнопка подгрузки следующей страницы называется «Показать ещё», без счётчика.

#### Scenario: Группы по сроку
- **WHEN** у пользователя есть просроченная задача, задача на завтра и задача без дедлайна
- **THEN** список показывает группы «Просрочено», «На этой неделе» и «Без срока», каждая со своей задачей

#### Scenario: Сортировка не по сроку
- **WHEN** пользователь выбирает сортировку по дате изменения
- **THEN** список показывается без подписей групп

### Requirement: Поиск в мобильном режиме
В мобильном режиме поиск задач SHALL открываться отдельной строкой поиска поверх шапки списка: кнопка «Назад», поле поиска и «Очистить». «Назад» MUST закрывать строку поиска и очищать запрос. «Очистить» MUST очищать поле, оставляя строку открытой.

#### Scenario: Открытие поиска
- **WHEN** пользователь в мобильном режиме нажимает поиск в шапке списка
- **THEN** открывается строка поиска с фокусом в поле, кнопками «Назад» и «Очистить»

#### Scenario: Закрытие поиска
- **WHEN** пользователь нажимает «Назад» в строке поиска
- **THEN** строка поиска закрыта, запрос очищен, список без поиска

### Requirement: Создание и детали в планшетном режиме
В планшетном режиме создание задачи SHALL открываться диалогом по центру панели с полной формой. Детали выбранной задачи в правом столбце MUST иметь кнопку «Закрыть». Она снимает выбор и возвращает подсказку «Выберите задачу».

#### Scenario: Создание на планшете
- **WHEN** пользователь в планшетном режиме нажимает «Создать задачу»
- **THEN** открывается диалог по центру панели

#### Scenario: Закрытие деталей
- **WHEN** пользователь нажимает «Закрыть» в деталях задачи в планшетном режиме
- **THEN** выбор снят, справа подсказка «Выберите задачу»
