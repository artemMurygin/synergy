# UI Design: add-meeting-transcription-agent

> **Макетов в Pencil нет (решение пользователя).** Лимит pen.dev закончился в этом расчётном периоде, и пользователь выбрал описать экраны текстом. Ниже экраны и состояния описаны словами и схемами. Это достаточная основа для реализации, потому что всё строится из уже готовых элементов Control Center. Макеты можно добавить позже в `design/synergy-design-kit.pen` → `Control Center` (`tD0BP`) → новый раздел `06 · Файлы в чате и встречи`, под `05 · Telegram`.

## Источник дизайна
- **.pen файл**: `design/synergy-design-kit.pen`, макеты не созданы (см. выше). Шаблон ссылается на `sallary-first-iteration.pen` и UI Kit `uDEum`, но в репозитории их нет (то же отклонение, что в прошлых изменениях).
- **Референсы в файле**:
  - главное окно чата `12 · Control Center · Чат (Electron)` (`WhlmQ`) и его состояния (`Qg2MW`);
  - вложения задачи в `03 · Задачи` (`NbLWY`): строка файла, перетаскивание, плашка ошибки;
  - уведомления `04 · Уведомления` (`s43f7`).
- **Компоненты и токены**: `Button / Master` (`pbEvR`), `Field / Master` (`b7hxv`), `Run Notice / Master` (`HfVTG`), токены `$brand-red`, `$brand-red-soft`, `$ink*`, `$surface*`, `$border*`, `$info`, `$info-soft`, `$r-md`, `$r-lg`, `$font-ui`. В коде это существующие классы Tailwind: `bg-surface-alt`, `text-ink-60`, `bg-brand-red-soft`, `text-brand-red`, `rounded-md`.
- **Принцип**: файлы в чате выглядят так же, как вложения задачи (`AttachmentList`): те же размеры, классы и иконки, но отдельным компонентом в `features/chat`, без изменения задач. Новых цветов и шрифтов нет.

### 1. Поле ввода с вложениями (`Composer` + `ComposerAttachments`)

```
┌─ колонка чата 720 ───────────────────────────────────────────┐
│ ┌─ карточки над полем (ряд, перенос, gap 8) ───────────────┐ │
│ │ [🎵 встреча-12-ноя.m4a  84 МБ  ▓▓▓▓▓░░ 62%   ✕]          │ │
│ │ [📄 смета.xlsx  1,2 МБ                       ✕]          │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [📎] [ Вопрос агенту…                          ] [Отправить] │
└──────────────────────────────────────────────────────────────┘
```

- **Кнопка «Прикрепить».** Иконочная кнопка `Paperclip` слева от поля, такой же высоты (`h-13`), вариант `outline`, `aria-label="Прикрепить файл"`. Открывает выбор файлов с фильтром допустимых типов (документы и записи из `file-storage`).
- **Перетаскивание.** Зона приёма — вся панель чата. Пока файл над панелью, поверх ленты показывается полупрозрачная подложка `$surface` и текст «Отпустите файлы, чтобы прикрепить» цветом `$brand-red`, как во вложениях задач.
- **Карточка над полем** (`ComposerAttachments`): строка высотой 52, фон `bg-surface-alt`, `rounded-md`, ширина по содержимому, не больше 320. Внутри иконка по виду файла (`AudioLines` для записи, `FileText` для документа), имя с обрезкой многоточием, размер `text-xs text-ink-60` и действие справа.
- **Состояния карточки:**
  - загрузка: под именем тонкая полоса прогресса `$brand-red` на `$border` и процент; действие — «Отменить загрузку» (`X`);
  - загружено: прогресса нет; действие — «Убрать» (`X`);
  - ошибка: фон `bg-brand-red-soft`, иконка `AlertCircle` `text-brand-red`, вместо размера текст ошибки; действия — «Повторить» (`RotateCw`) и «Убрать».
- **Отправка.** «Отправить» неактивна, пока есть загрузка или поле пустое и нет готовых файлов. С готовым файлом и пустым текстом кнопка активна. Пока идёт загрузка, рядом с кнопкой появляется подсказка `text-xs text-ink-60` «Дождитесь загрузки файлов».
- **Лимит.** Шестой файл не добавляется. Над полем на 4 секунды появляется плашка «К сообщению можно приложить не больше 5 файлов».

### 2. Файлы в сообщениях (`MessageAttachments` + `FileCard`)

```
                           ┌──────────────────────────────────┐
                           │ [🎵 встреча-12-ноя.m4a   84 МБ]  │  ← сообщение пользователя
                           └──────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ Расшифровка готова: 3 спикера, 1:12:40.       │  ← ответ агента
│ Напишите, кто есть кто, например:             │
│ «Спикер 1 — Анна».                            │
│ [📄 Расшифровка — встреча-12-ноя.docx  48 КБ ⬇]│
└──────────────────────────────────────────────┘
```

- **Сообщение пользователя.** Карточки идут над текстом пузыря, выровнены вправо, как сам пузырь. Сообщение из одного файла — пузырь без текста с одной карточкой.
- **Ответ агента.** Карточки идут после текста ответа, перед блоком хода работы агента. Во время потока карточка появляется в момент события `file-attached`, без ожидания конца ответа.
- **`FileCard`** — та же строка файла, что во вложениях задачи: иконка, имя, размер, действие «Скачать» (`Download`, `aria-label="Скачать <имя>"`). Нажатие на всю строку тоже скачивает файл. Во время скачивания иконка сменяется на `Loader2` с вращением.
- **Истёкший файл.** Строка `opacity-60`, курсор по умолчанию, вместо размера «Срок хранения истёк», без действия. Читается экранным диктором как неактивная (`aria-disabled`).
- **Ширина.** Карточка тянется на ширину пузыря, но не шире 360.

### 3. Сообщение системы в ленте
- Это обычный пузырь агента. Отличия: нет блока хода работы агента, а над текстом маленькая подпись `text-xs text-ink-60` с иконкой `Bell`: «Сообщение о расшифровке». По ней сообщение отличается от ответа на вопрос.
- Если чат открыт, сообщение появляется в конце ленты. Если пользователь пролистал историю вверх, лента не прокручивается сама, а внизу появляется кнопка «Новое сообщение ↓» в стиле существующей кнопки прокрутки.

### 4. Уведомление о расшифровке
- **Тексты** на сервере:
  - заголовок «Расшифровка готова», текст «встреча-12-ноя.m4a»;
  - заголовок «Не удалось расшифровать запись», текст «встреча-12-ноя.m4a».
- **Вид.** Используется существующий `NotificationItem` и всплывающее уведомление `NotificationToast`. Иконка по типу: `FileAudio` для `meeting-transcript.ready`, `AlertCircle` для `meeting-transcript.failed`.
- **Нажатие.** Открывает раздел «Чаты» и этот чат. Если чат удалён, показывается текст «Чат не найден» по образцу «Задача не найдена».

## Тексты сообщений системы (сервер)
Тексты собирает `NotifyChatOnTranscriptFinished`. Это не ответ модели, поэтому они фиксированы:

| Исход | Текст | Вложение |
|---|---|---|
| `completed` | «Расшифровка готова: {N} {спикер/спикера/спикеров}, {чч:мм:сс}. Напишите, кто есть кто, например: «Спикер 1 — Анна, Спикер 2 — Олег». Можно сразу перейти к задачам: напишите «извлеки задачи».» | `Расшифровка — {запись}.docx` |
| `no_speech` | «В записи {имя} не удалось найти речь. Проверьте, что это нужный файл, и загрузите его снова.» | — |
| `failed`: `provider-unavailable`, запись хранится | «Не удалось расшифровать {имя}: сервис распознавания сейчас недоступен. Напишите «попробуй ещё раз», и я повторю.» | — |
| `failed`: `timeout`, запись хранится | «Не удалось расшифровать {имя}: обработка заняла слишком много времени. Напишите «попробуй ещё раз», и я повторю.» | — |
| `failed`: `too-long` | «Запись {имя} длиннее 4 часов, такие пока не поддерживаются. Разделите её на части и загрузите по очереди.» | — |
| `failed`: `unsupported-media` | «Не удалось прочитать запись {имя}. Загрузите другой файл, например mp3 или m4a.» | — |

Для `provider-unavailable` и `timeout`, когда запись уже удалена, вместо «Напишите «попробуй ещё раз»…» стоит «Запись уже удалена, загрузите её заново».
