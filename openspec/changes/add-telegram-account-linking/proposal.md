## Why

Сотрудники и так весь день сидят в Telegram, а события системы (назначенная задача и т. п.) видны только в control-center и manager-helper. Нам нужен Telegram-бот, связанный с учётной записью пользователя. Он станет вторым каналом уведомлений, а потом и входом для работы с сервисами из Telegram: постановкой задач агенту текстом. Чтобы так можно было, система сначала должна надёжно знать, какому пользователю принадлежит Telegram-чат. Это изменение закладывает такую привязку и уведомления поверх неё.

## What Changes

- Backend: новый модуль `telegram`:
  - **привязка по deep-link.** Авторизованный пользователь запрашивает одноразовую ссылку `https://t.me/<bot>?start=<token>`, которая живёт 10 минут. Пользователь нажимает Start в боте, и его Telegram-аккаунт привязывается к учётной записи. Бот подтверждает привязку сообщением;
  - **ограничения привязки.** У пользователя один привязанный Telegram-аккаунт. Telegram-аккаунт может быть привязан только к одному пользователю. Новая привязка того же пользователя заменяет прежнюю;
  - **REST API для текущего пользователя:** статус привязки, выпуск ссылки, отвязка, включение и выключение уведомлений в Telegram;
  - **приём обновлений от Telegram:** webhook с секретным заголовком в окружениях с публичным адресом и long polling для локальной разработки. Бот работает только в личных чатах;
  - **команды бота:** `/start` (с токеном и без), `/help`, `/unlink`, `/mute`, `/unmute`. Если пишут из непривязанного чата, бот объясняет, как привязать аккаунт. Отключённый пользователь (`isActive = false`) считается непривязанным;
  - **канал доставки `telegram` для модуля `notifications`** из `add-realtime-notifications`. Каждое уведомление пользователя дублируется сообщением в привязанный чат, если уведомления в Telegram включены. Доставка идёт через outbox с ретраями. Повторная и параллельная обработка не шлёт сообщение второй раз; дубль возможен только при падении процесса сразу после отправки. Если пользователь заблокировал бота, привязка снимается автоматически.
- control-center: в меню аккаунта на nav rail появляется пункт «Telegram». Там можно подключить аккаунт (открыть ссылку и дождаться привязки), увидеть, к какому аккаунту выполнена привязка, переключить уведомления и отвязать аккаунт.
- manager-helper: то же в разделе «Telegram» на странице настроек расширения (options), которая открывается кнопкой настроек в side panel.

## Capabilities

### New Capabilities
- `telegram-account-linking`: привязка Telegram-аккаунта к пользователю через одноразовую deep-link-ссылку. Сюда входят ограничения привязки, статус, отвязка из приложения и из бота, распознавание пользователя по входящему сообщению, поведение бота в непривязанном чате и приём обновлений от Telegram.
- `telegram-notifications`: доставка уведомлений пользователя в привязанный Telegram-чат, переключатель уведомлений в приложении и в боте, повторы, защита от дублей и поведение при заблокированном боте.
- `telegram-linking-desktop-ui`: раздел «Telegram» в control-center: подключение, статус, переключатель уведомлений, отвязка.
- `telegram-linking-extension-ui`: тот же раздел на странице настроек manager-helper.

### Modified Capabilities
- `domain-event-outbox`: подписчик может сам отказать в доставке без повторов и может задать минимальную паузу до следующей попытки. Канал `telegram` подключается к `notifications` по требованию «Расширяемая доставка по каналам» без изменения этого требования.

## Impact

- **Зависимость:** `add-realtime-notifications` реализован и заархивирован: модуль `notifications`, порт канала доставки и outbox с подписчиками по каналам уже есть. Изменение расширяет outbox (немедленный отказ и пауза от подписчика).
- `backend/src/modules/telegram/*`: новый модуль со слоями domain, application, infrastructure, interface. В него входят агрегат привязки, хранилище одноразовых токенов в Redis, клиент Bot API, webhook-контроллер, poller, REST-контроллер и адаптер канала уведомлений.
- `backend/src/modules/auth`: модуль `telegram` читает активность и логин пользователя через публичный контракт каталога пользователей. Поведение `auth` не меняется.
- `backend/db/migrations`: таблицы `telegram_links` и `telegram_deliveries`, миграция `018_telegram.sql`.
- Конфигурация: используется существующий `TELEGRAM_BOT_TOKEN`. Добавляются `TELEGRAM_BOT_USERNAME`, `TELEGRAM_UPDATES_MODE` (`webhook | polling | off`), `TELEGRAM_WEBHOOK_URL`, `TELEGRAM_WEBHOOK_SECRET` и `TELEGRAM_LINK_TOKEN_TTL_SECONDS`, `TELEGRAM_DELIVERY_RESERVATION_MS`, все описываются в `.env.example`.
- Новый публичный эндпоинт `POST /telegram/webhook`, защищённый секретом, а не access-токеном. Эндпоинты `/telegram/link*` для пользователя.
- `control-center`: `/telegram` добавляется в `ALLOWED_PREFIXES` прокси `cc-api`, появляются UI в `features/` и пункт в `AccountMenu`.
- `manager-helper`: `src/shared/telegram-api.ts` и раздел Telegram на странице `src/options`.
- Внешняя зависимость: Telegram Bot API (HTTPS из бэкенда). Новые npm-пакеты не нужны.
- Вне рамок: постановка задач и любые другие команды агенту из Telegram (отдельное изменение поверх этой привязки), выбор типов уведомлений, групповые чаты, вход в приложение через Telegram.
