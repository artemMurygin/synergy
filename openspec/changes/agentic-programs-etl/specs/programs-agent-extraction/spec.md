## Purpose

Определить наблюдаемое поведение серверного агента, который извлекает данные каталога из группы связанных Google Sheets.

## ADDED Requirements

### Requirement: Агент обрабатывает группу связанных источников
Система SHALL запускать агента для одной заданной группы и предоставлять ему доступ к листам этой группы как к связанному набору источников.

#### Scenario: Запуск обработки группы
- **WHEN** в работу передана группа с несколькими связанными листами
- **THEN** агент может читать нужные диапазоны всех листов этой группы в рамках одного запуска

### Requirement: Агент возвращает данные каталога с происхождением
Система SHALL возвращать извлечённые программы, предложения, цены, текстовые фрагменты и справочники в структуре каталога, сохраняя для каждой записи ссылку на исходный лист и строку.

#### Scenario: Извлечение программы из нескольких листов
- **WHEN** цена и описание одной программы находятся в разных листах группы
- **THEN** агент возвращает связанные данные программы и указывает исходный лист и строку для каждой извлечённой записи

### Requirement: Агент сопоставляет извлечённые данные с текущим каталогом
Система SHALL позволять агенту искать текущие записи каталога и читать их идентификаторы, поля и связи с источниками для выбора между созданием новой записи и обновлением существующей.

#### Scenario: Изменилось название существующей программы
- **WHEN** агент находит в изменённом листе программу, которая по источнику и признакам соответствует текущей записи каталога
- **THEN** агент возвращает обновление с идентификатором этой записи, а не создание дубля

### Requirement: Агент возвращает план изменений каталога
Система SHALL принимать от агента структурированный план создания и обновления записей и применять его через прикладной порт записи, без прямого доступа агента к SQL.

#### Scenario: План содержит создание и обновление
- **WHEN** агент возвращает новую программу и изменение существующего предложения
- **THEN** application-слой создаёт программу и обновляет предложение по указанному идентификатору

### Requirement: Непредставимые отношения не искажаются
Система MUST не подменять отношения, для которых в каталоге нет подходящего представления, другими сущностями только ради их записи.

#### Scenario: Отношение не поддерживается каталогом
- **WHEN** источник описывает FAQ без привязки к программе или связь с альтернативным курсом, для которой нет сущности
- **THEN** система не записывает это отношение как сущность другого типа
