## MODIFIED Requirements

### Requirement: Статус заявки для автора
Система SHALL определять статус заявки для автора так:
- заявка без решения — «На рассмотрении»;
- отклонённая заявка — «Отклонена»;
- принятая заявка берёт статус привязанного навыка: `planned` — «Запланировано», `in_dev` — «В разработке», `testing` — «Тестируется», `launched` — «Запущено», `rework` — «Доработка».

Статус принятой заявки MUST выводиться из текущего статуса навыка в момент чтения и MUST NOT храниться отдельной копией. Для отклонённой заявки автору MUST быть видна причина отказа. Для принятой заявки автору MUST быть видны название и описание привязанного навыка. Если привязанный навык или его агент в архиве, автор MUST продолжать видеть последний статус навыка, его название и описание.

#### Scenario: Новая заявка
- **WHEN** сотрудник открывает только что поданную заявку
- **THEN** статус «На рассмотрении»

#### Scenario: Отклонённая заявка
- **WHEN** разработчик отклонил заявку с причиной «Уже есть в поставке»
- **THEN** автор видит статус «Отклонена» и причину

#### Scenario: Статус следует за навыком
- **WHEN** принятая заявка привязана к навыку, и разработчик переводит навык из `planned` в `in_dev`
- **THEN** автор без каких-либо действий над заявкой видит статус «В разработке»

#### Scenario: Доработка
- **WHEN** навык принятой заявки переходит из `launched` в `rework`
- **THEN** автор видит статус «Доработка»

#### Scenario: Навык в архиве
- **WHEN** навык принятой заявки в статусе `in_dev` архивирован
- **THEN** автор видит статус «В разработке», название и описание навыка

#### Scenario: Несколько заявок на один навык
- **WHEN** к одному навыку привязаны заявки двух авторов, и навык переходит в `launched`
- **THEN** обе заявки показывают «Запущено»

### Requirement: Решение «принять в навык»
Система SHALL позволять разработчику принять заявку на рассмотрении, привязав её к навыку одним из двух способов: выбрать существующий навык либо создать новый навык у выбранного агента (название, описание) и привязать к нему. Создание навыка и привязка заявки MUST выполняться атомарно. Привязка к несуществующему навыку или создание навыка у несуществующего агента MUST отвечаться 404. Привязка к архивному навыку, к навыку архивного агента или создание навыка у архивного агента MUST отвечаться 409, заявка остаётся на рассмотрении. Принять заявку, по которой решение уже принято, MUST отвечаться 409 без изменений. К одному навыку система MUST разрешать привязывать несколько заявок.

#### Scenario: Привязка к существующему навыку
- **WHEN** разработчик принимает заявку, выбрав существующий навык «Сводка встречи»
- **THEN** система отвечает 200, заявка привязана к этому навыку, а её статус для автора равен статусу навыка

#### Scenario: Создание нового навыка
- **WHEN** разработчик принимает заявку, создавая навык «Сверка актов» у агента Ассистент
- **THEN** навык создаётся в статусе `planned`, заявка привязывается к нему, автор видит «Запланировано»

#### Scenario: Ошибка при создании навыка
- **WHEN** принятие с созданием навыка завершается ошибкой, например нет такого агента
- **THEN** ни навык, ни привязка не создаются, заявка остаётся на рассмотрении

#### Scenario: Архивный навык
- **WHEN** разработчик принимает заявку в навык, который в архиве или чей агент в архиве
- **THEN** система отвечает 409, заявка остаётся на рассмотрении

#### Scenario: Новый навык у архивного агента
- **WHEN** разработчик принимает заявку, создавая навык у агента, который в архиве
- **THEN** система отвечает 409, навык не создаётся, заявка остаётся на рассмотрении

#### Scenario: Повторное решение
- **WHEN** разработчик пытается принять заявку, по которой решение уже принято
- **THEN** система отвечает 409, заявка и навык не меняются

#### Scenario: Решение без роли
- **WHEN** пользователь без роли `developer` пытается принять заявку
- **THEN** система отвечает 403 и заявка не меняется
