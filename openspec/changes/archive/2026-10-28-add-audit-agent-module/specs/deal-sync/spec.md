## Purpose

Периодически находит в CRM обновлённые сделки и ставит по каждой задачу аудита в очередь, без потерь и без дублей при сбоях.

## ADDED Requirements

### Requirement: Периодический запуск синхронизации
Система SHALL запускать синхронизацию с настраиваемым интервалом. При нескольких работающих инстансах приложения каждый интервал MUST порождать ровно один запуск.

#### Scenario: Плановый запуск
- **WHEN** наступает очередной интервал
- **THEN** выполняется один запуск синхронизации

#### Scenario: Несколько инстансов
- **WHEN** приложение работает в нескольких инстансах
- **THEN** за интервал выполняется один запуск, а не по одному на инстанс

### Requirement: Постановка задач аудита
Для каждой сделки, обновлённой с момента курсора, система SHALL поставить в очередь аудита одну задачу, содержащую только id сделки.

#### Scenario: Найдены обновлённые сделки
- **WHEN** CRM вернула N обновлённых сделок
- **THEN** в очередь аудита поставлено N задач, по одной на сделку, каждая с id сделки

#### Scenario: Сделка обновлена повторно, пока задача не обработана
- **WHEN** сделка с id X уже ожидает аудита, а синхронизация нашла её снова
- **THEN** вторая задача для X не создаётся

### Requirement: Курсор синхронизации
Система SHALL хранить в отдельном хранилище момент, до которого сделки уже забраны. Курсор MUST сдвигаться только после успешной постановки всех задач запуска. Если курсора нет, система MUST использовать окно по умолчанию.

#### Scenario: Успешный запуск
- **WHEN** все задачи запуска поставлены в очередь
- **THEN** курсор сдвигается на время начала этого запуска

#### Scenario: Сбой посреди запуска
- **WHEN** постановка задач прервана ошибкой
- **THEN** курсор не меняется и повторный запуск обрабатывает то же окно без пропуска сделок

#### Scenario: Курсор отсутствует
- **WHEN** запуск происходит при пустом хранилище курсора
- **THEN** используется окно по умолчанию, запуск не падает

### Requirement: Повторы при сбоях
При недоступности CRM или очереди система SHALL повторять запуск с нарастающей задержкой до настроенного лимита попыток. После исчерпания попыток сбой MUST фиксироваться в логах и метриках.

#### Scenario: Временная недоступность CRM
- **WHEN** CRM не отвечает во время запуска
- **THEN** запуск повторяется с задержкой, пока не удастся или не исчерпан лимит

#### Scenario: Лимит попыток исчерпан
- **WHEN** все попытки завершились ошибкой
- **THEN** сбой залогирован и учтён в метриках, следующий плановый запуск не блокируется
