## Why

Чат в `manager-helper` сегодня — прототип: история сообщений живёт в `useState` side panel, а память агента — в `MemorySaver` внутри процесса бэкенда (`sheets-qa`). После перезапуска бэкенда или закрытия панели всё теряется, а `sessionId` генерируется заново при каждой очистке. Менеджеру нужно вести отдельные диалоги по разным темам и возвращаться к ним позже.

## What Changes

- Добавить на бэкенде хранение чатов (сессий) и их сообщений в PostgreSQL: сессия с названием/темой, список сообщений с ролью, текстом, трассировкой tool calls и длительностью ответа.
- Добавить HTTP API управления сессиями: создать, получить список, получить сообщения сессии, переименовать, удалить.
- Привязать `POST /sheets-qa/ask` к сохранённой сессии: вопрос и ответ агента записываются в БД; несуществующий `sessionId` отклоняется.
- Заменить in-memory `MemorySaver` на постоянное хранилище контекста агента, чтобы после перезапуска бэкенда агент продолжал диалог с учётом прежней истории.
- В side panel расширения добавить раздел «Чаты»: список сессий, создание нового чата, переключение между чатами, переименование и удаление.
- При открытии панели восстанавливать последний активный чат и его историю из бэкенда; `sessionId` больше не генерируется на клиенте.
- Кнопка «очистить» заменяется созданием нового чата (история старого сохраняется).

Вне рамок: авторизация и разделение чатов по пользователям, полнотекстовый поиск по истории, синхронизация между устройствами, экспорт чатов.

## Capabilities

### New Capabilities
- `chat-sessions`: хранение в PostgreSQL чатов и их сообщений, API управления сессиями, привязка вопросов к агенту к сессии, сохранение контекста агента между перезапусками.
- `chat-session-switcher`: раздел side panel `manager-helper` со списком чатов, созданием, переключением, переименованием и удалением чатов, восстановлением активного чата при открытии.

## Impact

- **backend**: модуль `src/modules/sheets-qa` (контроллер, use-case, `DeepagentsSheetsAssistant` — замена `MemorySaver`), новые сущности/репозиторий/миграции в `src/database/postgres`, новый контроллер сессий.
- **manager-helper**: `src/sidepanel/use-chat.ts`, `App.tsx`, новые компоненты списка чатов, `src/shared/api.ts` (новые вызовы API; `askAgent` перестаёт принимать клиентский `sessionId` как источник истины).
- **Зависимости**: Postgres уже есть в проекте; возможно, понадобится постоянный checkpointer для LangGraph/deepagents (например, Postgres-вариант) — решается в design.
- **API**: новые эндпоинты сессий; контракт `POST /sheets-qa/ask` ужесточается (**BREAKING** для клиентов, передающих произвольный `sessionId` без предварительного создания сессии).
