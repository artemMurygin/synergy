## ADDED Requirements

### Requirement: Нижние шторки с захватом
Каждая нижняя шторка в мобильном режиме SHALL показывать сверху захват (grabber) — полоску 40×4 с радиусом 2. Шторку MUST можно закрыть свайпом вниз, Escape или кнопкой действия. В шторках, где макет не рисует строку заголовка, её MUST NOT быть: это шторка профиля, подтверждение удаления задачи, быстрое создание задачи, смена пароля. Фокус-ловушка и возврат фокуса сохраняются.

#### Scenario: Шторка профиля
- **WHEN** пользователь в мобильном режиме открывает меню профиля
- **THEN** шторка показывает захват сверху и пункты меню, строки «Профиль» с крестиком нет

#### Scenario: Закрытие свайпом
- **WHEN** пользователь тянет шторку за захват вниз
- **THEN** шторка закрывается, фокус возвращается на вызвавший элемент

### Requirement: Уточнённые размеры базовых элементов
Базовые элементы SHALL соответствовать мастерам UI Kit с уточнениями этого change:
- кнопки «основная», «вторичная» и «призрачная» — радиус 16;
- меню и меню профиля — радиус 20;
- поле ввода вне авторизации — серое поле `surface-alt` без обводки с радиусом 24, как поле авторизации. Мастер `Field / Master` в UI Kit приводится к этому виду.

Поля и кнопки MUST выглядеть одинаково в обоих приложениях.

#### Scenario: Кнопка в диалоге
- **WHEN** пользователь открывает любой диалог с кнопками действий
- **THEN** у основной и вторичной кнопок радиус 16

#### Scenario: Поле в форме задачи
- **WHEN** пользователь открывает форму создания задачи
- **THEN** поле названия серое, без обводки, с радиусом 24, как поле логина на экране входа

### Requirement: Состояния экранов авторизации
Ошибки на экранах входа и смены пароля SHALL показываться двухстрочным алертом: заголовок ошибки и подсказка, например «Проверьте данные и попробуйте снова.». Когда сервер ответил на вход 429, форма MUST показывать блок «Слишком много попыток входа» с иконкой таймера и текстом «Форма разблокируется автоматически…». Кнопка входа MUST быть недоступна и показывать обратный отсчёт «Повторить через м:сс». Когда время истекает, кнопка становится доступной сама. После добровольной смены пароля из меню профиля MUST показываться экран «Пароль изменён» с текстом «Все другие сеансы завершены. На этом устройстве вы остаётесь в системе.» и кнопкой возврата к работе. В `control-center` ошибка совпадения нового пароля с временным MUST звучать «Новый пароль не должен совпадать с временным», как в `manager-helper`. Эти состояния одинаковы в обоих приложениях.

#### Scenario: Лимит попыток входа
- **WHEN** сервер ответил 429 и разрешил повтор через 42 секунды
- **THEN** форма показывает «Слишком много попыток входа», кнопка недоступна с текстом «Повторить через 0:42», отсчёт идёт каждую секунду, по окончании кнопка снова доступна

#### Scenario: Неверный пароль
- **WHEN** пользователь ввёл неверный пароль
- **THEN** над формой алерт из двух строк: заголовок ошибки и «Проверьте данные и попробуйте снова.»

#### Scenario: Смена пароля из профиля
- **WHEN** пользователь сменил пароль через «Сменить пароль» в меню профиля
- **THEN** показан экран «Пароль изменён» с пояснением о завершении других сеансов, пользователь остаётся в системе

### Requirement: Всплывающие сообщения о результате действий
Приложения SHALL показывать результат действий, у которого нет своего места на экране, всплывающим сообщением (тостом) одного вида. У тоста есть иконка, заголовок, необязательное пояснение, необязательная кнопка действия («Повторить», «Открыть чат») и кнопка закрытия. Тост об успехе MUST сам скрываться через несколько секунд. Тост об ошибке с «Повторить» MUST оставаться, пока пользователь его не закроет или не нажмёт «Повторить». Тосты MUST объявляться программам чтения с экрана.

#### Scenario: Ошибка с повтором
- **WHEN** действие завершилось ошибкой, и показан тост с «Повторить»
- **THEN** тост не исчезает сам; «Повторить» повторяет действие и закрывает тост

#### Scenario: Успех
- **WHEN** задача удалена
- **THEN** показан тост об удалении, он скрывается сам через несколько секунд
