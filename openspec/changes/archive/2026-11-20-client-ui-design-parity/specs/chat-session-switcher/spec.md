## ADDED Requirements

### Requirement: Сочетание клавиш для поиска по чатам
В `control-center` поле поиска по чатам SHALL показывать подсказку «Поиск (⌘K)». Сочетание ⌘K на macOS и Ctrl+K на других системах MUST ставить фокус в поле поиска из любого места раздела «Чаты», в том числе когда список чатов скрыт: тогда список сначала показывается. Escape в поле поиска MUST очищать его и возвращать фокус в поле ввода сообщения.

#### Scenario: Фокус по сочетанию
- **WHEN** пользователь `control-center` нажимает ⌘K, пока фокус в поле ввода сообщения
- **THEN** фокус переходит в поле поиска по чатам

#### Scenario: Список скрыт
- **WHEN** список чатов скрыт, и пользователь нажимает ⌘K
- **THEN** список показывается, фокус в поле поиска

### Requirement: Меню чата в шапке
В шапке открытого чата в десктопном и планшетном режимах SHALL быть кнопка «…». Она открывает меню с пунктами «Переименовать» и «Удалить». «Переименовать» MUST включать изменение названия так же, как из списка чатов. «Удалить» MUST требовать того же подтверждения, что и удаление из списка. Для нового чата без сообщений меню MUST быть недоступно.

#### Scenario: Переименование из шапки
- **WHEN** пользователь открывает «…» в шапке чата и выбирает «Переименовать»
- **THEN** название чата становится редактируемым, а после подтверждения новое название видно в шапке и в списке

#### Scenario: Удаление из шапки
- **WHEN** пользователь выбирает «Удалить» в меню шапки и подтверждает
- **THEN** чат удалён, открыт самый свежий оставшийся чат или стартовое окно

## MODIFIED Requirements

### Requirement: Переименование и удаление чата в интерфейсе
Пользователь SHALL иметь возможность переименовать чат и удалить чат из списка через меню «…» строки чата с пунктами «Переименовать» и «Удалить». Кнопка «…» видна при наведении и у активного чата, а в мобильном режиме — всегда. Удаление MUST требовать подтверждения с иконкой корзины. Если удалён активный чат, панель MUST переключиться на самый свежий оставшийся чат или показать пустое состояние. Если сервер не принял переименование или удаление, панель MUST показать тост с заголовком, пояснением, кнопками «Повторить» и «Закрыть»:
- для переименования — «Не удалось переименовать чат», «Сервер не принял новое название, прежнее сохранено.»; прежнее название при этом возвращается;
- для удаления — «Не удалось удалить чат», «Чат остался в списке…»; чат остаётся в списке.

«Повторить» в тосте MUST повторять то же действие.

#### Scenario: Переименование
- **WHEN** пользователь выбирает «Переименовать» в меню «…» строки и задаёт новое название
- **THEN** новое название отображается в списке и в заголовке чата

#### Scenario: Удаление с подтверждением
- **WHEN** пользователь выбирает «Удалить» в меню «…» строки и подтверждает действие
- **THEN** чат исчезает из списка

#### Scenario: Отмена удаления
- **WHEN** пользователь отказывается подтвердить удаление
- **THEN** чат остаётся без изменений

#### Scenario: Удаление активного чата
- **WHEN** пользователь удаляет активный чат, а другие чаты есть
- **THEN** панель открывает самый свежий оставшийся чат

#### Scenario: Ошибка переименования
- **WHEN** сервер отвечает ошибкой на переименование
- **THEN** в списке прежнее название, показан тост «Не удалось переименовать чат» с «Повторить»; «Повторить» отправляет то же новое название

#### Scenario: Ошибка удаления
- **WHEN** сервер отвечает ошибкой на удаление
- **THEN** чат остаётся в списке, показан тост «Не удалось удалить чат» с «Повторить»

### Requirement: Форма быстрого подбора в контексте чата
В `manager-helper` в строке инструментов формы отправки, рядом с кнопкой вложений, SHALL быть кнопка «Подбор». Кнопка всегда видна, пока открыт чат, и не занимает отдельной строки. Форма быстрого подбора MUST NOT показываться в ленте чата. Нажатие на «Подбор» MUST открывать шторку «Быстрый подбор» с формой:
- в мобильном режиме — нижнюю шторку поверх чата;
- в планшетном — шторку в колонке чата, список чатов остаётся виден.

Форма содержит поля из словарей быстрого подбора: «Что ищем» («Образование» / «Курсы и ДПО»), уровень, база клиента, направления (не больше трёх), ЕГЭ, «Только с господдержкой», темы и «Своя тема» для курсов, «Сколько показать». Набор полей зависит от сегмента и уровня. Обязательных полей нет.

Под полями шторка MUST показывать превью «Запрос в чат» — ровно тот текст, который будет отправлен, — и название чата, которое он получит. Превью обновляется при каждом изменении формы. Выбор направлений MUST показывать счётчик выбранных из трёх. Когда выбрано три, остальные направления MUST быть недоступны с подсказкой, что можно выбрать до трёх.

Кнопка отправки MUST закрывать шторку и отправлять запрос в активный чат как обычный вопрос пользователя. Если у чата название по умолчанию, оно формируется из выбранных параметров, например «Бакалавриат · Медицина», а не из полного текста запроса. Пока агент отвечает, отправка из шторки MUST быть недоступна.

Значения формы MUST относиться к конкретному чату: при переключении на другой чат шторка показывает значения того чата или значения по умолчанию, а при возврате в первый чат в рамках открытой панели его значения восстанавливаются. После закрытия панели значения сбрасываются. Закрытие шторки без отправки MUST сохранять введённые значения этого чата.

#### Scenario: Новый чат
- **WHEN** пользователь создаёт новый чат
- **THEN** показано стартовое окно, формы в ленте нет, в форме отправки видна кнопка «Подбор»

#### Scenario: Чат с ответами
- **WHEN** пользователь открывает чат, где уже есть ответы агента
- **THEN** формы в ленте нет, под последним ответом показаны подсказки следующего шага, кнопка «Подбор» доступна в форме отправки

#### Scenario: Открытие шторки
- **WHEN** пользователь нажимает «Подбор» в мобильном режиме
- **THEN** открывается нижняя шторка «Быстрый подбор» со значениями по умолчанию и превью запроса по умолчанию

#### Scenario: Превью запроса
- **WHEN** пользователь выбирает уровень «Бакалавриат и специалитет» и направления «Медицина» и «Психология»
- **THEN** превью показывает собранный текст запроса с синонимами направлений и название «Бакалавриат · Медицина, Психология»

#### Scenario: Лимит направлений
- **WHEN** выбрано три направления
- **THEN** счётчик показывает три из трёх, остальные направления недоступны, видна подсказка о лимите

#### Scenario: Отправка запроса
- **WHEN** пользователь нажимает кнопку отправки в шторке
- **THEN** шторка закрывается, запрос появляется в чате как сообщение пользователя, агент начинает отвечать, кнопка «Подбор» остаётся в форме отправки

#### Scenario: Переключение во время заполнения
- **WHEN** пользователь частично заполнил форму в чате A, переключился на чат B и вернулся в чат A
- **THEN** в чате B форма со значениями по умолчанию, а в чате A восстановлены прежние значения

#### Scenario: Название по форме
- **WHEN** в новом чате пользователь отправляет запрос через форму с уровнем «Бакалавриат и специалитет» и направлением «Медицина»
- **THEN** чат получает короткое название по этим параметрам
