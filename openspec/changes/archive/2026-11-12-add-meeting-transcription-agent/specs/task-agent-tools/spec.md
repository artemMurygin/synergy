## MODIFIED Requirements

### Requirement: Действие от имени пользователя
Агент SHALL выполнять все действия с задачами от имени пользователя, с которым он ведёт диалог. Пользователь, от чьего имени выполняется действие, MUST определяться системой по аутентификации и MUST NOT зависеть от текста сообщения или от решения модели. Права пользователя MUST проверяться при каждом действии теми же правилами, что и при работе через приложение. Единственное исключение — постановщик при создании задачи: пользователь может явно указать другого постановщика. Инициатором такой задачи MUST фиксироваться собеседник агента, и права MUST проверяться для него.

#### Scenario: Попытка действовать от другого пользователя
- **WHEN** пользователь пишет агенту «измени статус задачи от имени Петра»
- **THEN** изменение, если выполняется, выполняется от имени самого пользователя, а не Петра

#### Scenario: Задача с другим постановщиком
- **WHEN** пользователь просит поставить задачу, где постановщик — Пётр, и подтверждает карточку
- **THEN** задача создаётся с постановщиком Пётр, а инициатором зафиксирован сам пользователь

#### Scenario: Нет прав на действие
- **WHEN** агент пытается выполнить действие, на которое у пользователя нет прав
- **THEN** действие не выполняется, а агент сообщает пользователю, что действие недоступно

## ADDED Requirements

### Requirement: Постановщик задачи
При создании задачи агент SHALL позволять указать постановщика — активного пользователя системы. Если постановщик не назван, постановщиком MUST становиться собеседник агента. Постановщик MUST определяться через поиск пользователей с теми же правилами неоднозначности, что и для ответственного. Карточка задачи MUST показывать постановщика по логину, а если он отличается от собеседника, то с явной пометкой.

#### Scenario: Постановщик не назван
- **WHEN** пользователь просит поставить задачу, не называя постановщика
- **THEN** в карточке постановщиком указан сам пользователь

#### Scenario: Неоднозначный постановщик
- **WHEN** пользователь называет постановщиком «Олег», а в системе два пользователя с этим именем
- **THEN** агент просит выбрать одного из них и не показывает карточку до выбора

### Requirement: Создание задач списком
Агент SHALL уметь создавать несколько задач по одному подтверждению, если список пришёл от специалиста по встречам или пользователь сам перечислил несколько задач. В списке не больше 30 задач. Перед подтверждением агент MUST:
- уточнить по каждой задаче исполнителя, постановщика, описание и срок, сопоставив названные имена с пользователями системы. Если имя совпадает с именем спикера, MUST использоваться сопоставление, уже подтверждённое пользователем;
- предложить заполнить незаполненные поля одним сообщением на весь список;
- показать итоговый список карточек с номерами.

Пользователь MUST иметь возможность исправить или исключить задачу по номеру. Любая правка MUST приводить к новому показу списка и новому запросу подтверждения. Задачи MUST создаваться только после явного подтверждения всего списка, каждая отдельно. Ошибка создания одной задачи MUST NOT отменять остальные. После создания агент MUST вывести итог по каждой задаче: создана (название, исполнитель, постановщик) или не создана и почему. Если список пришёл из встречи, агент MUST также приложить к ответу документ «Поставленные задачи» с этим итогом. Повторное подтверждение MUST NOT создавать повторные задачи.

#### Scenario: Список из трёх задач
- **WHEN** агент показал три карточки, и пользователь ответил «да, создавай»
- **THEN** создаются три задачи, а агент выводит итог по каждой

#### Scenario: Исключение задачи
- **WHEN** агент показал список, и пользователь ответил «вторую не надо»
- **THEN** агент показывает список без второй задачи и снова ждёт подтверждения, ничего не создано

#### Scenario: Частичный сбой
- **WHEN** при создании списка из трёх задач одна отклонена из-за отключённого исполнителя
- **THEN** две задачи созданы, а в итоге для третьей указана причина

#### Scenario: Документ итога для списка из встречи
- **WHEN** список задач пришёл от специалиста по встречам, и пользователь подтвердил его
- **THEN** после создания агент выводит итог в чат и прикладывает документ «Поставленные задачи»

#### Scenario: Повторное «да»
- **WHEN** список уже создан, и пользователь ещё раз пишет «да»
- **THEN** новые задачи не создаются

#### Scenario: Слишком длинный список
- **WHEN** в списке 40 задач
- **THEN** агент предлагает разбить список на части не больше 30 и не создаёт задачи одним подтверждением
