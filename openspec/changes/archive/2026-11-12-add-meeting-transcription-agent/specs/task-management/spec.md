## MODIFIED Requirements

### Requirement: Поля задачи
Система SHALL хранить для каждой задачи: идентификатор, название, описание, статус, дедлайн, создателя (постановщика), инициатора, ответственного, список наблюдателей, время создания, время последнего изменения и время закрытия. Инициатор — пользователь, который фактически выполнил создание. Обычно он совпадает с создателем. Название MUST быть строкой длиной от 1 до 200 символов после обрезки пробелов. Описание MUST быть необязательным и не длиннее 10000 символов. Дедлайн MUST быть необязательным моментом времени в формате ISO 8601 с часовым поясом. Ответственный MUST быть необязательным и единственным. Наблюдателей MUST быть не более 50, повторы MUST игнорироваться. Для задач, созданных до появления поля, инициатор MUST считаться равным создателю.

#### Scenario: Задача с минимальным набором полей
- **WHEN** клиент создаёт задачу, указав только название
- **THEN** система создаёт задачу со статусом `todo`, пустым описанием, без дедлайна, без ответственного и без наблюдателей, а создателем и инициатором становится текущий пользователь

#### Scenario: Пустое или слишком длинное название
- **WHEN** клиент создаёт или изменяет задачу, указав пустое название или название длиннее 200 символов
- **THEN** система отвечает 400 и не меняет данные

#### Scenario: Повторы среди наблюдателей
- **WHEN** клиент передаёт один и тот же идентификатор наблюдателя несколько раз
- **THEN** система сохраняет его один раз

#### Scenario: Старая задача
- **WHEN** клиент запрашивает задачу, созданную до появления поля инициатора
- **THEN** инициатор в ответе равен создателю

### Requirement: Создание задачи
Система SHALL создавать задачу по запросу `POST /tasks` и возвращать созданную задачу. Создателем и инициатором при `POST /tasks` MUST становиться пользователь из access-токена; значения, переданные в теле запроса, MUST игнорироваться. Создатель, отличный от инициатора, MUST задаваться только при создании задачи агентом по подтверждению пользователя. Инициатором при этом MUST оставаться аутентифицированный собеседник агента. Создатель, ответственный и наблюдатели MUST ссылаться на существующих активных пользователей. Задача вместе с наблюдателями MUST сохраняться атомарно. Вместе с задачей в той же транзакции система MUST фиксировать событие о создании задачи (идентификатор, название, создатель, инициатор, ответственный), чтобы другие части системы гарантированно на него отреагировали. Если событие зафиксировать не удалось, задача MUST не создаваться.

#### Scenario: Успешное создание с участниками
- **WHEN** клиент создаёт задачу с названием, описанием, дедлайном, ответственным и тремя наблюдателями
- **THEN** система отвечает 201 и возвращает задачу со всеми переданными полями, статусом `todo`, создателем и инициатором из токена

#### Scenario: Несуществующий или отключённый пользователь
- **WHEN** клиент указывает ответственного или наблюдателя, которого нет среди активных пользователей
- **THEN** система отвечает 422 с кодом, указывающим на неизвестного пользователя, и не создаёт задачу

#### Scenario: Попытка задать создателя
- **WHEN** клиент передаёт в теле `POST /tasks` поле создателя или инициатора, отличное от текущего пользователя
- **THEN** система сохраняет создателем и инициатором текущего пользователя

#### Scenario: Создание агентом с другим постановщиком
- **WHEN** агент по подтверждению пользователя A создаёт задачу с постановщиком B
- **THEN** создатель задачи — B, инициатор — A, событие о создании содержит обоих

#### Scenario: Отключённый постановщик
- **WHEN** агент создаёт задачу с постановщиком, который отключён
- **THEN** задача не создаётся, причина — неизвестный пользователь

#### Scenario: Событие о создании задачи
- **WHEN** клиент успешно создаёт задачу
- **THEN** вместе с задачей зафиксировано событие о её создании с идентификатором, названием, создателем, инициатором и ответственным

#### Scenario: Сбой при сохранении
- **WHEN** при сохранении задачи, её наблюдателей или события происходит ошибка
- **THEN** система не сохраняет ни задачу, ни наблюдателей, ни событие
