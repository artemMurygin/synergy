## Why

Фундамент уже есть: хранилище файлов (`file-storage`) и фоновая расшифровка встреч с разделением на собеседников (`meeting-transcription`). Но пользователь пока не может ими воспользоваться: в чат нельзя отправить файл, агент не умеет работать с расшифровкой, а результат нельзя получить документом. Это изменение собирает полный сценарий в чате: запись встречи → расшифровка в Word → имена спикеров → задачи из встречи → постановка задач.

## What Changes

- **Файлы в чате.** Пользователь прикладывает файл к сообщению: файл загружается через существующий `POST /files`, а в запуск агента передаётся его `fileId`. Агент может вернуть файл в ответе: в сообщении появляется карточка файла со ссылкой на скачивание. Вложения сохраняются в истории чата и показываются после перезагрузки.
- **Сегменты расшифровки в отдельной таблице.** Вместо поля `segments JSONB` в `meeting_transcript` появляется таблица `meeting_transcript_segment`: номер спикера, время начала, время конца, текст, порядковый номер. Имена спикеров хранятся отдельно: `meeting_transcript_speaker` (номер спикера → имя). Сами сегменты не переписываются. Существующие данные переносятся миграцией. **BREAKING** для `GET /transcripts/:fileId`: в ответе появляются имена спикеров. Клиентов у эндпоинта пока нет.
- **Готовая расшифровка приходит в чат сама.** Когда пользователь загрузил запись в чат, агент отвечает, что расшифровка запущена, и запуск завершается. По событию `meeting-transcript.completed` в тот же чат добавляется сообщение ассистента с файлом расшифровки `.docx` и предложением указать имена спикеров. Пользователь получает уведомление. Если речь не найдена, в чат приходит сообщение об этом, без предложения повторить. При сбое приходит понятная причина. Повтор предлагается только при временных причинах (сервис недоступен, превышено время) и пока запись хранится. В остальных случаях агент объясняет, что сделать: обрезать запись или загрузить другой файл. Если запись удалил сам пользователь, сообщение не приходит.
- **Документы Word.** Генерация `.docx` (не устаревшего бинарного `.doc`; Word и аналоги открывают `.docx` одинаково):
  - расшифровка: шапка (дата, длительность, участники), затем реплики «[чч:мм:сс] Имя: текст». Подряд идущие реплики одного спикера склеиваются;
  - задачи встречи: таблица «№, задача, описание, исполнитель, постановщик, срок, основание (цитата и таймкод)»;
  - поставленные задачи: итог постановки списка из встречи — таблица «№, задача, исполнитель, постановщик, срок, результат (создана или причина отказа)». Документ выпускает специалист по задачам после создания.
  Документы сохраняются в `file-storage` как файлы пользователя со сроком хранения документов. Сборку `.docx` выполняет общий генератор документов (код без LLM). Модули встреч и задач передают ему свою модель документа.
- **Специалист по встречам** в профиле «приложение» (рядом со специалистами по ценам и задачам). Его инструменты:
  - найти расшифровку по вложению или последнюю в чате, узнать статус;
  - показать спикеров с примерами реплик, чтобы пользователю было проще их опознать;
  - назначить имена спикерам (одним вызовом для нескольких спикеров) и выдать исправленный `.docx`;
  - извлечь задачи из расшифровки и выдать `.docx` со списком;
  - передать согласованный список задач специалисту по задачам.
  После каждого шага агент предлагает следующий: имена → извлечь задачи → создать задачи в системе. Каждый шаг выполняется только после согласия пользователя.
- **Постановка задач списком.** Специалист по задачам принимает список задач из встречи. Агент уточняет по каждой задаче исполнителя, постановщика, описание и срок, сопоставляет имена с пользователями системы через существующий поиск пользователей и показывает итоговый список карточек. После одного явного подтверждения всего списка задачи создаются. Итог по каждой задаче (создана или нет и почему) выводится в чат и прикладывается документом «Поставленные задачи». Повторное подтверждение не создаёт дубликаты.

Вне скоупа:
- Telegram: записи встреч через бота, профиль «Telegram» не меняется;
- запись встречи прямо из клиента (микрофон, захват звонка);
- редактирование текста реплик (исправляются только имена спикеров);
- автоматическое распознавание личности по голосу;
- протокол или саммари встречи, кроме списка задач;
- вложения файлов для специалиста по ценам.

## Capabilities

### New Capabilities
- `chat-attachments`: файлы во входящих сообщениях пользователя и в ответах агента: передача `fileId` в запуск, проверка владельца, хранение вложений в истории чата, ссылки на скачивание, истёкший срок хранения.
- `chat-attachments-ui`: прикрепление файла в чате приложения Electron (`control-center`): выбор и перетаскивание, прогресс загрузки, отмена, ошибки типа и размера, карточки файлов в сообщениях, скачивание, появление сообщения о готовой расшифровке в открытом чате. Расширение в этом изменении не меняется.
- `meeting-assistant`: сценарий специалиста по встречам: приём записи, сообщение о готовности расшифровки в чат, назначение имён спикеров, извлечение задач из встречи, передача списка задач на постановку, предложения следующего шага.
- `meeting-documents`: содержание и формат документов `.docx` (расшифровка, задачи встречи, поставленные задачи), их сохранение как файлов пользователя, перевыпуск после изменения имён.

### Modified Capabilities
- `meeting-transcription`: сегменты хранятся в отдельной таблице, у расшифровки появляются имена спикеров (с правом менять их только у владельца), ответ API содержит имена, появляется эндпоинт назначения имён; запоминается чат, в который отправлена запись. Спека пока лежит в изменении `add-file-storage`: его нужно заархивировать до начала этого изменения, чтобы дельта легла на `openspec/specs/meeting-transcription`.
- `assistant-agent-profiles`: в профиль «приложение» добавляется специалист по встречам. Специалист по задачам может получать поручение от специалиста по встречам.
- `task-agent-tools`: создание нескольких задач по одному подтверждению списка; постановщиком задачи может быть указанный пользователь, а не только собеседник агента. Требование «действие от имени пользователя» уточняется: права и фактический инициатор по-прежнему определяются аутентификацией.
- `task-management`: у задачи появляется поле «инициатор»: кто фактически создал задачу. Создатель (постановщик) может отличаться от инициатора только при создании через агента; `POST /tasks` по-прежнему берёт создателя из токена.
- `notifications`: уведомление «расшифровка готова» со ссылкой на чат; уведомление постановщику, если задачу от его имени поставил другой пользователь.
- `agent-streaming-protocol`: запуск агента принимает вложения (`fileIds`); в потоке событий появляется событие о файле, который вернул агент.
- `chat-sessions`: сообщения истории содержат вложения; в чат может добавить сообщение не только запуск агента, но и система (расшифровка готова). Это не считается активным запуском.

## Impact

- **БД**:
  - миграция `022_meeting_transcript_segments.sql`: таблицы `meeting_transcript_segment` и `meeting_transcript_speaker`, перенос данных из `segments JSONB`, удаление колонки;
  - вложения сообщений чата: `chat_message_attachment` или аналог (решается в design).
- **backend**:
  - `transcription/meeting`: репозиторий сегментов, назначение имён, событие о завершении уже есть;
  - новая возможность агента `meetings` (`AgentCapability`): инструменты, промпт, сборка документов;
  - `assistant`: `RunInput` с вложениями, событие файла в протоколе, добавление сообщения в чат по событию расшифровки, подключение возможности в `AgentProfileFactory`;
  - `tasks`: пакетное создание задач агентом, постановщик, поле «инициатор» (миграция `task.initiator_id`);
  - `notifications`: уведомления «расшифровка готова» и «задача поставлена от вашего имени».
- **Зависимости**: `docx` (генерация `.docx` в Node) в общем модуле `shared/documents`.
- **Клиенты**: только `control-center` (Electron): прикрепление файла, карточки файлов, прогресс, появление сообщения о готовой расшифровке в открытом чате. Расширение не меняется.
- **LLM**: извлечение задач по длинной расшифровке (1–2 часа ≈ 15–30 тыс. токенов) идёт одним вызовом; если расшифровка не помещается, нарезается кусками (решается в design). Стоимость расшифровки не меняется.
- **Решения, принятые с пользователем**:
  - постановщик — указанный пользователь: задача создаётся с ним в роли создателя, инициатором фиксируется собеседник агента, постановщик получает уведомление;
  - файлы в чате делаем только в Electron.
