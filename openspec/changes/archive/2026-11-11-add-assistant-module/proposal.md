## Why

Агентская часть живёт внутри модуля `sheets-qa`: чаты, запуск, стриминг и единственный агент (по ценовой политике) связаны между собой. Это мешает добавить второго агента (по задачам) и не позволяет собрать из разных агентов один чат. Кроме того, чат сейчас не принадлежит пользователю, а Telegram должен получить урезанного агента только для задач. Решать это нужно до того, как агентов станет больше, иначе каждый новый агент и канал придётся встраивать в `sheets-qa`.

## What Changes

- Новый backend-модуль `assistant`: хранилище чатов и сообщений, запуск агента, стриминг, отмена, один активный запуск на чат. Всё это переезжает из `sheets-qa` без изменения внешних HTTP-контрактов для приложений.
- Чат принадлежит пользователю и доступен из любого приложения этого пользователя. Чужие чаты недоступны (для постороннего чат «не найден»).
- Агент собирается по **профилю клиента**. Профилей два:
  - `app` — оркестратор (deep agent) с подагентами: ценовая политика (`sheets-qa`, изолированный контекст) и задачи (видит историю чата);
  - `telegram` — обычный агент без подагентов и оркестратора, только с инструментами задач.
- Клиент определяется по заголовку запроса `X-Client-App` (`manager-app`, `employee-app`); Telegram определяется самим каналом и заголовком задаваться не может. Сейчас оба приложения используют профиль `app`; фабрика принимает идентификатор клиента, чтобы позже развести профили без переделки чатов. Заголовок выбирает только профиль и не влияет на права.
- Модули `tasks` и `sheets-qa` предоставляют `assistant` свою **возможность** (имя, описание, инструменты, промпт); `assistant` собирает из них агентов и ничего не знает об их внутренностях. Агент по задачам и его инструменты живут в `tasks`, агент по ценам остаётся в `sheets-qa`.
- Инструменты задач вызывают существующие сценарии модуля `tasks` от имени пользователя, который пишет агенту; подменить пользователя LLM не может. Права проверяются в инструментах.
- Telegram: свободный текст привязанного пользователя передаётся агенту профиля `telegram` через существующий порт обработчика свободного текста. У Telegram отдельный диалог пользователя, он не показывается в списке чатов приложений.
- **BREAKING**: существующие чаты не имеют владельца. Судьба старых чатов (удаление или иное) определяется в design; по умолчанию они удаляются вместе с данными агента.

Вне скоупа: разные наборы возможностей для приложения руководителя и приложения сотрудника (сейчас одинаковые), голосовой ввод, удаление задач и работа с вложениями через агента, общие чаты нескольких людей, вопросы по ценовой политике в Telegram.

## Capabilities

### New Capabilities
- `assistant-agent-profiles`: выбор профиля агента по клиенту (`app`, `telegram`), состав профилей, определение клиента по заголовку `X-Client-App`, поведение при неизвестном значении, подключение возможностей модулей.
- `task-agent-tools`: что агент умеет делать с задачами (создание, поиск, изменение), как действует от имени пользователя и как отказывает при нарушении прав.
- `telegram-assistant-chat`: работа привязанного пользователя с агентом в Telegram — отдельный диалог, только задачи, отказ на темы вне задач, скрытие диалога из списков приложений.

### Modified Capabilities
- `chat-sessions`: у чата появляется владелец, доступ только владельцу, один чат виден из всех приложений пользователя, диалоги Telegram скрыты из списка, меняется требование о сохранности существующих чатов.
- `agent-streaming-protocol`: запуск агента выполняется от имени аутентифицированного пользователя и по профилю его клиента.
- `telegram-account-linking`: требование «Свободный текст от привязанного пользователя» меняется с ответа «не поддерживается» на передачу агенту.

## Impact

- **backend**: новый модуль `assistant`; `sheets-qa` теряет чаты и запуск и сохраняет только агента по ценам и его данные; `tasks` получает слой агента (`interface/agent`); `telegram` подключает реализацию порта обработчика свободного текста; `auth` — определение клиента запроса.
- **БД**: миграция таблицы чатов (владелец, канал), перенос в новый модуль, обработка существующих чатов и их checkpoint-данных.
- **HTTP API**: эндпоинты чатов и агента фильтруют по текущему пользователю и читают `X-Client-App`; пути и формат событий сохраняются. Заголовок нужно разрешить в CORS.
- **Клиенты** (control-center, manager-helper): каждое приложение добавляет в запросы чатов и агента заголовок `X-Client-App` со своим значением. Без заголовка всё продолжает работать (профиль «приложение»), поэтому выкладка клиентов не блокирует backend.
- **Параллельное изменение `add-telegram-voice-task-agent`** будет удалено и переписано заново после этого изменения, поэтому конфликтов требований нет: данное изменение — основа, на которой строится новая версия.

## Допущения

- Набор инструментов задач: создать задачу, найти задачи, найти пользователей, изменить задачу (заголовок, описание, статус, срок, ответственный, наблюдатели). Удаление задач и вложения не входят.
- Заголовок `X-Client-App` задаётся самим клиентом и подделывается. Пока у приложений один профиль и права проверяются независимо от клиента, это допустимо. Если профили начнут различаться доступом к чувствительным возможностям, заголовок нельзя считать границей безопасности.
- Существующий заголовок `X-Client-Type` (`desktop` или cookie) отвечает за способ передачи токенов и для выбора профиля не используется.
