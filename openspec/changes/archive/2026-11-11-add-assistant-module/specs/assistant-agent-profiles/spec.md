## Purpose

Определяет, какой агент отвечает пользователю в зависимости от клиента, через который он пишет: приложения или Telegram. Профиль задаёт набор возможностей агента и исключает доступ к лишним функциям в ограниченных каналах.

## ADDED Requirements

### Requirement: Профиль агента по клиенту
Система SHALL определять профиль агента по клиенту, от которого пришёл запрос. Клиентов три: приложение руководителя, приложение сотрудника и Telegram. Приложение руководителя и приложение сотрудника MUST использовать профиль «приложение», Telegram MUST использовать профиль «Telegram». Профиль MUST определять набор возможностей агента: какие темы он обрабатывает и какими инструментами пользуется.

#### Scenario: Запрос из приложения руководителя
- **WHEN** пользователь отправляет вопрос из приложения руководителя
- **THEN** вопрос обрабатывает агент профиля «приложение»

#### Scenario: Запрос из приложения сотрудника
- **WHEN** пользователь отправляет вопрос из приложения сотрудника
- **THEN** вопрос обрабатывает агент профиля «приложение» с тем же набором возможностей, что и у руководителя

#### Scenario: Сообщение из Telegram
- **WHEN** привязанный пользователь пишет боту
- **THEN** сообщение обрабатывает агент профиля «Telegram»

### Requirement: Клиент определяется заголовком запроса
Приложение SHALL указывать себя в заголовке запроса `X-Client-App` со значением `manager-app` (приложение руководителя) или `employee-app` (приложение сотрудника), и система MUST определять клиента по этому заголовку, а не по телу запроса. Если заголовок отсутствует, система MUST обрабатывать запрос как запрос из приложения с профилем «приложение». Заголовок с неизвестным значением, а также со значением `telegram` MUST отклоняться ошибкой валидации без запуска агента. Клиент «Telegram» MUST определяться только самим каналом Telegram и MUST NOT задаваться заголовком HTTP-запроса. Заголовок определяет только выбор профиля и MUST NOT влиять на права пользователя: права проверяются независимо от клиента.

#### Scenario: Заголовок приложения
- **WHEN** запрос содержит `X-Client-App: employee-app`
- **THEN** система определяет клиента как приложение сотрудника и использует его профиль

#### Scenario: Заголовка нет
- **WHEN** запрос от приложения не содержит заголовка `X-Client-App`
- **THEN** система использует профиль «приложение», запрос выполняется как обычно

#### Scenario: Неизвестное значение заголовка
- **WHEN** запрос содержит `X-Client-App: unknown-app`
- **THEN** система отклоняет запрос ошибкой валидации, агент не запускается и ничего не сохраняется

#### Scenario: Попытка выдать себя за Telegram
- **WHEN** HTTP-запрос содержит `X-Client-App: telegram`
- **THEN** система отклоняет запрос ошибкой валидации, профиль «Telegram» не применяется

#### Scenario: Значение клиента в теле запроса
- **WHEN** тело запроса содержит поле с именем клиента
- **THEN** система игнорирует это поле и определяет клиента только по заголовку

### Requirement: Состав профиля «приложение»
Агент профиля «приложение» SHALL самостоятельно решать по содержанию вопроса, чем отвечать: вопросы о ценовой политике он MUST передавать специалисту по ценовой политике, вопросы о задачах — специалисту по задачам. Специалист по ценовой политике MUST получать только текст поручения. Специалист по задачам MUST получать также историю текущего чата. Один чат MUST допускать вопросы обоих видов подряд.

#### Scenario: Вопрос о ценах
- **WHEN** пользователь спрашивает о ценовой политике в чате
- **THEN** ответ формирует специалист по ценовой политике, а пользователь видит один общий ответ в чате

#### Scenario: Вопрос о задачах
- **WHEN** пользователь просит поставить задачу в чате
- **THEN** запрос выполняет специалист по задачам с учётом предыдущих сообщений чата

#### Scenario: Смена темы в одном чате
- **WHEN** пользователь сначала спрашивает о ценах, а затем в том же чате просит найти свои задачи
- **THEN** оба вопроса получают ответ специалиста по своей теме, а история чата содержит оба обмена

### Requirement: Состав профиля «Telegram»
Агент профиля «Telegram» SHALL работать только с задачами. Он MUST NOT иметь инструментов и специалистов за пределами работы с задачами, включая вопросы по ценовой политике. На запрос вне темы задач агент MUST ответить, что умеет только работать с задачами, и MUST NOT выполнять никаких действий.

#### Scenario: Вопрос о ценах в Telegram
- **WHEN** привязанный пользователь спрашивает бота о ценовой политике
- **THEN** бот отвечает, что работает только с задачами, и не обращается к данным о ценах

#### Scenario: Запрос о задаче в Telegram
- **WHEN** привязанный пользователь просит бота найти свои задачи
- **THEN** бот выполняет поиск задач и возвращает результат

### Requirement: Возможности подключаются модулями
Каждая предметная область (задачи, ценовая политика) SHALL предоставлять свою возможность агента отдельно от общей сборки: название, описание для выбора, инструменты и инструкции. Добавление возможности в профиль или удаление её из профиля MUST NOT требовать изменений в самой предметной области.

#### Scenario: Одна возможность в двух профилях
- **WHEN** возможность работы с задачами подключена и в профиль «приложение», и в профиль «Telegram»
- **THEN** инструменты и инструкции по задачам в обоих профилях совпадают

### Requirement: Расширяемость профилей
Система SHALL позволять назначить отдельный профиль любому из клиентов без изменения чатов и их истории. Пока отдельный профиль не назначен, клиент MUST использовать профиль «приложение».

#### Scenario: Отдельный профиль для клиента
- **WHEN** для приложения сотрудника задан собственный профиль
- **THEN** чаты и история пользователя остаются прежними, а новые запросы из этого приложения обрабатывает агент нового профиля
