## Why

После `add-assistant-module` бот в Telegram уже передаёт свободный текст агенту задач, а у пользователя есть отдельный Telegram-диалог. Но голосовые сообщения бот не принимает, хотя ставить задачи голосом на ходу — основной сценарий. Ответ приходит только после долгой синхронной обработки, без индикатора. Диалог нельзя начать заново. Агент создаёт задачу сразу, без проверки пользователем. Это изменение закрывает эти пробелы. Приоритет — скорость, поэтому строим на уже готовых модулях `assistant`, `tasks` и `telegram`.

## What Changes

- Новый backend-модуль транскрибации: принимает голосовую запись (`ogg/opus` из Telegram) и возвращает текст. Первый провайдер — `google/gemini-3.1-flash-lite` через OpenRouter. Лимиты по длительности и размеру, понятные отказы.
- Telegram принимает голосовые сообщения привязанного пользователя: скачивает файл, расшифровывает, показывает распознанный текст и передаёт его агенту так же, как написанный.
- На сообщения других типов (фото, документы, стикеры) бот отвечает, что понимает только текст и голос.
- Сообщения для агента обрабатываются в фоне: бот сразу принимает обновление Telegram, показывает «печатает…» до ответа, длинный ответ отправляет несколькими сообщениями.
- Команда `/new` начинает Telegram-диалог с агентом заново: прежний диалог и его контекст удаляются.
- Скилл агента задач «постановка задачи»: перед созданием агент собирает поля, дозапрашивает незаполненное, показывает карточку и создаёт задачу только после явного подтверждения пользователя. Скилл действует в обоих профилях (`app` и `telegram`), без HITL-прерываний.
- Агент задач знает текущую дату и время по Москве, чтобы превращать «завтра» и «до пятницы» в конкретный срок.

Уже сделано в `add-assistant-module` и сюда не входит: владелец и канал чата, удаление старых чатов, отдельный Telegram-диалог, передача свободного текста агенту, инструменты задач (`create_task`, `search_tasks`, `find_users`, `update_task`), отказ на темы вне задач.

Вне скоупа: голосовой ввод в Electron-приложении и расширении, inline-кнопки подтверждения, надёжная очередь (переживание рестарта), ФИО пользователей для поиска исполнителя.

## Capabilities

### New Capabilities
- `voice-transcription`: преобразование голосовой записи в текст — формат, лимиты длительности и размера, ответ «речь не распознана», поведение при сбое провайдера, запрет логировать содержимое.

### Modified Capabilities
- `telegram-assistant-chat`: голосовые сообщения, фоновая обработка с индикатором «печатает…», ответы несколькими сообщениями, команда `/new`.
- `telegram-account-linking`: требование «Свободный текст от привязанного пользователя» дополняется голосовыми сообщениями и ответом на неподдерживаемые типы.
- `task-agent-tools`: требование «Создание задачи агентом» меняется — обязательная карточка и подтверждение перед созданием, дозапрос необязательных полей, относительные даты по Москве.

`telegram-assistant-chat` и `task-agent-tools` появляются в основных спеках при архивации `add-assistant-module`. Его нужно заархивировать до этого изменения.

## Impact

- **backend**:
  - новый модуль транскрибации;
  - `telegram`: разбор голоса и прочих типов сообщений, `getFile` и скачивание через Bot API, фоновая очередь на чат, «печатает…», нарезка ответа, `/new`;
  - `assistant`: сценарий сброса Telegram-диалога (удаление сессии и thread из checkpointer);
  - `tasks`: скилл постановки задачи и текущая дата в промпте агента задач.
- **БД**: без миграций; `/new` удаляет строку Telegram-диалога (уникальный индекс «один Telegram-диалог на владельца» остаётся).
- **HTTP API и клиенты**: без изменений.
- **Зависимости и инфраструктура**: ключ OpenRouter уже используется. Если провайдер не примет `ogg/opus`, понадобится `ffmpeg` в Docker-образе backend.
- **Стоимость**: около $0,0016 за 90 секунд голоса по бенчмарку.
