## ADDED Requirements

### Requirement: Отделы, которым доступен продукт
Система SHALL хранить для каждого продукта набор отделов из справочника отделов (`employee-directory`), которым этот продукт доступен. Набор MAY быть пустым, что означает «доступность не указана». Набор MUST быть справочной пометкой: он MUST NOT влиять на то, какие продукты, агенты, навыки, инструкции и формы видит пользователь, и на его права. Каталог (`GET` каталога) и список продуктов агента в ответах каталога MUST содержать у каждого продукта отделы набора (идентификатор и название), упорядоченные по названию. Удаление отдела из справочника MUST убирать его из наборов всех продуктов, а продукт MUST оставаться без изменений.

#### Scenario: Продукт с отделами в каталоге
- **WHEN** продукту control-center назначены отделы «КЦ 2» и «КЦ 1», и сотрудник без ролей запрашивает каталог
- **THEN** у продукта control-center отделы «КЦ 1» и «КЦ 2» в этом порядке

#### Scenario: Доступность не указана
- **WHEN** продукту не назначено ни одного отдела
- **THEN** в каталоге у продукта пустой список отделов

#### Scenario: Пометка не ограничивает доступ
- **WHEN** продукт доступен только отделу «КЦ 1», а каталог запрашивает сотрудник отдела «Бухгалтерия»
- **THEN** сотрудник видит продукт, его агентов и навыки так же, как сотрудник «КЦ 1»

#### Scenario: Удаление отдела
- **WHEN** администратор удаляет пустой отдел «КЦ 3», назначенный двум продуктам
- **THEN** у обоих продуктов в каталоге больше нет «КЦ 3», остальные отделы на месте

### Requirement: Назначение отделов продукту
Система SHALL позволять пользователю с ролью `admin` задать набор отделов продукта целиком: переданный список заменяет прежний набор. Повторы в списке MUST схлопываться. Пустой список MUST очищать набор. Успешный запрос MUST отвечать 200 и продуктом с новым набором отделов. Если хотя бы один отдел не найден, система MUST отвечать 404 и MUST NOT менять набор. Неизвестный продукт или некорректный идентификатор продукта MUST отвечаться 404. Пользователю без роли `admin` MUST отвечаться 403, в том числе разработчику. Запрос без access-токена MUST отвечаться 401. Число отделов в запросе MUST быть ограничено установленным пределом, превышение — 400.

#### Scenario: Администратор задаёт отделы
- **WHEN** администратор задаёт продукту manager-helper отделы «КЦ 1» и «КЦ 2»
- **THEN** система отвечает 200, у продукта ровно эти два отдела

#### Scenario: Замена набора
- **WHEN** у продукта отделы «КЦ 1» и «КЦ 2», и администратор задаёт только «КЦ 3»
- **THEN** у продукта остаётся один отдел «КЦ 3»

#### Scenario: Очистить набор
- **WHEN** администратор задаёт продукту пустой список
- **THEN** у продукта нет отделов

#### Scenario: Неизвестный отдел
- **WHEN** в списке есть идентификатор отдела, которого нет в справочнике
- **THEN** система отвечает 404, набор продукта не меняется

#### Scenario: Разработчик без роли admin
- **WHEN** пользователь с ролью `developer` без роли `admin` задаёт отделы продукта
- **THEN** система отвечает 403
