## Why

Агент должен работать с файлами пользователя: Excel-таблицами, Word-документами и записями встреч. Сейчас файлы умеют хранить только вложения задач, и только на локальном диске контейнера (без volume, поэтому при пересборке они теряются). Общего хранилища для чата нет, срока хранения нет, а запись встречи никто не расшифровывает. Это изменение закладывает фундамент: хранилище файлов со сроком жизни и фоновую расшифровку записей встреч с разделением на собеседников. Сценарии агента (заполнение таблиц, задачи из встречи, файлы в чате) пойдут отдельными изменениями поверх этого.

## What Changes

- **MinIO** в `docker-compose` (S3-совместимое хранилище): свой volume, проверка готовности, бакет создаётся бэкендом при старте. Наружу MinIO не публикуется, файлы отдаёт только бэкенд.
- Новый backend-модуль **`files`**:
  - загрузка файла (`POST /files`, multipart) потоком прямо в MinIO;
  - метаданные (`GET /files/:id`), удаление (`DELETE /files/:id`);
  - скачивание по короткоживущей подписанной ссылке (`POST /files/:id/download-link` → `GET /files/:id/content?token=…`). Ссылка работает в Chrome Extension и Electron без заголовка `Authorization`.
  - Доступ только у владельца, чужой файл неотличим от несуществующего (404).
  - Белый список типов, тип определяется по содержимому, а не по расширению. Лимиты размера отдельно для записей и для документов.
- **Срок хранения**:
  - записи (аудио и видео) — 1 день, отсчёт начинается после завершения расшифровки. Пока расшифровка идёт, запись не удаляется, но не дольше 7 дней;
  - остальные файлы — 30 дней;
  - ежедневная очистка (BullMQ) удаляет просроченные файлы из MinIO. Строка метаданных остаётся со статусом «удалён», чтобы потом показать в чате «срок хранения истёк».
- Событие **`file.uploaded`** через существующий outbox.
- **Фоновая расшифровка встреч** в модуле `transcription`:
  - по событию `file.uploaded` для каждой записи сразу ставится задача в очередь BullMQ;
  - провайдер — `elevenlabs/scribe-v2` через OpenRouter (`/audio/transcriptions`, тот же ключ, что уже используется), с разделением на собеседников (`diarize`);
  - у OpenRouter лимиты 25 МБ и 60 секунд на запрос, поэтому `ffmpeg` перекодирует запись в mono opus и режет её на куски по 10 минут (каждый заведомо меньше 20 МБ) с перекрытием 30 секунд. Метки спикеров между кусками сопоставляются по словам в перекрытии, чтобы «Спикер 1» был одним человеком на всю запись;
  - результат: сегменты «спикер, начало, конец, текст», язык, длительность, число спикеров;
  - расшифровка сохраняется в БД и остаётся после удаления записи;
  - API `GET /transcripts/:fileId` (статус и сегменты) и `POST /transcripts/:fileId/retry` (повтор после сбоя, пока запись не удалена);
  - события `meeting-transcript.completed` и `meeting-transcript.failed` через outbox (подписчиков пока нет).
- Корень BullMQ (`BullModule.forRootAsync`) переезжает из `audit-agent` в общий модуль: новым очередям он нужен без зависимости от `audit-agent`.

Вне скоупа:
- файлы в чате и инструменты агента для файлов;
- создание задач по встрече (отдельное изменение);
- UI загрузки и скачивания в клиентах;
- перевод вложений задач (`task-attachments`) на MinIO;
- загрузка частями с докачкой;
- прямой API ElevenLabs (недоступен).

## Capabilities

### New Capabilities
- `file-storage`: загрузка, метаданные, скачивание по подписанной ссылке и удаление файлов пользователя; типы, лимиты, доступ владельца; срок хранения по виду файла, удержание на время обработки, ежедневная очистка, событие о загрузке.
- `meeting-transcription`: фоновая расшифровка записей встреч с разделением на собеседников: автоматический запуск, статусы, повтор, хранение результата после удаления записи, приватность логов.

### Modified Capabilities
Нет. `task-attachments` и `voice-transcription` (из `add-telegram-voice-task-agent`) не меняются.

## Impact

- **Инфраструктура**:
  - сервис `minio` в `backend/docker-compose.yml`;
  - `ffmpeg` и `ffprobe` в Docker-образе бэкенда (`apk add ffmpeg`);
  - новые env: `S3_*`, `FILES_*`, `MEETING_TRANSCRIPTION_*`. Новых внешних ключей нет: используется `OPENROUTER_API_KEY`;
  - если перед бэкендом стоит reverse proxy, его лимит тела запроса нужно поднять до лимита записей.
- **БД**: миграции `020_files.sql` (`stored_file`) и `021_meeting_transcripts.sql` (`meeting_transcript`).
- **backend**:
  - новый модуль `files`;
  - модуль `transcription` расширяется: расшифровка встреч, подписчик, BullMQ-процессор, HTTP-контроллер;
  - `shared/queue` (корень BullMQ);
  - `audit-agent` перестаёт сам регистрировать корень BullMQ.
- **Зависимости**: `@aws-sdk/client-s3`, `@aws-sdk/lib-storage`, `file-type`. `@nestjs/jwt` уже есть: подписанные ссылки делаем на нём.
- **Пересечение**: модуль `transcription` сейчас создаётся в `add-telegram-voice-task-agent` (изменения ещё не закоммичены). Это изменение реализуется после него и не меняет `TranscribeVoiceUseCase`.
- **Стоимость**: `elevenlabs/scribe-v2` через OpenRouter — примерно $0,22 за час записи (по бенчмарку $0,0052 за 85 с), плюс около 5% на перекрытие кусков.
- **HTTP API и клиенты**: новые эндпоинты, существующие не меняются.
