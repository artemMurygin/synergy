## ADDED Requirements

### Requirement: Переход к заявке в портале
Приложение SHALL по клику на уведомление со ссылкой на объект типа `request` отмечать уведомление прочитанным и открывать в браузере по умолчанию страницу этой заявки в портале Featurer. Адрес портала MUST задаваться конфигурацией приложения. Приложение MUST открывать только адрес, принадлежащий настроенному порталу, и MUST корректно кодировать идентификатор заявки в адресе. Если адрес портала не настроен, приложение MUST оставить уведомление прочитанным и сообщить, что портал недоступен, не ломая список уведомлений. Приложение MUST NOT открывать портал внутри собственного окна.

#### Scenario: Клик по уведомлению о заявке
- **WHEN** пользователь кликает по уведомлению `request.accepted` в списке или во всплывающем уведомлении
- **THEN** уведомление становится прочитанным, а в браузере по умолчанию открывается страница этой заявки в портале

#### Scenario: Портал не настроен
- **WHEN** пользователь кликает по уведомлению о заявке, а адрес портала в конфигурации не задан
- **THEN** уведомление становится прочитанным, приложение сообщает, что портал недоступен, остальные уведомления работают как прежде

#### Scenario: Чужой адрес
- **WHEN** уведомление о заявке содержит идентификатор, из которого нельзя составить адрес настроенного портала
- **THEN** приложение не открывает браузер и показывает понятное сообщение

#### Scenario: Прочие уведомления
- **WHEN** пользователь кликает по уведомлению о задаче или чате
- **THEN** поведение не меняется
