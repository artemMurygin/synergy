## Why

Идеи по автоматизации и жалобы на агентов приходят хаотично: в личку, в чаты, голосом. Идеи теряются, автор не знает, что стало с его предложением, а эффект от ИИ нечем показать. Featurer — внутренний портал, который это решает (см. `FEATURER_ROADMAP.md`). Перед тем как строить его по частям, нужен самый тонкий сквозной срез: один путь «идея → решение → запуск → автор узнал» через все слои. Так архитектурные решения (модель заявки и навыка, вывод статуса, уведомления, веб-вход) проверятся сразу, а следующие этапы будут наращивать работающий каркас, а не собирать его с нуля.

## What Changes

- **Роль разработчика.** Появляется хранение ролей пользователя, пока с одной ролью `developer`. Роль назначается seed'ом или SQL, интерфейса управления ролями нет. Действия разработчика (очередь, решения, навыки) доступны только с этой ролью. Профиль текущего пользователя возвращает его роли, чтобы портал показывал нужные разделы.
- **Минимальный каталог.** Продукты (control-center, manager-helper, Telegram-бот, веб) и их агенты заводятся seed'ом. Навык принадлежит агенту, у него есть название, описание и статус `planned → in_dev → testing → launched`. Разработчик создаёт навык при решении по заявке и двигает его статус. Сотрудник видит навык, к которому привязана его заявка.
- **Подача идеи.** Любой вошедший сотрудник подаёт идею по короткой анкете: название, описание процесса, частота (в день, неделю или месяц), минут за один раз, сколько человек так делают.
- **Мои заявки.** Сотрудник видит свои заявки с понятным статусом: «На рассмотрении», «Отклонена» с причиной, «Запланировано», «В разработке», «Тестируется», «Запущено».
- **Очередь и решение.** Разработчик видит очередь новых заявок, открывает заявку и принимает одно из двух решений: принять с привязкой к навыку (выбрать существующий или создать новый у выбранного агента) или отклонить с обязательной причиной.
- **Статус выводится автоматически.** После принятия статус заявки для автора берётся из статуса навыка. Разработчик меняет только навык, заявки обновляются сами. Несколько заявок можно привязать к одному навыку.
- **Уведомления.** При решении по заявке и при каждой смене статуса привязанного навыка автор получает уведомление через существующий конвейер: outbox → правило уведомлений → приложение и Telegram. Появляется новый тип объекта уведомления — `request`.
- **Переход из уведомлений в портал.** Клик по уведомлению типа `request` в `control-center` и в расширении `manager-helper` открывает страницу заявки в портале в браузере. Для этого портал получает прямую ссылку на заявку, а клиенты получают адрес портала в конфигурации.
- **Веб-портал `portal/`.** Новое веб-приложение: вход существующей учёткой (refresh-токен в cookie, как у расширения), анкета, «Мои заявки», для разработчика — очередь, экран решения и список навыков со сменой статуса. Origin портала добавляется в белый список cookie-эндпоинтов. Минимальный UI на токенах дизайн-кита, без полировки.

Вне скоупа (следующие этапы роадмапа):
- отделы, ФИО, роли кроме `developer`, интерфейс администратора (Э1);
- управление продуктами и агентами из интерфейса, публичный каталог и роадмап (Э2);
- расширенная анкета, оценка трудозатрат, решения «нужны уточнения», «дубликат», «новый агент», «новый продукт» (Э3);
- комментарии, внутренние заметки, показ заявки внутри control-center и manager-helper (Э4); в этом этапе клиенты только открывают портал;
- баги, голоса, инструкции, доступы отделов к продуктам (Э5–Э7).

## Capabilities

### New Capabilities
- `user-roles`: хранение ролей пользователя (пока только `developer`), назначение через seed, проверка роли на эндпоинтах, роли в профиле текущего пользователя.
- `featurer-catalog`: продукты и агенты из seed'а, навыки агентов, жизненный цикл статуса навыка, создание навыка и смена статуса разработчиком.
- `featurer-requests`: подача идеи, «Мои заявки», очередь разработчика, решения «принять в навык» и «отклонить с причиной», вывод статуса заявки из статуса навыка, события смены статуса заявки.
- `featurer-portal-ui`: веб-портал: вход и сессия, анкета идеи, «Мои заявки» со статусами, очередь и экран решения, список навыков со сменой статуса, видимость разделов по роли.

### Modified Capabilities
- `notifications`: новый тип объекта `request`; уведомление автора при решении по заявке и при смене статуса привязанного навыка.
- `notifications-desktop-ui`: клик по уведомлению `request` открывает заявку в портале в браузере.
- `notifications-extension-ui`: то же для боковой панели и системных уведомлений расширения.

## Impact

- **backend:** миграции (роли пользователей, продукты, агенты, навыки, заявки), seed продуктов и агентов, новый модуль Featurer (домен, use cases, HTTP API), новые события в outbox, новое правило в модуле `notifications`, роли в профиле в модуле `auth`.
- **portal/:** новое приложение на стеке control-center (React 19, Vite, TanStack Query, zustand, Tailwind 4).
- **Конфигурация:** origin портала в белом списке `OriginGuard`; хостинг портала и SameSite cookie `mh_refresh` проверяются в design.
- **control-center, manager-helper:** обработка клика по уведомлению `request` (открыть портал в браузере) и адрес портала в конфигурации клиента. Остальное поведение уведомлений не меняется.
- **Telegram:** доставка работает без изменений, по общему конвейеру.
