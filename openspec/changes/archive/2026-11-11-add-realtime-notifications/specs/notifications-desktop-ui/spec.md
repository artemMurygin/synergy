## Purpose

Уведомления в desktop-приложении control-center: индикатор непрочитанных, список уведомлений, всплывающие уведомления о новых событиях, переход к объекту и отметка прочитанными, обновление в реальном времени.

## ADDED Requirements

### Requirement: Соединение в реальном времени в приложении
Приложение SHALL держать соединение уведомлений в реальном времени, пока пользователь залогинен. Соединение MUST устанавливаться после входа и восстановления сессии и закрываться при выходе. Access-токен MUST не передаваться в интерфейс приложения. После истечения токена или разрыва сети приложение MUST переподключаться автоматически, со свежим токеном.

#### Scenario: Вход
- **WHEN** пользователь входит в приложение
- **THEN** приложение устанавливает соединение уведомлений, и новые уведомления начинают приходить без перезагрузки

#### Scenario: Выход
- **WHEN** пользователь выходит
- **THEN** соединение закрывается, а список и счётчик уведомлений очищаются

#### Scenario: Истёк токен соединения
- **WHEN** сервер закрыл соединение из-за истечения access-токена
- **THEN** приложение переподключается с обновлённым токеном, пользователь ничего не делает

### Requirement: Индикатор непрочитанных
Приложение SHALL показывать в навигационном рейле кнопку уведомлений с числом непрочитанных. При нуле число MUST не показываться. Больше 99 MUST отображаться как `99+`. Число MUST обновляться в реальном времени при создании и прочтении уведомлений в любом интерфейсе пользователя.

#### Scenario: Новое уведомление
- **WHEN** приходит новое уведомление
- **THEN** число на кнопке увеличивается на 1 без перезагрузки

#### Scenario: Прочитано в расширении
- **WHEN** пользователь прочитал уведомление в manager-helper
- **THEN** число в control-center уменьшается без перезагрузки

#### Scenario: Много непрочитанных
- **WHEN** у пользователя 150 непрочитанных уведомлений
- **THEN** на кнопке отображается `99+`

### Requirement: Список уведомлений
Приложение SHALL по нажатию кнопки уведомлений открывать список уведомлений пользователя, новые первыми, с подгрузкой следующих страниц. Непрочитанные MUST визуально отличаться от прочитанных. Для каждого уведомления MUST показываться заголовок, текст и относительное время создания. Приложение MUST показывать состояния загрузки, пустого списка и ошибки с возможностью повторить.

#### Scenario: Открытие списка
- **WHEN** пользователь нажимает кнопку уведомлений
- **THEN** открывается список с его уведомлениями, непрочитанные выделены

#### Scenario: Нет уведомлений
- **WHEN** у пользователя нет уведомлений
- **THEN** список показывает пустое состояние

#### Scenario: Ошибка загрузки
- **WHEN** запрос списка завершился ошибкой
- **THEN** список показывает сообщение об ошибке и кнопку «Повторить»

#### Scenario: Новое уведомление при открытом списке
- **WHEN** список открыт, и приходит новое уведомление
- **THEN** оно появляется первым в списке без перезагрузки

### Requirement: Переход к объекту и отметка прочитанным
Приложение SHALL по клику на уведомление о задаче отмечать уведомление прочитанным, переключаться в раздел «Задачи» и открывать карточку этой задачи. Если задача удалена или недоступна, приложение MUST показывать понятное сообщение, а уведомление MUST оставаться прочитанным. Приложение MUST давать отметить прочитанными все уведомления одним действием.

#### Scenario: Клик по уведомлению о задаче
- **WHEN** пользователь кликает по уведомлению `task.assigned`
- **THEN** уведомление становится прочитанным, открывается раздел «Задачи» с карточкой этой задачи

#### Scenario: Задача удалена
- **WHEN** пользователь кликает по уведомлению об удалённой задаче
- **THEN** уведомление становится прочитанным, а приложение сообщает, что задача не найдена

#### Scenario: Прочитать все
- **WHEN** пользователь выбирает «Прочитать все»
- **THEN** все уведомления в списке становятся прочитанными, а число непрочитанных скрывается

### Requirement: Всплывающее уведомление
Приложение SHALL при получении нового уведомления показывать в окне приложения всплывающее уведомление с заголовком и текстом, которое само скрывается через несколько секунд. Клик по нему MUST вести к объекту так же, как клик в списке. Одно уведомление MUST не показываться всплывающим повторно, даже если сервер прислал его ещё раз.

#### Scenario: Пришло новое уведомление
- **WHEN** приходит новое уведомление, пока приложение открыто
- **THEN** появляется всплывающее уведомление с его заголовком и текстом и через несколько секунд скрывается

#### Scenario: Повторная доставка
- **WHEN** сервер повторно присылает уже показанное уведомление
- **THEN** второе всплывающее уведомление не появляется, а в списке оно остаётся одно

### Requirement: Синхронизация после переподключения
Приложение SHALL после каждого восстановления соединения перезапрашивать список и число непрочитанных, чтобы показать уведомления, созданные во время разрыва.

#### Scenario: Сеть пропадала
- **WHEN** сеть пропала, за это время пришло уведомление, а затем сеть восстановилась
- **THEN** после переподключения уведомление есть в списке, а счётчик актуален
