# UI Design: add-realtime-notifications

## Источник дизайна
- **.pen файл**: `design/synergy-design-kit.pen`. Это единственный файл дизайна в проекте. Шаблон схемы ссылается на `design/sallary-first-iteration.pen` и UI Kit `uDEum`, но в этом репозитории их нет (то же отклонение было в прошлых change, например в `add-electron-auth`).
- **UI Kit**: `Дизайн-система` (`OBWB5`) → `01 · Synergy UI Kit` (`k9JASi`). Новые мастер-компоненты лежат в `05 · Молекулы` (`W1oMzb`) → `Row G` (`G9XK2`) → `Panel Уведомления (компоненты)` (`vNTmH`), рядом с панелью `Panel Задачи (компоненты)`.
- **Корневые разделы** (новые разделы встроены в существующие фреймы сущностей файла, а не лежат отдельными корневыми фреймами в `document`, как и прошлые change):
  - Control Center (`tD0BP`) → `04 · Уведомления` (`s43f7`), под `03 · Задачи`;
  - Manager Helper (`DILPP`) → `09 · Уведомления` (`RCYNX`), под `08 · Создание задачи · редизайн`, с разделителем `O82dg`.
- **Токены**: `$brand-red`, `$brand-red-soft`, `$ink`, `$ink-80`, `$ink-60`, `$ink-40`, `$surface`, `$surface-alt`, `$surface-sunken`, `$border`, `$info`, `$info-soft`, `$r-sm`, `$r-md`, `$r-lg`, `$r-pill`, `$font-display` (Onest), `$font-ui` (Raleway). Хардкод есть только в мокапах системных уведомлений Chrome/ОС: это не наш UI, поэтому там шрифт Inter и системные цвета.

## Отклонения от architecture.md
1. **Расположение кнопки в рейле cc.** В `architecture.md` сказано только «монтируется в `layouts/NavRail`». В дизайне кнопка стоит в нижней группе рейла, над кнопкой темы и аватаром: это глобальное действие, а не раздел. Подписи под иконкой нет («Уведомления» не помещается в 48 px), вместо неё тултип при наведении и `aria-label`.
2. **Состояние «после „Прочитать все“».** Отдельное состояние поповера (`CMuzQ`): счётчик «N новых» скрыт, кнопка неактивна. В архитектуре этого состояния нет. Логики оно не меняет, но `NotificationsPopover` должен блокировать кнопку при `unreadCount = 0`.
3. **Счётчик в шапке списка.** В шапке поповера и оверлея стоит бейдж «N новых» (`Badge / Master`) из `unreadCountQuery` / `unreadCount`. Компоненту списка нужен доступ к числу непрочитанных. В cc это уже есть через query. В mh `NotificationsOverlay` нужен проп `unreadCount` (сейчас в props его нет).
4. **Тосты cc: стопка и пауза.** Видно не больше 3 тостов, новое снизу, старшие уходят вверх. При наведении таймер 6 с на паузе. В архитектуре есть только «автоскрытие через 6 с», поэтому `notifications.store` должен ограничивать очередь и поддерживать паузу.
5. **Кнопка закрытия и ссылка «Открыть задачу» в тосте.** В архитектуре клик ведёт к объекту. В дизайне вся карточка кликабельна, «Открыть задачу» служит визуальной подсказкой, крестик закрывает тост (`onDismiss`, как у mh `NotificationToast`). У cc `NotificationToast` тоже нужен `onDismiss`.
6. **«Задача не найдена» в manager-helper** (`LA1Op`). Спека `notifications-extension-ui` требует сообщения о недоступной задаче только для desktop. Детали задачи в панели всё равно получат 404, поэтому состояние нарисовано по аналогии с cc. Предлагается добавить сценарий в `notifications-extension-ui` (или в `tasks-extension-ui`) на этапе tasks.
7. **Широкая панель mh (≥ 640 px).** На узкой панели `NotificationsOverlay` закрывает секцию целиком под шапкой. На широкой это выпадающий список 400 px под кнопкой (`I6dze`). Значит, у `NotificationsOverlay` два варианта раскладки по ширине: тот же брейкпоинт, что у сплита в `TasksSplitView`.
8. **Формат времени.** В cc полный формат («2 мин назад», «вчера», «12 окт»), в узкой панели mh короткий («2 мин», «1 ч»), потому что строка 380 px. Форматтер относительного времени должен поддерживать короткий режим.
9. **Унаследованные расхождения макетов mh.** Узкие экраны `07 · Задачи` (`SElzj`, `Kqh0G`) нарисованы до общей шапки. В новых экранах сверху добавлена шапка `PanelHeader`. Контекстная строка деталей взята из существующего макета (56 px), хотя `design/panel-header-sync-prompt.md` задаёт для неё 48 px. Ориентироваться нужно на код `PanelHeader` / контекстной строки.
10. **Системные уведомления Chrome и бейдж** (`iautc`) — только референс, они явно подписаны «рендерит браузер». Их внешний вид задают Chrome и ОС. Из нашего кода в них попадают только иконка, заголовок, текст и число на бейдже.
11. **Не нарисовано:** ошибка подгрузки следующей страницы (предлагается внизу списка строка с «Повторить» по образцу `Load More`) и баннер «нет соединения» для потока в реальном времени: спеки требуют только тихого переподключения, отдельного UI для разрыва нет.

Проверка layout: каждый раздел проверен по экспорту в PNG (полный масштаб и 0.5–0.8). Обрезанного текста, наложений и пустых контейнеров нет. `Get`-проверка `ctx.problems` даёт ложные срабатывания «clipped» на слотах и на `Me` в рейле. На нетронутых макетах файла они такие же, и на рендере их нет (как и в `add-electron-auth`).
