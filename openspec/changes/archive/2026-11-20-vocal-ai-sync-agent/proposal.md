## Why

Для оценки звонков менеджеров/руководителей компания использует внешний сервис VocalAI (app.vocal-ai.ru), у которого нет публичного API — только внутренний REST, используемый фронтендом (см. `vocal-ai-api-research.md`). Чтобы дать LLM-агенту возможность отвечать на вопросы по звонкам (транскрипты, оценки по чек-листу, теги, саммари) без прямого похода во внешний сервис на каждый запрос, нужно регулярно выгружать звонки в локальную БД и дать агенту инструменты для чтения/фильтрации этих данных.

## What Changes

- Новый бэкенд-клиент VocalAI API: двухшаговая авторизация через SSO Синергии (`POST /api/auth/proxy/synergy_login` → `POST /api/auth/provider/synergy`), хранение и авто-обновление короткоживущего access-токена (TTL ~30 мин) через повторный логин.
- Фоновая периодическая синхронизация (раз в 5–10 минут) звонков по всем сконфигурированным проектам VocalAI: `POST /api/calls/project/{id}` с окном `startDate..endDate`, upsert в локальные таблицы (без полного текста транскрипции — она весит много и не нужна при каждой выгрузке).
- Разовая стартовая полная выгрузка истории звонков по проекту (та же выгрузка, но с окном "с начала истории" вместо "с последней синхронизации"), запускаемая один раз при подключении проекта.
- Окно перехлёста при инкрементальной синхронизации (например, -2 дня от `last_synced_at`), чтобы подтянуть звонки с обновлённой оценкой/тегами после первой выгрузки (апелляции, пересчёт).
- Ленивая загрузка полной транскрипции конкретного звонка по запросу (через `GET /api/call/{id}`) с кэшированием в БД навсегда (транскрипт неизменен после оценки).
- Набор инструментов (tools) для LLM-агента, работающих только с локальной БД: список/фильтрация звонков, саммари звонка, метрики и теги звонка, получение транскрипта (с ленивой подгрузкой при первом обращении), агрегированная статистика по менеджерам/метрикам за период.
- **BREAKING**: нет (новая функциональность, не затрагивает существующие модули).

Размер укладывается в один change (оценочно ≤40 задач): клиент API + воркер синхронизации + схема БД — это одна логическая единица, инструменты агента — вторая, обе малы по объёму и тесно связаны (тулы читают то, что пишет синк).

## Capabilities

### New Capabilities
- `vocal-ai-call-sync`: клиент VocalAI API (авторизация через SSO Синергии, авто-обновление токена), периодическая инкрементальная синхронизация звонков проектов в локальные таблицы (звонки, метрики по чек-листу, теги, саммари), стартовая полная выгрузка, ленивая догрузка и кэширование полной транскрипции по `callId`.
- `vocal-ai-agent-tools`: набор инструментов LLM-агента для чтения и фильтрации синхронизированных данных о звонках (по дате, менеджеру, проекту, оценке, тегу, метрике), получения деталей/транскрипта звонка и агрегированной статистики, без прямых обращений к внешнему VocalAI API.

## Impact

- **Новый код**: `backend/src/modules/vocal-ai-call-sync/` (клиент внешнего API, BullMQ/cron-джоба синхронизации, Slonik-репозитории, use case стартовой выгрузки) и `backend/src/modules/vocal-ai-agent-tools/` (use cases + определения тулов для агента).
- **БД**: новые таблицы и миграции (`db/migrations/NNN_vocal_ai_*.sql`) — проекты VocalAI, звонки, метрики звонка, теги звонка, саммари звонка, транскрипция звонка (заполняется лениво), состояние синхронизации по проекту.
- **Конфигурация**: новые переменные окружения в `src/shared/config/env.schema.ts` — учётные данные для логина в VocalAI (секрет), список отслеживаемых `projectId`/`spaceId`, интервал синхронизации.
- **Внешние зависимости**: исходящие HTTP-запросы к `app.vocal-ai.ru` и `id.synergy.ru` (SSO).
- **Существующие модули**: не затрагиваются (новые модули, нет изменений в существующих контрактах).
