## Purpose

Раздел «Задачи» в Electron-приложении control-center: просмотр, фильтрация, создание и изменение задач с участниками и вложениями поверх REST API бэкенда.

## ADDED Requirements

### Requirement: Навигация между чатами и задачами
Приложение SHALL показывать узкий левый рейл с разделами «Чаты» и «Задачи». Активный раздел MUST быть виден в рейле. Переключение MUST сохранять состояние неактивного раздела (выбранный чат, фильтры задач, открытая задача) в рамках запуска приложения. Раздел MUST быть недоступен, пока нет действующей сессии.

#### Scenario: Переключение в задачи и обратно
- **WHEN** пользователь выбирает чат, переходит в «Задачи» и возвращается в «Чаты»
- **THEN** тот же чат остаётся выбранным, а при следующем входе в «Задачи» сохраняются фильтры и открытая задача

#### Scenario: Нет сессии
- **WHEN** пользователь не авторизован
- **THEN** рейл и раздел задач не показываются, пользователь видит экран входа

### Requirement: Список задач
Раздел SHALL показывать задачи списком: название, статус, ответственный, дедлайн, число вложений. Просроченные задачи (дедлайн в прошлом, статус не «Готово») MUST быть визуально выделены и подписаны текстом, а не только цветом. Список MUST быть постраничным; по умолчанию сортировка по времени создания, новые первыми; пользователь MUST иметь возможность сортировать по дедлайну, времени создания и изменения.

#### Scenario: Загрузка списка
- **WHEN** пользователь открывает раздел
- **THEN** до ответа сервера показываются скелетоны строк, затем задачи первой страницы

#### Scenario: Просроченная задача
- **WHEN** у задачи дедлайн в прошлом и статус «К выполнению» или «В работе»
- **THEN** строка помечена как просроченная текстовой меткой и акцентным цветом

#### Scenario: Пустой список
- **WHEN** под фильтры не подходит ни одна задача
- **THEN** показывается пустое состояние с текстом и действием «Сбросить фильтры» (или «Создать задачу», если фильтров нет)

#### Scenario: Ошибка загрузки
- **WHEN** запрос списка завершился ошибкой сети или сервера
- **THEN** показывается сообщение об ошибке с кнопкой «Повторить», ранее загруженные данные не пропадают

### Requirement: Фильтры и поиск
Раздел SHALL предоставлять быстрые представления «Все», «Мои» (я ответственный), «Я наблюдаю», «Созданные мной», «Просроченные», фильтр по статусу и поиск по подстроке названия. Фильтры MUST комбинироваться по «И», смена фильтра MUST возвращать на первую страницу, ввод в поиск MUST отправляться на сервер с задержкой.

#### Scenario: Представление «Мои»
- **WHEN** пользователь выбирает «Мои»
- **THEN** список содержит только задачи, где ответственный — текущий пользователь

#### Scenario: Комбинация фильтров
- **WHEN** выбраны «Мои» и статус «В работе» и введена подстрока
- **THEN** запрос содержит все три условия и список им соответствует

#### Scenario: Быстрый ввод в поиск
- **WHEN** пользователь печатает в поиске
- **THEN** запрос уходит после паузы в наборе, а не на каждый символ

### Requirement: Создание задачи
Пользователь SHALL создавать задачу из диалога: название (обязательно), описание, дедлайн, ответственный, наблюдатели. Кнопка отправки MUST блокироваться, пока название пустое или идёт запрос. Ошибки валидации сервера MUST отображаться у соответствующих полей; ошибка `TASK_USER_NOT_FOUND` MUST показываться у поля участников. После успеха диалог закрывается, список обновляется, новая задача открывается в панели деталей.

#### Scenario: Успешное создание
- **WHEN** пользователь вводит название и подтверждает
- **THEN** задача создаётся со статусом «К выполнению», появляется в списке и открывается в панели деталей

#### Scenario: Пустое название
- **WHEN** название пустое или состоит из пробелов
- **THEN** отправка недоступна, запрос не выполняется

#### Scenario: Участник стал неактивным
- **WHEN** сервер отвечает 422 `TASK_USER_NOT_FOUND`
- **THEN** диалог остаётся открытым, введённые данные сохранены, у поля участников показана ошибка

### Requirement: Панель деталей задачи
Выбор задачи SHALL открывать справа панель (drawer) поверх списка с полными данными: название, описание, статус, дедлайн, создатель, ответственный, наблюдатели, времена создания, изменения и закрытия, вложения. Панель MUST закрываться кнопкой и клавишей Escape; список под ней остаётся доступным. Открытая задача MUST быть выделена в списке.

#### Scenario: Открытие и закрытие
- **WHEN** пользователь выбирает задачу, затем нажимает Escape
- **THEN** панель открывается с данными задачи и закрывается, выделение в списке снимается

#### Scenario: Задача удалена другим пользователем
- **WHEN** сервер отвечает 404 при загрузке или сохранении открытой задачи
- **THEN** панель сообщает, что задача удалена, закрывается, задача пропадает из списка

### Requirement: Изменение задачи
Пользователь SHALL менять статус одним действием из списка и из панели деталей, а также изменять название, описание, дедлайн (включая снятие), ответственного (включая снятие) и наблюдателей из панели. Изменения MUST отправляться частичным обновлением только изменённых полей. Смена статуса MUST отражаться в интерфейсе сразу и откатываться с сообщением, если сервер отказал. Время закрытия MUST показываться только у задач в статусе «Готово».

#### Scenario: Закрытие из списка
- **WHEN** пользователь меняет статус задачи на «Готово» в строке списка
- **THEN** статус меняется сразу, после ответа показывается время закрытия

#### Scenario: Отказ сервера при смене статуса
- **WHEN** запрос смены статуса завершился ошибкой
- **THEN** статус возвращается к прежнему и показывается сообщение об ошибке

#### Scenario: Снятие ответственного и дедлайна
- **WHEN** пользователь очищает поля ответственного и дедлайна и сохраняет
- **THEN** в запросе передаются `null` для этих полей, задача отображается без них

### Requirement: Выбор пользователей
Выбор ответственного и наблюдателей SHALL выполняться поиском по логину среди активных пользователей (`GET /users`) с задержкой ввода. Ответственный — один, наблюдатели — несколько без повторов и не более 50. Текущего пользователя MUST быть легко выбрать одним действием («Я»).

#### Scenario: Поиск пользователя
- **WHEN** пользователь вводит часть логина
- **THEN** показываются подходящие активные пользователи, выбор добавляет его в поле

#### Scenario: Лимит наблюдателей
- **WHEN** выбрано 50 наблюдателей
- **THEN** добавление следующего недоступно, показано пояснение

### Requirement: Вложения
В панели деталей пользователь SHALL загружать файлы (выбор в диалоге или перетаскивание), видеть список вложений (имя, размер) и скачивать или удалять их. Клиент MUST заранее проверять лимиты размера и числа файлов, известные из конфигурации, и показывать понятную ошибку при ответах 413 и 422 сервера. Загрузка MUST показывать ход выполнения и допускать отмену. Удаление MUST требовать подтверждения. Скачивание MUST сохранять файл под исходным именем.

#### Scenario: Загрузка файла
- **WHEN** пользователь перетаскивает файл в панель деталей
- **THEN** показывается прогресс, по завершении файл появляется в списке вложений

#### Scenario: Файл слишком большой
- **WHEN** сервер отвечает 413
- **THEN** пользователь видит сообщение о превышении размера, вложение не добавляется

#### Scenario: Достигнут лимит числа файлов
- **WHEN** сервер отвечает 422 с кодом лимита вложений
- **THEN** пользователь видит сообщение о лимите, вложение не добавляется

#### Scenario: Скачивание
- **WHEN** пользователь нажимает «Скачать»
- **THEN** файл сохраняется на диск под исходным именем

#### Scenario: Удаление вложения
- **WHEN** пользователь подтверждает удаление
- **THEN** вложение исчезает из списка; при 404 оно тоже убирается из списка

### Requirement: Удаление задачи
Пользователь SHALL удалять задачу из панели деталей после явного подтверждения. После удаления панель закрывается, задача пропадает из списка.

#### Scenario: Подтверждённое удаление
- **WHEN** пользователь подтверждает удаление
- **THEN** задача исчезает из списка, панель закрыта

#### Scenario: Отмена удаления
- **WHEN** пользователь закрывает подтверждение без согласия
- **THEN** задача остаётся без изменений

### Requirement: Потеря сессии и недоступность сервера
Раздел задач SHALL вести себя при ошибках так же, как раздел чатов: при потере сессии пользователь возвращается на экран входа, при недоступном сервере видит ошибку подключения с повтором. Несохранённые данные диалога создания MUST не теряться при временной сетевой ошибке.

#### Scenario: Истёк refresh-токен
- **WHEN** во время работы с задачами сессия потеряна
- **THEN** показывается экран входа; после повторного входа раздел открывается в прежнем состоянии

#### Scenario: Сервер недоступен
- **WHEN** запрос списка не доходит до сервера
- **THEN** показывается ошибка подключения с кнопкой повтора

### Requirement: Доступность и клавиатура
Все действия раздела SHALL быть доступны с клавиатуры: фокус виден, диалоги и панель удерживают фокус и возвращают его на вызвавший элемент при закрытии; статус и просрочка MUST передаваться текстом; интерактивные элементы MUST иметь доступные имена; поддерживается тёмная тема.

#### Scenario: Фокус после закрытия панели
- **WHEN** пользователь закрывает панель деталей клавишей Escape
- **THEN** фокус возвращается на строку задачи, из которой панель была открыта
