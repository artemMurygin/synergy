## ADDED Requirements

### Requirement: Список активных пользователей
Система SHALL возвращать страницу активных пользователей по `GET /users` для выбора ответственного и наблюдателей задач. Каждый элемент MUST содержать только идентификатор и логин. Система MUST поддерживать поиск по подстроке логина без учёта регистра и пагинацию (`limit`, `page`, как в остальных списках API) с общим числом записей. Отключённые пользователи MUST не попадать в список. Список MUST быть отсортирован по логину. Эндпоинт MUST быть защищён access-токеном, как и остальные; хэши паролей и служебные поля MUST не возвращаться.

#### Scenario: Список без параметров
- **WHEN** аутентифицированный клиент вызывает `GET /users`
- **THEN** система отвечает 200 и возвращает первую страницу активных пользователей (`id`, `login`) по возрастанию логина и общее число

#### Scenario: Поиск по логину
- **WHEN** клиент вызывает `GET /users?search=an`
- **THEN** система возвращает только активных пользователей, в логине которых есть «an», независимо от регистра

#### Scenario: Отключённый пользователь
- **WHEN** пользователь отключён
- **THEN** он не входит в `GET /users`, даже если подходит под поиск

#### Scenario: Недопустимые параметры
- **WHEN** клиент передаёт `limit` больше максимального или слишком длинный `search`
- **THEN** система отвечает 400

#### Scenario: Запрос без токена
- **WHEN** клиент вызывает `GET /users` без access-токена
- **THEN** система отвечает 401
