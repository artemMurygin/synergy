## Why

Схема БД каталога программ (`add-programs-db-schema`) готова, но пуста: данные живут в семи Google-таблицах в виде, непригодном для точных выборок (цена, срок и форма в одной ячейке, колонки «форма × база», факультет и адрес в строках-заголовках, логины и платёжные ссылки рядом с данными). Агенту подбора (`add-programs-selection-agent`) нужны наполненные и актуальные каталог и индекс содержимого, поэтому ETL нужен до него.

## What Changes

- **Чтение Google-таблиц** через Sheets API с сервисным аккаунтом. Список таблиц берётся из `raw-data-liks-list.json` (7 таблиц). Читаются метаданные листов (скрыт ли лист, идентификатор, название), значения и объединённые ячейки.
- **Отбор листов:** скрытые листы и листы с «копия» в названии не загружаются; ручное отключение через `source_sheet.is_enabled`.
- **Фильтр секретов до записи:** колонки и ячейки с логинами, паролями, токенами и платёжными ссылками исключаются (в том числе когда секрет лежит в ячейке с безобидным заголовком), их значения не попадают ни в `raw_row`, ни в каталог.
- **Staging:** сырые строки листа пишутся в `raw_row` с хэшем строки; лист с неизменившимся хэшем содержимого пропускается.
- **Разбор листов гибридом:** LLM один раз на лист строит «карту» (роль колонок, форма × база × дата за колонкой, строки-заголовки факультета и площадки, заметки о сроках); карта кэшируется по хэшу шапки. Дальше код детерминированно разворачивает строки в предложения, цены по видам, сроки, коды направлений. Цены и сроки разбирает код, значения LLM проверяются по допустимым наборам и по исходному тексту ячейки.
- **Справочники прозой** (скидки, способы оплаты, группы продуктов, региональные ставки) извлекает LLM по схеме с проверками; флаг `internal_only` для внутренних регламентов.
- **Идемпотентная загрузка:** upsert по естественному ключу; записи, которых нет в последней выгрузке листа, удаляются в той же транзакции. Один лист синхронизируется одной транзакцией: при сбое остаются прежние данные.
- **Защита от пустой выгрузки:** если лист вернул меньше 50% от прошлого числа строк, удаление не выполняется, фиксируются ошибка в логе и метрика.
- **Индекс содержимого:** текст программ нарезается на фрагменты по типам разделов, считаются эмбеддинги, пересчёт только для изменившихся фрагментов.
- **Регулярный запуск:** повторяющийся job BullMQ с фиксированным интервалом создаёт по одной задаче синхронизации на каждый включённый лист; интервал задаётся в env.

## Capabilities

### New Capabilities
- `sheets-ingestion`: чтение листов из Google-таблиц, отбор листов (скрытые, копии, `is_enabled`), исключение секретных колонок, запись сырых строк и хэшей, пропуск неизменившихся листов.
- `sheet-structure-mapping`: построение и проверка карты листа (LLM), кэширование по хэшу шапки, версионирование, ручная правка карты, статус «не поддержан».
- `programs-sync`: преобразование сырых строк в каталог и справочники, идемпотентный upsert по естественному ключу, удаление отсутствующих записей, транзакция на лист, защита от пустой выгрузки, трассировка источника.
- `content-embedding`: нарезка текста на фрагменты по типам разделов, карточка-профиль программы, расчёт эмбеддингов только для изменившихся фрагментов, устойчивость к сбоям провайдера.
- `sync-scheduling`: регулярный job с интервалом, постановка задач синхронизации по листам в очередь, повторные попытки, наблюдаемость (логи и метрики по каждому листу).

## Impact

- **Код:** новый модуль `backend/src/modules/programs-etl/` по слоям domain / application / infrastructure / interface (парсеры, use-cases, адаптер Sheets API, репозитории Postgres, адаптер эмбеддингов, процессор очереди).
- **Зависимости:** добавляется `googleapis` (или `@googleapis/sheets`); эмбеддинги через уже установленный `@langchain/openai`; очередь через уже установленный `@nestjs/bullmq`.
- **Конфигурация (`env.schema.ts`):** учётные данные сервисного аккаунта Google, интервал регулярного job, имя модели эмбеддингов; `OPENAI_API_KEY` становится обязательным для построения карт листов и расчёта эмбеддингов.
- **Доступ:** все 7 таблиц должны быть расшарены на email сервисного аккаунта (доступ на чтение).
- **БД:** таблицы каталога из `add-programs-db-schema` не меняются; добавляется миграция с таблицей карт листов (хэш шапки, карта JSONB, модель, версия промпта, признак ручной правки). `INSERT ... ON CONFLICT` должен учитывать предикаты частичных уникальных индексов программы.
- **Внешние расходы:** вызовы OpenAI для карт листов (только при изменении шапки) и эмбеддингов (только изменившиеся фрагменты). БД: для кэша карт нужна небольшая таблица, это добавляется миграцией в этом change.
- **Зависимости между change:** `add-programs-selection-agent` читает данные, которые наполняет этот change.
- **Вне объёма:** UI и HTTP-эндпоинты ручного запуска, история цен, инструменты и промпты агента подбора, интерфейс просмотра и правки карт листов (карты правятся напрямую в БД).
