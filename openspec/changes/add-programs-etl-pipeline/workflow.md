# Workflow: add-programs-etl-pipeline

## Правило выполнения

Работа идёт в текущей ветке `feat/price-policy-rag` по прямому указанию пользователя, без отдельного worktree. Блоки `tasks.md` выполняются строго по порядку: следующий начинается только после проверок текущего и отдельного коммита. Каждый блок получает сабагент с явной ответственностью за файлы этого блока. Координатор проверяет результат, обновляет статус OpenSpec и передаёт следующему агенту только после завершения предыдущего блока. Уже существующие чужие изменения в рабочем дереве не изменяются и не включаются в коммиты ETL.

В каждом TDD-наборе соблюдается порядок: тест → ожидаемое падение → реализация → зелёный тест и соседняя регрессия. Галочка в `tasks.md` ставится сразу после подтверждения соответствующего пункта. Неуспешная проверка или новое противоречие в спецификации останавливает переход к следующему блоку до исправления.

## Последовательность

| Фаза | Блок `tasks.md` | Результат | Проверка перед коммитом |
|---|---|---|---|
| 1 | 1. Подготовка модуля и схемы | Модуль, зависимости, конфигурация, `sheet_mapping` | typecheck, конфиг, повторный прогон мигратора |
| 2 | 2. Доменные типы и защитные правила | VO, фильтр секретов, защита от пустой выгрузки | red/green тесты домена |
| 3 | 3. Разбор строк и фрагментов | Парсер и построитель чанков на фикстурах | red/green тесты реальных форматов |
| 4 | 4. Чтение Google Sheets | Адаптер чтения метаданных и значений | red/green тесты с подставным клиентом |
| 5 | 5. Карта листа и её кэш | LLM-карта, репозиторий карты, извлекатель справочников | red/green тесты и интеграция с тестовой БД |
| 6 | 6. Postgres: реестр и транзакционная запись | Реестр, атомарный upsert/удаление, векторы | red/green интеграционные тесты, rollback |
| 7 | 7. Use-cases синхронизации | `PlanSync`, `SyncSheet` | red/green сценарии и соседняя регрессия |
| 8 | 8. Эмбеддинги | Адаптер и `EmbedPendingChunks` | red/green, проверка хэша и размерности |
| 9 | 9. Очередь и наблюдаемость | Scheduler, processor, метрики и логи | red/green, тесты очередей и метрик |
| 10 | 10. Сквозная проверка и API Contract | Полный цикл, отказоустойчивость, контракт задач | typecheck, lint, tests, OpenSpec strict |
| 11 | 11. Code review | Два прохода ревью с исправлениями | отсутствие блокирующих замечаний, полный тестовый прогон |

Коммит каждой фазы включает только её код, тесты и обновлённые галочки `tasks.md`. Первый коммит также включает плановые артефакты change. У блока 11 может быть несколько коммитов: исправление и повторное ревью.

## Передача между агентами

Для каждой фазы агент получает номер блока, файл `tasks.md`, связанные спецификации и владение конкретными модулями. Он сообщает: выполненные пункты, red/green команды и результаты, затронутые файлы, хэш коммита и оставшиеся риски. Координатор не начинает следующую фазу, пока эти данные не проверены.
