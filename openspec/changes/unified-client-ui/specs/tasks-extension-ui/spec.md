## ADDED Requirements

### Requirement: Загрузка и удаление вложений задачи
В деталях задачи пользователь боковой панели SHALL иметь возможность загрузить вложение и удалить своё вложение так же, как в `control-center`: с проверкой лимитов, прогрессом загрузки, понятными ошибками для слишком большого файла и неподдерживаемого типа, удаление — с подтверждением.

#### Scenario: Загрузка вложения
- **WHEN** пользователь в деталях задачи выбирает файл допустимого размера
- **THEN** виден прогресс, после загрузки файл появляется в списке вложений задачи

#### Scenario: Слишком большой файл
- **WHEN** пользователь выбирает файл больше лимита
- **THEN** файл не загружается, показано сообщение о превышении размера

## MODIFIED Requirements

### Requirement: Переключение между чатом и задачами
Side panel SHALL позволять переключаться между «Чаты» и «Задачи» навигацией, общей с `control-center`: рейлом в планшетном режиме и нижним таб-баром в мобильном. Переключение MUST не прерывать идущий ответ ассистента и не терять состояние чата. Последний выбранный раздел MUST запоминаться между открытиями панели. Раздел задач MUST быть доступен только после входа.

#### Scenario: Переключение во время ответа
- **WHEN** ассистент отвечает, а пользователь переходит в «Задачи» и возвращается
- **THEN** ответ продолжает приходить, чат показывает актуальное состояние

#### Scenario: Запоминание раздела
- **WHEN** пользователь закрывает панель на разделе «Задачи» и открывает её снова
- **THEN** открывается «Задачи»

### Requirement: Мои задачи
Экран SHALL по умолчанию показывать представление «Мои»: задачи, где текущий пользователь ответственный, отсортированные по дедлайну (ближайшие первыми, без дедлайна — в конце). Строка содержит название, статус, дедлайн и метку просрочки текстом. Представления MUST показываться сегментированным переключателем:
- в планшетном режиме видны «Все», «Мои» и «Ещё»;
- в мобильном режиме видны «Все», «Мои», «Просрочено» со счётчиком и «Ещё»;
- в меню «Ещё» MUST быть остальные представления: «Я наблюдаю», «Созданные мной» и, в планшетном режиме, «Просрочено».

Фильтр по статусу и сортировка MUST быть доступны на второй строке под представлениями. Пользователь MUST иметь возможность искать по названию. Список постраничный с подгрузкой по запросу пользователя.

#### Scenario: Открытие экрана
- **WHEN** пользователь открывает «Задачи»
- **THEN** выбрано представление «Мои», ближайший дедлайн первым

#### Scenario: Представление из меню «Ещё»
- **WHEN** пользователь в планшетном режиме открывает «Ещё» и выбирает «Я наблюдаю»
- **THEN** список содержит задачи, где пользователь наблюдатель, а сегмент «Ещё» показан выбранным

#### Scenario: Просроченная задача
- **WHEN** дедлайн задачи в прошлом
- **THEN** строка подписана «Просрочено» и выделена акцентом

#### Scenario: Пустой экран
- **WHEN** у пользователя нет подходящих задач
- **THEN** показывается пустое состояние с действием «Создать задачу»

#### Scenario: Ошибка загрузки
- **WHEN** запрос завершился ошибкой
- **THEN** показывается сообщение и кнопка «Повторить»

### Requirement: Детали задачи
Пользователь SHALL открывать экран деталей: описание, статус, дедлайн, создатель, ответственный, наблюдатели, вложения. Экран MUST позволять изменить название, описание, статус и дедлайн, сменить ответственного и наблюдателей, скачать, загрузить и удалить вложение. Возврат к списку MUST сохранять позицию прокрутки и фильтр.

#### Scenario: Открытие деталей
- **WHEN** пользователь выбирает задачу в списке в мобильном режиме
- **THEN** открывается экран деталей, кнопка «Назад» возвращает к списку в том же состоянии

#### Scenario: Скачивание вложения
- **WHEN** пользователь нажимает на вложение
- **THEN** файл скачивается под исходным именем

#### Scenario: Задача удалена
- **WHEN** сервер отвечает 404 на загрузку деталей
- **THEN** показывается сообщение, пользователь возвращается к списку, задача убрана
