## Purpose

Синхронизирует звонки из внешнего сервиса VocalAI (оценки, транскрипты, теги, саммари) в локальное хранилище с предсказуемой консистентностью, чтобы downstream-потребители (агентские инструменты) могли читать данные без обращений к внешнему API на каждый запрос.

## ADDED Requirements

### Requirement: Авторизация в VocalAI через SSO Синергии
Система SHALL получать рабочий access-токен VocalAI через двухшаговую авторизацию: обмен учётных данных Синергии на токен Keycloak, затем обмен токена Keycloak на токен VocalAI.

#### Scenario: Успешная авторизация
- **WHEN** сервис синхронизации запускается и не имеет действующего access-токена VocalAI
- **THEN** он выполняет вход через SSO Синергии и обмен на токен VocalAI, и сохраняет полученные access- и refresh-токены для последующих запросов

#### Scenario: Ошибка авторизации
- **WHEN** учётные данные Синергии недействительны или SSO возвращает ошибку
- **THEN** синхронизация этого цикла не выполняется, ошибка логируется с достаточным контекстом для диагностики, и попытка повторяется на следующем запланированном цикле

### Requirement: Автоматическое обновление access-токена
Система SHALL обновлять access-токен VocalAI через refresh-токен без повторного полного логина через SSO, когда токен истёк или близок к истечению.

#### Scenario: Токен истёк во время запроса к API
- **WHEN** запрос к VocalAI API возвращает статус 401
- **THEN** система обновляет access-токен через refresh-токен и повторяет исходный запрос один раз

#### Scenario: Refresh-токен недействителен
- **WHEN** обновление access-токена через refresh-токен также завершается ошибкой
- **THEN** система выполняет полный повторный логин через SSO; если и он не удаётся, цикл синхронизации завершается с ошибкой без повреждения уже сохранённых данных

### Requirement: Инкрементальная синхронизация по дате звонка
Система SHALL периодически (с настраиваемым интервалом, по умолчанию 5–10 минут) запрашивать у VocalAI звонки каждого сконфигурированного проекта, созданные в диапазоне дат с момента предыдущей успешной синхронизации этого проекта до текущего момента.

#### Scenario: Появился новый звонок
- **WHEN** в VocalAI создан новый звонок с датой звонка внутри окна синхронизации
- **THEN** этот звонок присутствует в результате запроса по дате звонка и будет записан в локальное хранилище

### Requirement: Инкрементальная синхронизация по дате оценки
Система SHALL дополнительно запрашивать у VocalAI звонки, оценённые (дата оценки) в диапазоне дат с момента предыдущей успешной синхронизации проекта до текущего момента, независимо от даты самого звонка.

#### Scenario: Старый звонок получил оценку только сейчас
- **WHEN** звонок был создан задолго до текущего окна синхронизации, но получил оценку (дату оценки) внутри текущего окна
- **THEN** этот звонок присутствует в результате запроса по дате оценки и его актуальные метрики/оценка будут записаны в локальное хранилище, даже если дата самого звонка вне окна синхронизации по дате звонка

### Requirement: Дедупликация и консистентная запись синхронизированных звонков
Система SHALL объединять результаты запроса по дате звонка и запроса по дате оценки в один набор уникальных звонков по идентификатору звонка перед записью, и производить запись как upsert (вставка или полное обновление существующей записи), не теряя и не дублируя звонки, попавшие в оба результата.

#### Scenario: Звонок попал в оба результата
- **WHEN** звонок одновременно соответствует окну синхронизации и по дате звонка, и по дате оценки
- **THEN** в локальном хранилище для него существует ровно одна запись с актуальными данными, без дублей

#### Scenario: Частичный сбой записи
- **WHEN** во время сохранения набора звонков происходит сбой (например, ошибка БД на одном из звонков)
- **THEN** уже успешно сохранённые в рамках этого цикла звонки остаются сохранёнными, а ошибка для несохранённых звонков логируется для повторной обработки на следующем цикле

### Requirement: Отслеживание состояния синхронизации по проекту
Система SHALL хранить для каждого сконфигурированного проекта VocalAI отметку времени последней успешной синхронизации и использовать её как начальную границу окна для следующего цикла.

#### Scenario: Первый запуск синхронизации для проекта
- **WHEN** для проекта ещё не выполнялась синхронизация
- **THEN** система выполняет стартовую полную выгрузку истории звонков проекта (без ограничения по дате начала) и после её завершения устанавливает отметку времени последней синхронизации

#### Scenario: Повторный запуск после успешного цикла
- **WHEN** предыдущий цикл синхронизации проекта завершился успешно
- **THEN** следующий цикл использует сохранённую отметку времени последней синхронизации как начало окна запроса

### Requirement: Ленивая загрузка и постоянное кэширование транскрипции звонка
Система SHALL не загружать полный текст транскрипции звонка во время обычной (инкрементальной или стартовой) синхронизации, а загружать и сохранять его по отдельному запросу при первом обращении к конкретному звонку, после чего повторные обращения к той же транскрипции SHALL использовать только локально сохранённую копию без обращения к внешнему API.

#### Scenario: Транскрипция запрошена первый раз
- **WHEN** запрошена транскрипция звонка, для которого она ещё не сохранена локально
- **THEN** система запрашивает полную карточку звонка у VocalAI API, сохраняет транскрипцию локально навсегда и возвращает её

#### Scenario: Транскрипция запрошена повторно
- **WHEN** запрошена транскрипция звонка, которая уже сохранена локально
- **THEN** система возвращает сохранённую транскрипцию без обращения к внешнему VocalAI API

### Requirement: Устойчивость к сбоям внешнего API
Система SHALL продолжать работу при временной недоступности или ошибках VocalAI API: ошибка одного цикла синхронизации или одного проекта SHALL NOT прерывать синхронизацию других проектов и SHALL NOT приводить к потере ранее сохранённых данных.

#### Scenario: VocalAI API временно недоступен
- **WHEN** запрос к VocalAI API завершается сетевой ошибкой или ошибкой 5xx
- **THEN** синхронизация текущего проекта в этом цикле прерывается с логированием ошибки, а синхронизация остальных проектов и следующий плановый цикл продолжаются как обычно
