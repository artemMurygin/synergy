## MODIFIED Requirements

### Requirement: Продукты и агенты из seed
Система SHALL содержать продукты и их агентов, заведённые сидером при развёртывании. Начальный набор продуктов: control-center, manager-helper, Telegram-бот, веб. Агент MAY входить в несколько продуктов и MUST входить хотя бы в один; навыки и статус агента общие для всех его продуктов. Агент с одним и тем же `slug`, указанный у нескольких продуктов, MUST быть одной записью, связанной с каждым из этих продуктов. Повторный запуск сидера MUST NOT создавать дубликаты, MUST NOT перезаписывать существующие записи и MUST NOT удалять связи агента с продуктами; недостающие связи из начального набора MUST добавляться. Если название продукта или агента из начального набора уже занято записью с другим `slug` (без учёта регистра), сидер MUST пропускать эту запись и её связи, сообщать об этом в выводе и завершаться без ошибки.

Кроме сидера, продукты и агенты MUST создаваться только при принятии заявки (см. `featurer-requests`, «Принятие с созданием агента»). Отдельное создание, редактирование и удаление продуктов, агентов и их связей через API MUST NOT предоставляться.

#### Scenario: Первый запуск сидера
- **WHEN** сидер запускается на пустой базе
- **THEN** создаются продукты начального набора, их агенты и связи агентов с продуктами

#### Scenario: Повторный запуск сидера
- **WHEN** сидер запускается, когда продукты и агенты уже существуют
- **THEN** количество продуктов и агентов не меняется

#### Scenario: Агент в двух продуктах
- **WHEN** в начальном наборе агент Ассистент указан у продуктов control-center и Telegram-бот
- **THEN** создаётся один агент Ассистент, связанный с обоими продуктами

#### Scenario: Новая связь для существующего агента
- **WHEN** агент уже есть в базе, а в начальный набор добавили его второй продукт, и сидер запускается повторно
- **THEN** у агента появляется связь со вторым продуктом, имя и признак архива агента не меняются

#### Scenario: Название из сидера уже занято
- **WHEN** при принятии заявки создан агент «Цены» со `slug` `ceny`, а в начальном наборе есть агент «Цены» со `slug` `prices`, которого ещё нет в базе
- **THEN** сидер пропускает агента `prices`, сообщает об этом и завершается без ошибки

#### Scenario: Агент создан при принятии заявки
- **WHEN** разработчик принимает заявку с созданием агента «Сверщик»
- **THEN** агент появляется в каталоге и в списке агентов наравне с агентами из сидера

#### Scenario: Ручное создание недоступно
- **WHEN** клиент пытается создать продукт или агента отдельным запросом, без принятия заявки
- **THEN** такого действия в API нет

## ADDED Requirements

### Requirement: Slug нового агента и продукта
Система SHALL генерировать `slug` агента и продукта, созданных при принятии заявки, из названия: кириллица транслитерируется в латиницу, буквы переводятся в нижний регистр, все символы, кроме латинских букв и цифр, заменяются дефисом, повторные дефисы схлопываются, а дефисы по краям удаляются. Длина `slug` MUST быть ограничена установленным пределом. Если `slug` уже занят записью того же вида (в том числе архивной), система MUST добавлять суффикс `-2`, `-3` и так далее до первого свободного. Если из названия не остаётся ни одного символа, система MUST использовать базу `agent` для агента и `product` для продукта. Сгенерированный `slug` MUST возвращаться в ответах наравне со `slug` из сидера и после создания MUST NOT меняться.

#### Scenario: Кириллическое название
- **WHEN** создаётся агент «Сверка актов»
- **THEN** его `slug` — `sverka-aktov`

#### Scenario: Занятый slug
- **WHEN** создаётся продукт «Веб 2.0», а `slug` `veb-2-0` уже занят
- **THEN** продукт получает `slug` `veb-2-0-2`

#### Scenario: Название без букв и цифр
- **WHEN** создаётся агент с названием «★★★»
- **THEN** его `slug` — `agent`, а если он занят, то `agent-2`

### Requirement: Уникальность названий агентов и продуктов
Система SHALL не допускать двух агентов с одинаковым названием и двух продуктов с одинаковым названием. Названия сравниваются без учёта регистра и пробелов по краям, архивные записи тоже учитываются. Создание агента или продукта с занятым названием при принятии заявки MUST отвечаться 409 с указанием, что занято (агент или продукт). Ничего не создаётся, заявка остаётся в `under_review`. Если два разработчика одновременно создают записи с одинаковым названием, успешно MUST завершаться ровно одно принятие.

#### Scenario: Занятое название агента
- **WHEN** при принятии создаётся агент «ЗАДАЧИ», а агент «Задачи» уже есть
- **THEN** система отвечает 409 «агент с таким названием уже есть»

#### Scenario: Название архивного агента
- **WHEN** агент «Цены» в архиве, и при принятии создаётся агент «Цены»
- **THEN** система отвечает 409, архивного агента можно восстановить из архива и принять заявку в него

#### Scenario: Занятое название продукта
- **WHEN** при принятии создаётся новый продукт «Веб», а продукт «Веб» уже есть
- **THEN** система отвечает 409 «продукт с таким названием уже есть», агент и навык не создаются

#### Scenario: Одновременное создание
- **WHEN** два разработчика одновременно принимают разные заявки, создавая агента «Сверщик»
- **THEN** одно принятие успешно, второе получает 409 и его заявка остаётся на рассмотрении
