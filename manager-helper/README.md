# Manager Helper

Расширение Google Chrome (Manifest V3) на React + TypeScript + Vite + [@crxjs/vite-plugin](https://crxjs.dev).

## Структура

```
manifest.config.ts      манифест расширения (типизированный)
vite.config.ts          Vite + React + Tailwind + CRXJS
src/
  background/           service worker
  content/              content script
  sidepanel/            side panel (React), открывается по клику на иконку
  options/              страница настроек (React)
  shared/               общие типы сообщений, стили
public/icons/           иконки расширения
scripts/                вспомогательные скрипты
```

## Команды

| Команда             | Что делает                              |
| ------------------- | --------------------------------------- |
| `npm run dev`       | dev-сервер с HMR, собирает в `dist/`    |
| `npm run build`     | typecheck + production-сборка в `dist/` |
| `npm run typecheck` | проверка типов                          |
| `npm run lint`      | ESLint                                  |
| `npm run format`    | Prettier                                |
| `npm run icons`     | перегенерировать заглушки иконок        |

## Запуск в Chrome

1. `npm install`
2. `npm run dev`
3. Открыть `chrome://extensions`, включить «Режим разработчика».
4. «Загрузить распакованное расширение» → выбрать папку `dist/`.

Side panel, options и content script обновляются через HMR, service worker перезагружается автоматически.

## Авторизация

Расширение показывает экран входа в боковой панели; адрес бэкенда и вход/выход (блок «Аккаунт») настраиваются на странице `options`. Запросы к бэкенду идут через `src/shared/auth` (`authFetch`): access-токен хранится только в памяти, refresh-токен бэкенд кладёт в HttpOnly cookie `mh_refresh`, запросы к `/auth/*` отправляются с `credentials: 'include'`.

- ID расширения фиксирован полем `key` в `manifest.config.ts`: `facoikcjgloanpnjokljdemgipikeoho`. В `AUTH_ALLOWED_ORIGINS` бэкенда достаточно `chrome-extension://*` (любое расширение) или точного `chrome-extension://facoikcjgloanpnjokljdemgipikeoho` (переменные окружения auth, сидер и порядок выката описаны в `backend/README.md`).
- Для адреса бэкенда не localhost расширение запрашивает разрешение на хост (`optional_host_permissions`); при отказе адрес не сохраняется. При смене адреса сессия завершается.
- Первый вход: временный пароль, выданный сидером, затем обязательная смена пароля.
- Откат: установить предыдущую сборку расширения; состояние входа в `chrome.storage` не хранится.

## Задачи

В боковой панели есть два раздела, переключатель «Чат / Задачи» находится в шапке панели. Раздел доступен только после входа, последний выбранный раздел запоминается между открытиями панели. Переключение не прерывает ответ ассистента и не сбрасывает состояние чата.

Код: `src/sidepanel/tasks/` (экран, раскладка `tasks-layout.ts`, хуки), `src/shared/tasks-api.ts` (клиент и разбор ответов `/tasks`, `/users`), `src/shared/tasks-view.ts`. Запросы идут через общий `authFetch`, права хоста в манифесте не менялись.

- **Мои задачи.** По умолчанию показываются незавершённые задачи («К выполнению», «В работе»), где пользователь ответственный, по дедлайну (ближайшие первыми, без дедлайна в конце). Представления: «Мои», «Наблюдаю», «Созданные мной», «Готовые»; поиск по названию; подгрузка страниц по запросу. Просрочка подписывается текстом «Просрочено».
- **Быстрое создание.** Одно поле названия (Enter), необязательные дедлайн и ответственный (по умолчанию «я»); расширенные поля в раскрывающейся части. При ошибке сервера введённый текст сохраняется.
- **Смена статуса.** Одним действием из строки списка и из деталей; изменение применяется сразу и откатывается с сообщением при отказе сервера.
- **Детали.** Описание, дедлайн, создатель, ответственный, наблюдатели, вложения. Можно изменить название, описание, дедлайн и ответственного, скачать вложение под исходным именем. Загрузка и удаление вложений, удаление задачи и редактирование наблюдателей в расширении не поддерживаются, это делается в control-center.
- **Узкая панель** (от 320 px): один столбец, список и детали сменяют друг друга, «Назад» возвращает к списку с тем же фильтром и прокруткой.
- **Версия для планшета (панель растянута, от 640 px).** Порог `WIDE_BREAKPOINT = 640` берётся из `src/sidepanel/panel-layout.ts` и общий с чатом. Два столбца: слева список с представлениями и быстрым созданием, справа детали выбранной задачи; пока задача не выбрана, справа подсказка «Выберите задачу». Выбор, смена статуса и редактирование работают без перехода между экранами, кнопка «Назад» в деталях не показывается. При сужении ниже 640 px раздел возвращается к одному столбцу, выбранная задача и фильтр сохраняются. Какие столбцы показывать, решает чистая функция `tasksPaneVisibility(widthPx, selectedId)`.

Контракт API (`GET/POST/PATCH /tasks`, `GET /tasks/:id/attachments/:id`, `GET /users`) описан в `backend/README.md`; zod-схемы и парсеры не шарятся между пакетами, у control-center своя копия.
