# Control Center

Electron-приложение (electron-vite, React 19, zustand, TanStack Query, shadcn/Tailwind, zod).

## Команды

| Команда             | Что делает                       |
| ------------------- | -------------------------------- |
| `npm run dev`       | запуск в режиме разработки       |
| `npm run build`     | typecheck + сборка               |
| `npm run typecheck` | проверка типов (node и web)      |
| `npm test`          | Vitest                           |

## Доступ к API

Renderer ходит в бэкенд через кастомный протокол `cc-api://backend/...`. Main-процесс (`src/main/cc-api-protocol.ts`) пересылает запрос на адрес бэкенда, подставляет Bearer-токен и вырезает `Authorization`, `Cookie` и служебные заголовки клиента. Разрешены только префиксы `/threads`, `/agent`, `/tasks` и `/users`; остальные пути получают 403. Тело запроса и ответ передаются потоком, поэтому через прокси работают multipart-загрузка и бинарное скачивание вложений.

## Раздел «Задачи»

Узкий левый рейл переключает «Чаты» и «Задачи» (активный раздел хранится в zustand `ui.store`, роутера нет). Оба раздела остаются смонтированными, поэтому выбранный чат, фильтры и открытая задача сохраняются на время запуска. Без действующей сессии рейл и раздел не показываются, виден экран входа.

- Список: название, статус, ответственный, дедлайн, число вложений; просроченные задачи подписаны текстом. Пагинация, сортировка по дедлайну, времени создания и изменения (по умолчанию новые первыми).
- Фильтры: «Все», «Мои», «Я наблюдаю», «Созданные мной», «Просроченные», статус, поиск по названию с задержкой ввода. Фильтры комбинируются по «И», смена фильтра возвращает на первую страницу.
- Создание в диалоге: название обязательно, описание, дедлайн, ответственный, наблюдатели (до 50). Выбор пользователей по логину через `GET /users` (`UserPicker`, есть быстрый выбор «Я»). Ошибка `TASK_USER_NOT_FOUND` показывается у поля участников.
- Панель деталей (drawer, не модальная): правка полей, смена статуса, участники, вложения (загрузка выбором или перетаскиванием с прогрессом и отменой, скачивание под исходным именем, удаление с подтверждением), удаление задачи. Ответы 413 и 422 (`TASK_ATTACHMENT_LIMIT`) превращаются в понятные сообщения.
- Потеря сессии и недоступность сервера обрабатываются так же, как в чатах.

Код: `src/renderer/src/features/tasks/`, клиенты `lib/backend/tasks.api.ts`, `users.api.ts`, схемы `tasks.schema.ts`. Схемы дублируют контракт бэкенда (`backend/src/modules/tasks/interface/http/tasks.responses.ts`, `users.responses.ts`) и не шарятся с manager-helper.

## Зависимость от add-electron-auth

Бэкенд защищён Bearer-токеном, а прокси подставляет его из сессии, которую ведёт change `add-electron-auth` (`src/main/auth`, экран входа, мост в preload). Без этого change запросы к `/tasks` и `/users` получат 401 и раздел задач работать не будет. Порядок работ: сначала влить `add-electron-auth`, затем проверять control-center против защищённого бэкенда.
