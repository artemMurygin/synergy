# Control Center

Electron-приложение (electron-vite, React 19, zustand, TanStack Query, shadcn/Tailwind, zod).

## Команды

| Команда             | Что делает                       |
| ------------------- | -------------------------------- |
| `npm run dev`       | запуск в режиме разработки       |
| `npm run build`     | typecheck + сборка               |
| `npm run typecheck` | проверка типов (node и web)      |
| `npm test`          | Vitest                           |

## Доступ к API

Renderer ходит в бэкенд через кастомный протокол `cc-api://backend/...`. Main-процесс (`src/main/cc-api-protocol.ts`) пересылает запрос на адрес бэкенда, подставляет Bearer-токен и вырезает `Authorization`, `Cookie` и служебные заголовки клиента. Разрешены только префиксы `/threads`, `/agent`, `/tasks`, `/users`, `/notifications`, `/telegram` и `/files` (`ALLOWED_PREFIXES`); остальные пути получают 403. Префикс `/files` нужен файлам в чате: загрузка (`POST /files`), подписанная ссылка (`POST /files/:id/download-link`) и само скачивание по ней. Тело запроса и ответ передаются потоком, поэтому через прокси работают multipart-загрузка и бинарное скачивание вложений.

## Файлы в чате

К сообщению можно приложить до 5 файлов (таблицы, документы, записи встреч). Записи встреч бэкенд расшифровывает сам, результат приходит в тот же чат отдельным сообщением.

- Поле ввода: кнопка «Прикрепить файл» или перетаскивание на панель чата («Отпустите файлы, чтобы прикрепить»). Файл загружается сразу после выбора (`POST /files` через `xhrUpload`), карточка показывает прогресс, отмену, ошибку и повтор. Отправка недоступна, пока идёт загрузка. Шестой файл даёт подсказку о лимите. Допустимые расширения (`ACCEPTED_FILE_TYPES`) — подсказка для диалога выбора, проверяет тип сервер (415 и 413 превращаются в понятные тексты).
- Отправка: id загруженных файлов кладутся в `runConfig.custom.fileIds` сообщения, `ChatRuntimeProvider` (`liftFileIds`) переносит их в `forwardedProps.fileIds` запроса `POST /agent`. Сообщение может состоять только из файлов. Если сервер отказал с 410 `FILE_GONE` (срок хранения файла истёк), отправленные файлы возвращаются в черновик, а просроченный помечается ошибкой.
- Лента: файлы сообщения показываются карточками (`FileCard`, `MessageAttachments`) у сообщений пользователя и агента. У сообщений из истории файлы приходят в `attachments`, а файлы, которые агент приложил во время ответа, — событием AG-UI `CUSTOM` `file-attached` (`message-files.ts`); одна карточка на файл. Клик скачивает файл через свежую подписанную ссылку и сохраняет под исходным именем; ошибка скачивания показывается над лентой. Файл с истёкшим сроком (`status: deleted`) показан неактивной карточкой «Срок хранения истёк».
- Сообщения системы (`source: system`, например «Расшифровка готова») показываются как ответ агента с пометкой «Сообщение о расшифровке» и без служебных отметок запуска.
- Уведомления `meeting-transcript.ready` и `meeting-transcript.failed` ведут в чат с записью (цель `chat`). Если этот чат открыт, история перечитывается, а при открытом разделе «Чаты» тост не показывается: сообщение и так появится в ленте.

Код: `src/renderer/src/features/chat/` (`use-composer-attachments.ts`, `ComposerAttachments.tsx`, `Composer.tsx`, `FileCard.tsx`, `MessageAttachments.tsx`, `file-downloads.tsx`, `message-files.ts`), клиенты `lib/backend/files.api.ts`, `files.queries.ts`, `xhr-upload.ts`, схемы `files.schema.ts` и `schema.ts` (вложения и `source` в истории).

## Раздел «Задачи»

Узкий левый рейл переключает «Чаты» и «Задачи» (активный раздел хранится в zustand `ui.store`, роутера нет). Оба раздела остаются смонтированными, поэтому выбранный чат, фильтры и открытая задача сохраняются на время запуска. Без действующей сессии рейл и раздел не показываются, виден экран входа.

- Список: название, статус, ответственный, дедлайн, число вложений; просроченные задачи подписаны текстом. Пагинация, сортировка по дедлайну, времени создания и изменения (по умолчанию новые первыми).
- Фильтры: «Все», «Мои», «Я наблюдаю», «Созданные мной», «Просроченные», статус, поиск по названию с задержкой ввода. Фильтры комбинируются по «И», смена фильтра возвращает на первую страницу.
- Создание в диалоге: название обязательно, описание, дедлайн, ответственный, наблюдатели (до 50). Выбор пользователей по логину через `GET /users` (`UserPicker`, есть быстрый выбор «Я»). Ошибка `TASK_USER_NOT_FOUND` показывается у поля участников.
- Панель деталей (drawer, не модальная): правка полей, смена статуса, участники, вложения (загрузка выбором или перетаскиванием с прогрессом и отменой, скачивание под исходным именем, удаление с подтверждением), удаление задачи. Ответы 413 и 422 (`TASK_ATTACHMENT_LIMIT`) превращаются в понятные сообщения.
- Потеря сессии и недоступность сервера обрабатываются так же, как в чатах.

Код: `src/renderer/src/features/tasks/`, клиенты `lib/backend/tasks.api.ts`, `users.api.ts`, схемы `tasks.schema.ts`. Схемы дублируют контракт бэкенда (`backend/src/modules/tasks/interface/http/tasks.responses.ts`, `users.responses.ts`) и не шарятся с manager-helper.

## Зависимость от add-electron-auth

Бэкенд защищён Bearer-токеном, а прокси подставляет его из сессии, которую ведёт change `add-electron-auth` (`src/main/auth`, экран входа, мост в preload). Без этого change запросы к `/tasks` и `/users` получат 401 и раздел задач работать не будет. Порядок работ: сначала влить `add-electron-auth`, затем проверять control-center против защищённого бэкенда.
