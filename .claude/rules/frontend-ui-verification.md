# Проверка UI после изменений во фронтенде

## Когда
- Любое изменение, которое влияет на то, что видит или делает пользователь: разметка, стили, компоненты, состояние, обработчики, запросы к API, тексты.
- Проверка делается сама, до финального ответа. Не нужно ждать просьбы пользователя и не нужно спрашивать, проверять ли.
- Можно пропустить только при изменениях, которые не попадают в UI: только тесты, только типы, переименование без изменения поведения. В ответе тогда одной строкой сказать, что UI не проверялся и почему.

## Порядок
1. Сначала `npm run typecheck` и `npm test` в изменённом приложении. Если упали — чинить, в браузер не идти.
2. Потом открыть приложение и пройти изменённый сценарий руками: клики, ввод, переходы, пустые и ошибочные состояния, если они затронуты.
3. Сделать скриншот изменённого экрана и посмотреть на него, сравнить с макетом в `design/`, если задача была по макету.
4. Проверить консоль на ошибки и предупреждения React.
5. Если нашлась проблема — исправить и пройти проверку заново.

## manager-helper (расширение Chrome)
- Инструмент: MCP-сервер `extension` (`mcp__extension__browser_*`). Не использовать `claude-in-chrome`: брендовый Chrome не грузит распакованное расширение.
- Перед проверкой собрать: `cd manager-helper && npx vite build` (или держать запущенным `npm run dev`). Браузер грузит `manager-helper/dist`, без сборки проверяется старый код.
- Боковая панель: `chrome-extension://facoikcjgloanpnjokljdemgipikeoho/src/sidepanel/index.html`.
- Страница настроек: `chrome-extension://facoikcjgloanpnjokljdemgipikeoho/src/options/index.html`.
- Окно 400×800 — это ширина боковой панели, вёрстку проверять именно в ней.
- Инструменты: `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_take_screenshot`, `browser_console_messages`.

## control-center (Electron)
- Инструмент: MCP-сервер `electron-stagewright` (`mcp__electron-stagewright__*`).
- Запуск: `electron_launch` (или `electron_attach`, если приложение уже запущено через `npm run dev`), дальше передавать `session_id` во все вызовы, в конце `electron_stop`.
- Чтение и действия: `electron_snapshot`, `electron_find`, `electron_click`, `electron_type`, `electron_expect_*`, `electron_screenshot`, `electron_console_logs`.
- Данные приходят с бэкенда через `cc-api://backend/...`. Если бэкенд не запущен и экран пустой из-за этого — сказать об этом, а не считать проверку пройденной.

## Если проверить не удалось
- MCP-сервер не подключился, сборка не запускается, нет бэкенда или авторизации — не делать вид, что проверка прошла.
- В финальном ответе прямо написать, что именно не проверено и что мешает, и предложить, как это поправить.

## Что писать в ответе
- Одна-две строки: какие сценарии пройдены в браузере и что видно на скриншоте.
- Найденные и исправленные по ходу проверки проблемы — коротко.
