# Дизайн-система

Макеты открываются и правятся только через `mcp__pencil__*` (файлы `.pen` зашифрованы, `cat`, `grep`, Read не работают).

## Файлы
- `design/synergy-design.pen` — экраны. `design/design-kit.lib.pen` — UI Kit (библиотека, в `synergy-design.pen` её компоненты и переменные видны с префиксом `t:`).
- Изменения библиотеки открытый документ подхватывает только после повторного открытия файла.

## UI Kit
- Компоненты экранов только из UI Kit: `Решение 01 · Synergy UI Kit` (базовые) и `Решение 02 · Клиентские приложения (CC, MH)` (оболочка, чат, задачи, уведомления, профиль и Telegram, авторизация). Новый элемент сначала рисуется мастером в UI Kit, потом ставится экземпляром.
- Имена мастеров в UI Kit совпадают с именами компонентов пакета `@synergy/ui-kit`. Таблица Node ID мастеров лежит в `ui-design.md` change `unified-client-ui`.
- Переменные UI Kit: имя без префикса `t:` = имя CSS-токена кода (`--color-<имя>`, `--radius-<имя>`, шрифты `--font-ui` Raleway, `--font-display` Onest, `--font-chat` Inter, `--font-mono` JetBrains Mono). Примеры: `brand-red`, `brand-red-soft`, `ink`, `ink-60`, `ink-80`, `surface`, `surface-alt`, `surface-sunken`, `border`, `info-soft`, `success-soft`, `warning`, `warning-soft`, `r-md` (-> `--radius-md`). Значения в макете и в коде совпадают.
- В макете на экране переменная пишется `$t:<имя>`, в самой библиотеке `$<имя>`.
- Иконки только lucide, размер 18 (в плотных местах 14–16).
- Цвета, скругления и шрифты не вводятся вне переменных UI Kit: нужна новая переменная — добавить в библиотеку, не писать «сырым» значением.

## Только светлая тема
Тёмных вариантов в макетах нет и быть не должно. Не добавлять themes в переменные и тёмные экраны.

## Чат на assistant-ui
Элементы чата (сообщения, группа вызовов инструментов, композер, вложения, подсказки следующего шага) рисуются по образцу примитивов `assistant-ui`: `Thread`, `Message`, `Composer`, `ToolGroup`. Структура и состояния макета соответствуют тому, что даёт библиотека, без своих надстроек поверх неё.

## Порядок согласования правок дизайна
1. Правка начинается с макета: мастер в UI Kit, затем экраны на трёх форматах, затем проверка (layout без clipping, один скриншот секции).
2. Node ID новых и изменённых секций и мастеров вписываются в `ui-design.md` активного change («Экраны», «Ключевые состояния экранов», «Новые компоненты UI Kit»).
3. Новые и изменённые экраны показываются пользователю и принимаются до кода. Без подтверждения код по макету не пишется.
4. Удаление фреймов только по согласованию с пользователем: сначала список с Node ID и причиной, потом удаление.
5. Расхождение макета со спекой или кодом не решается молча: фиксируется в `ui-design.md` («Отклонения») и выносится вопросом.
